# 题目要求解读

## 题目要求

终于开始真正写编译器啦！

第一步就是分词了，即什么符号对应的是什么类别，哪些符号组成一个单词。

SysY 语言总共有以下几种类别：

| 单词名称            | 类别码        | 单词名称  | 类别码     | 单词名称 | 类别码     | 单词名称   | 类别码      |
| --------------- | ---------- | ----- | ------- | ---- | ------- | ------ | -------- |
| **Ident**       | IDENFR     | while | WHILETK | >=   | GEQ     | ;      | SEMICN   |
| **IntConst**    | INTCON     | case  | CASETK  | \|   | OR      | <      | LSS      |
| **CharConst**   | CHARCON    | char  | CHARTK  | !    | NOT     | =      | ASSIGN   |
| **StringConst** | STRCON     | else  | ELSETK  | %    | MOD     | >      | GRE      |
| continue        | CONTINUETK | main  | MAINTK  | (    | LPARENT | [      | LBRACK   |
| default         | DEFAULTTK  | void  | VOIDTK  | )    | RPARENT | ]      | RBRACK   |
| printf          | PRINTFTK   | int   | INTTK   | *    | MULT    | {      | LBRACE   |
| return          | RETURNTK   | if    | IFTK    | +    | PLUS    | }      | RBRACE   |
| static          | STATICTK   | !=    | NEQ     | ,    | COMMA   | -      | MINU     |
| break           | BREAKTK    | <=    | LEQ     | /    | DIV     | switch | SWITCHTK |
| const           | CONSTTK    | ==    | EQL     | :    | COLON   | &&     | AND      |

我们的任务就是写一个程序，将一段 SysY 程序的文字流拆散，识别出单词，然后输出单词的类别码。

## 解题思路

> 注意：本文代码实现均使用 JAVA。

### 数据结构

设计一个名叫 `Token` 的类（此 token 非彼 token！），包括三个字段：`tokenType`（类型）、`tokenContent`（取值） 和 `lineNum`（位置/行号）。

同时，由于 `tokenType` 的所有值就在上面的表格中，所以自然可以创建一个枚举类 `TokenType`，存放所有的类型的类别码。（当然不这样也完全没事）

然后就是想办法如何输出结果。这里给出两种方案：

1. 每分析出一个单词就输出其 Token；
2. 建立一个 Token 数组，分析完之后再一次性输出。

看上去第 1 种方案非常简单无脑，也省时间空间。但是题目还有一个要求哦：如果出现错误，只输出错误而不输出 Token。因此千万不要上来就用第 1 种方法，发现最后两个测试点过不去了！

因此可以再建一个 `TokenArrayListManager` 类，用于掌管 Token 数组。

> 不用这个类也完全可以，毕竟只是对 `ArrayList<Token>` 的一层封装。但是，后续语法分析等阶段会需要使用词法分析出的 Token 数组，与其在 `Lexer` 里面写 `getter()` 方法，不如单独建一个类来的清楚。

另外，也可以照葫芦画瓢，设计错误码的数据结构。

### Lexer

Lexer 就是词法分析器了，这个类中将要写关键的词法分析代码了。

观察词法表格的差异点，很自然的可以想到，需要将**保留字**、**运算符**和**标识符/常量**分类讨论。

运算符最简单，因为不是字母，且长度固定，直接匹配即可；而保留字、标识符/常量都可能是字母组成的，且长度不固定，需要进一步讨论。

> 虽然理论课上讲了由正则式到自动机的转化，但其实我觉得并不需要这么麻烦，也不用真的设计出一个完善的自动机再写代码。只要有一个自动机的理论框架在脑子里，想必并不会很困难。

一个 Lexer 最关键的东西就是**双指针**。主指针指向单词开头的位置，副指针往后继续匹配。匹配成功后，主指针移动到副指针位置即可。

这里给出几个提示：

1. 标识符可能有下划线；
2. 保留字和标识符或许应该使用同一个方法，毕竟保留字的语法是标识符的子集；
3. 保留字的判断可以用哈希表；
4. 注意除号 `/` 不可直接匹配！因为还可能是注释的符号！忽视这个只能得 96%的分数；
5. 注意转义符 `\` 不能直接写入字符串！
6. 注意 `=` 和 `==` 等的匹配逻辑。

private int lineNum = 1; // 初始化行号

### 关键方法 `lexerAnalyze()`

```java
public void lexerAnalyze() {  
    int codeLength = code.length();  
    code += "\0\0"; // 避免指针移动到文件末尾的时候越界  
  
    // 主指针不断遍历 code，对不同的类型进行分类判断  
    for (readIndex = 0; readIndex < codeLength; readIndex++) {  
        char first = code.charAt(readIndex);  
        char second = code.charAt(readIndex + 1);  
        String doubleChars = "" + first + second;  
        String singleChar = "" + first;  
        if (first == '\n') {  
            lineNum++;  
        }  
        // 空白字符（空格、制表符、回车等）与 BOM：直接跳过  
        else if (Character.isWhitespace(first) || first == '\uFEFF') {  
            // 不产生单词  
        }  
        // 标识符  
        else if (Character.isLetter(first) || first == '_') {  
            handleIdentifier(code, codeLength, singleChar);  
        }  
        // int, char, ... 均同理  
        else if (Character.isDigit(first)) {  
            handleInteger(code, codeLength, singleChar);  
        } else if (singleChar.equals("'")) {  
            handleCharConst(code, codeLength);  
        } else if (singleChar.equals("\"")) {  
            handleStringConst(code, codeLength);  
        } else if (doubleChars.equals("&&")) {  
            tokenArrayListManager.addToken(new Token("&&", TokenType.AND, lineNum));  
            readIndex++;  
        } else if // 后略  
        // 其余未匹配任何单词类型的字符均为非法字符  
            else {  
            errorCount++;  
            errorArrayListManager.addError(new Error(ErrorType.INVALID_CHARACTER, lineNum));  
        }  
    }  
}
```

> 以上方法是基于指导书的写法，我后续将 else if 改为了 switch。

### 双指针分析变长单词

以方法 `handleIdentifier()` 为例，指导书是这么写的：

```java
private void handleIdentifier(String code, int codeLength, String startCode) {
    StringBuilder identifier = new StringBuilder(startCode);
    for (int j = readIndex + 1; j < codeLength; j++) {
        char id = code.charAt(j);
        if (!(Character.isLetterOrDigit(id) || id == '_')) {
            readIndex = j - 1;
            break;
        }
        identifier.append(id);
    }
    String identifierContent = identifier.toString();
    TokenType identifierType;
    if (reservedWords.containsKey(identifierContent)) {
        identifierType = reservedWords.get(identifierContent);
    } else {
        identifierType = TokenType.IDENFR;
    }
    tokenArrayListManager.addToken(new Token(identifierContent, identifierType, lineNum));
}
```

大致思路是：一直往后匹配，直到非字母或下划线时停止，指针回退 1 个字符。判断整个单词是否是保留字，如果不是则是标识符。

但是这样其实没有真正用上双指针，每次拼接一个字符会导致整体运行时间大大延长。于是我后续改成了这样的写法：

```java
private void handleIdentifier(char[] src, int codeLength) {  
    int start = readIndex;  
    int end = start + 1;  
    while (end < codeLength && isIdChar(src[end])) {  
        end++;  
    }  
    readIndex = end - 1;  
    String content = new String(src, start, end - start);  
    addToken(content, RESERVED_WORDS.getOrDefault(content, TokenType.IDENFR));  
}
```
