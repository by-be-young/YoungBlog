# 题目要求解读

这个实验只交一件东西：`mips.txt`。评测机读它，丢进课程版 MARS 跑，比对输出。

前面的词法、语法、语义三个实验都在读源程序，这一个开始写能执行的东西。作业把它拆成两半：

| 半程 | 输入 | 输出 | 评分 |
| --- | --- | --- | --- |
| 中间代码生成 | 语法树 | 四元式序列 `ir.txt` | 不评分，但出错时只能靠它定位 |
| 目标代码生成 | 四元式 | MIPS 汇编 `mips.txt` | 只看这个 |

配置文件里写死目标：

```json
{
  "programmingLanguage": "Java",
  "objectCode": "MIPS"
}
```

## 输入与输出

| 文件 | 谁写 | 说明 |
| --- | --- | --- |
| `testfile.txt` | 评测机 | 唯一输入，程序自己不许读标准输入 |
| `error.txt` | 我的编译器 | 前面阶段有错时的唯一输出 |
| `ir.txt` | 我的编译器 | 四元式，调试用 |
| `mips.txt` | 我的编译器 | 提交物 |

`error.txt` 只要有内容，就什么文件都不生成：

```java
if (!errorManager.getErrorArrayList().isEmpty()) {
    writeErrorFile();
    return;
}
```

> 之所以敢这么干，是因为后面所有代码都可以假设“名字查得到、类型对得上”。一边翻译一边查错的话，每个函数都得带兜底分支，主干逻辑会被 if 淹没。

## 七个词，先认识一下

后文反复用到这几个词，先用一段代码解释清楚，不展开。

| 词 | 是什么 | 在这份代码里长什么样 |
| --- | --- | --- |
| 语法树 | 源程序的结构化表示，每个节点是一个语法成分 | `IrExpr.visitExp` 收到的 `Exp` 对象 |
| 四元式 | 一条只有两个输入、一个动作、一个输出的指令 | `(add, t0, b, t1)` |
| IR | 中间表示，这里是四元式序列 | `ir.txt` 整个文件 |
| 栈帧 | 函数每次调用在栈上占的那块内存 | `addiu $sp,$sp,-24` 开出来的 24 字节 |
| 栈槽 | 栈帧里给一个值划的 4 字节格子，地址写成 `fp+偏移` | `sw $t0, 0($fp)` 里的 `0($fp)` |
| MARS | 课程用的 MIPS 模拟器，负责把汇编跑起来 | 打开的窗口里点“运行” |
| syscall | 让模拟器帮忙做输入输出的指令，编号放在 `$v0` | `li $v0, 1` + `syscall` 打印整数 |

> 最容易混的是“栈帧”和“栈槽”。栈帧是整块，一次函数调用一块；栈槽是块里的小格，一个变量或一个临时值一格。`$fp` 指向这块的头，所以任何一格的地址都是 `fp + 数字`。

## 必须兑现的语义

题目只给文法，语义散在指导书和测试点里。动手前先过一遍：

| 语义 | 具体要求 |
| --- | --- |
| `int` | 32 位有符号，除法向零截断，`%` 余数跟随被除数 |
| `char` | 无符号 8 位，任何算术结果模 256（255+1=0，0-1=255） |
| 数组 | `int` 元素 4 字节，`char` 元素 1 字节，下标从 0 开始，不查越界 |
| 数组传参 | 传首地址，形参长度未知 |
| `static` 局部变量 | 只初始化一次，跨调用保留，递归共享同一份 |
| 逻辑与 / 逻辑或 | 短路，右侧有副作用时求值顺序必须对 |
| `printf` | 先把所有实参求完，再逐段输出 |
| 运行时库 | `get_int` / `get_char` / `get_string` / `put_int` / `put_char` / `put_string` |

> 后两条会在输出上直接暴露，所以评测器特别爱考。短路写错，`f() || g()` 会多调一次 `g`；`printf` 顺序写错，输出会混进新值。

# 解题思路

与其先背规则，不如从最小的程序开始。每加一个语法成分，就看一次 `ir.txt` 和 `mips.txt`。规则是从这些输出里读出来的，不是背出来的。

## 第一步：`return 1`

```c
int main() {
    return 1;
}
```

`ir.txt` 只有一行：

```text
func main : INT ()
    (ret, 1, -, -)  ; line 2
```

`mips.txt` 有九行有效指令：

```text
# ---- main ----
.globl main
main:
    addiu $sp, $sp, -8
    sw $fp, 0($sp)
    sw $ra, 4($sp)
    move $fp, $sp
    li $v0, 1
    j .Lmain_end
.Lmain_end:
    li $v0, 10
    syscall
```

逐条读：

- `.globl main`：把 `main` 标成全局符号，MARS 从它开始跑。
- `addiu $sp,$sp,-8`：栈往下长 8 字节，这就是这一帧。
- `sw $fp,0($sp)`、`sw $ra,4($sp)`：把旧的 `$fp`、`$ra` 存进这一帧。
- `move $fp,$sp`：让 `$fp` 指向这一帧的头。之后所有变量都用 `fp+偏移` 找。
- `li $v0,1`：返回值放 `$v0`。
- `j .Lmain_end`：跳到统一出口。
- 出口 `li $v0,10` + `syscall`：告诉 MARS 程序结束。

> `$sp` 是栈顶指针，进函数减、出函数加。`$fp` 是本帧的基准，函数运行期间不变。`$ra` 是“返回后跳回哪”，`jal` 会覆盖它，所以每个函数自己存一份。
>
> 为什么 8 字节就够：这一帧没有变量也没有临时值，只存旧 `$fp` 和 `$ra`。后面每多一个变量或临时值，这个数就加 4。
>
> 为什么 `return` 不直接 `jr`：函数可能有多个 `return`，每个都写一遍恢复现场容易漏。统一出口只写一次，谁返回就先放 `$v0` 再跳过来。

## 第二步：两个变量相加

```c
int main() {
    int a = 1;
    int b = 2;
    return a + b;
}
```

```text
func main : INT ()
    (assign, 1, -, a)  ; line 2
    (assign, 2, -, b)  ; line 3
    (assign, a, -, t0)  ; line 0
    (add, t0, b, t1)  ; line 4
    (ret, t1, -, -)  ; line 4
```

```text
main:
    addiu $sp, $sp, -24
    sw $fp, 16($sp)
    sw $ra, 20($sp)
    move $fp, $sp
    li $t0, 1
    sw $t0, 0($fp)          ← a
    li $t0, 2
    sw $t0, 4($fp)          ← b
    lw $t0, 0($fp)
    sw $t0, 8($fp)          ← 物化 a
    lw $t0, 8($fp)
    lw $t1, 4($fp)
    addu $t2, $t0, $t1
    sw $t2, 12($fp)         ← t1
    lw $v0, 12($fp)
    j .Lmain_end
```

这里能看出三件事。

**每个值都在栈上有一格。** `a` 在 `0($fp)`，`b` 在 `4($fp)`，两个临时值在 `8`、`12`。栈帧 24 字节 = 两个变量 8 + 两个临时 8 + 保存区 8。

**`(assign, a, -, t0)` 看着多余，其实保命。** 加法左边先搬进 `t0`，右边 `b` 直接在 `addu` 时读。

**常量赋值是 `li` + `sw` 两条。** 先把常量装进寄存器，再写回栈槽，两步都不省。

> 左边为什么要多这一条 `assign`：右边可能是 `a + f()`，`f()` 会把 `a` 改掉。先把 `a` 的旧值搬进 `t0`，加法用的才是“加法开始时 a 的值”。右边不用搬，因为它算完立刻用掉，中间没有别的代码插进来。
>
> 代价是 `ir.txt` 里 `assign` 特别多。这笔开销买的是求值顺序与源码一致，性能留给优化。

## 第三步：加一个 `if`

```c
int main() {
    int a = 1;
    int b = 2;
    if (a < b) { return 1; } else { return 0; }
}
```

```text
    (assign, a, -, t0)  ; line 0
    (lt, t0, b, t1)  ; line 4
    (if, t1, .Lmain_0, -)  ; line 0
    (goto, .Lmain_2, -, -)  ; line 0
.Lmain_0:
    (ret, 1, -, -)  ; line 4
    (goto, .Lmain_1, -, -)  ; line 0
.Lmain_2:
    (ret, 0, -, -)  ; line 4
.Lmain_1:
```

```text
    lw $t0, 8($fp)
    lw $t1, 4($fp)
    slt $t2, $t0, $t1
    sw $t2, 12($fp)
    lw $t0, 12($fp)
    bne $t0, $zero, .Lmain_0
    j .Lmain_2
.Lmain_0:
    li $v0, 1
    j .Lmain_end
    j .Lmain_1
.Lmain_2:
    li $v0, 0
    j .Lmain_end
.Lmain_1:
```

读法：先比较，把结果 0/1 放进临时变量；`bne` 在结果非 0 时跳“真”标签 `.Lmain_0`，否则 `j` 到“假”标签 `.Lmain_2`。

几个细节：

- `<` 用 `slt` 一条算完，结果先落临时变量，不直接决定跳转。
- 两个分支各自 `return`，都跳 `.Lmain_end`。
- `.Lmain_0` 里 `return` 之后还有一条 `j .Lmain_1`，永远不执行——语句序列结束时会补一条跳出口的指令，而 `return` 已经跳走了。

> 比较为什么不和跳转合成一条：`&&`、`||` 要反复判断同一个结果，合成“比较+跳转”会生成一堆标签。先算出 0/1，后面想怎么跳都行。多一次搬运换结构简单。
>
> 为什么要两个标签：成立跳 then，不成立跳 else。两处都得有落点，一个不够。

## 第四步：加数组

```c
int g[4] = {1, 2};

int main() {
    int i = 0;
    g[i] = 5;
    return g[1];
}
```

```text
global g : INT_ARRAY[4] { 1, 2, 0, 0 }

func main : INT ()
    (assign, 0, -, i)  ; line 4
    (assign, i, -, t0)  ; line 0
    (store, g, t0, 5)  ; line 5
    (load, g, 1, t1)  ; line 6
    (ret, t1, -, -)  ; line 6
```

```text
.data
.align 2
g:
    .word 1, 2, 0, 0
.text
...
    li $t2, 5
    la $t0, g
    lw $t1, 4($fp)
    sll $t1, $t1, 2
    addu $t0, $t0, $t1
    sw $t2, 0($t0)
```

`g[i] = 5` 分五步：把 5 装进 `$t2`；`la` 拿数组首地址；读下标；下标 `sll 2`（乘 4）加进地址；`sw` 写值。

`g[1]` 少了读下标那步，下标是常量，直接 `li $t1, 1` 再乘 4。

> `store` 的字段顺序要看清楚：`(store, g, t0, 5)` 里的 `5` 是待存的值，`t0` 是下标。这就是“`STORE` 的 target 放值”那处约定。我第一版按习惯写成 `(store, g, 5, t0)`，下标永远是 5，数组全错。
>
> 下标为什么乘 4：`int` 元素占 4 字节，第 `i` 个元素的地址是“首地址 + i*4”。`char` 数组元素占 1 字节，所以后面 `char` 的寻址不加 `sll`。

数组初值写进数据段：`g` 声明 4 格，初值只给两个，剩下补 0。

## 第五步：加函数调用

```c
int add(int a, int b) {
    return a + b;
}

int main() {
    int s = 0;
    s = add(s, 3);
    return s;
}
```

```text
    (assign, s, -, t0)  ; line 0
    (call, add, -, t1; args: t0, 3)  ; line 7
    (assign, t1, -, s)  ; line 7
```

```text
main:
    addiu $sp, $sp, -20
    ...
    addiu $sp, $sp, -8       ← 给两个实参留位置
    lw $t0, 4($fp)
    sw $t0, 0($sp)           ← 第 0 个实参
    li $t0, 3
    sw $t0, 4($sp)           ← 第 1 个实参
    jal add
    addiu $sp, $sp, 8        ← 用完立刻收回
    sw $v0, 8($fp)           ← 返回值落到 t1
```

被调函数 `add` 这边：

```text
add:
    addiu $sp, $sp, -24
    sw $fp, 16($sp)
    sw $ra, 20($sp)
    move $fp, $sp
    lw $t0, 24($fp)          ← 第 0 个实参
    sw $t0, 0($fp)           ← 形参 a
    lw $t0, 28($fp)          ← 第 1 个实参
    sw $t0, 4($fp)           ← 形参 b
    ...
```

`add` 的栈帧 24 字节，实参却在 `fp+24`、`fp+28`，紧贴栈帧外面。

> 实参区属于调用方：`main` 用 `addiu $sp,$sp,-8` 压出两格，`jal` 之后控制权交给 `add`，那两格还在。所以被调函数只按偏移读，不负责释放；`main` 回来后自己加回 8。
>
> 递归能工作也是同一个原因：每次调用开一块新栈帧，旧的 `$fp`、`$ra`、实参都留在原地，层层叠上去，回来一层层弹。

## 第六步：`char` 与 `printf`

```c
int main() {
    char c = 'A';
    char d = c + (char)10;
    printf("%c%c\n", c, d);
    return 0;
}
```

```text
string .str0 = "\n"

func main : INT ()
    (assign, 65, -, c)  ; line 2
    (assign, c, -, t0)  ; line 0
    (cast, 10, -, t1)  ; line 3
    (add, t0, t1, t2)  ; line 3
    (cast, t2, -, t3)  ; line 3
    (assign, t3, -, d)  ; line 3
    (assign, c, -, t4)  ; line 0
    (assign, d, -, t5)  ; line 0
    (call, put_char, -, -; args: t4)  ; line 4
    (call, put_char, -, -; args: t5)  ; line 4
    (call, put_string, -, -; args: .str0)  ; line 4
```

```text
    li $t0, 65
    sb $t0, 0($fp)          ← c，1 字节
    lbu $t0, 0($fp)
    andi $t0, $t0, 0xFF
    ...
    addu $t2, $t0, $t1
    andi $t2, $t2, 0xFF     ← 加法结果取低 8 位
    ...
    lw $a0, 24($fp)
    li $v0, 11
    syscall                 ← put_char
    lw $a0, 28($fp)
    li $v0, 11
    syscall
    la $a0, .str0
    li $v0, 4
    syscall                 ← put_string
```

三件事：

- `char` 变量读写用 `sb` / `lbu`，占 1 字节；`int` 用 `sw` / `lw`，占 4 字节。
- 每次 `char` 运算后跟一条 `andi 0xFF`，把结果截到 0~255。
- `printf` 先切成段，再按段调用 `put_char` / `put_int` / `put_string`，实参放 `$a0`，编号放 `$v0`。

> `andi 0xFF` 就是“模 256”。`char c = 250; c = c + 10;` 应该得到 4，不截就是 260，用 `%c` 打出来是乱码。截断写在 `emitBinary` 一处，所有算术自动带上。
>
> 为什么常量的 `cast` 也生成 `andi`：10 本来就小于 256，这条其实多余。真实输出还会出现连着两条 `andi`（`CAST` 一次、写回 char 槽又一次）。不影响结果，属于窥孔优化该删的冗余。

## 第七步：`switch`

```c
int main() {
    int i = 0;
    switch (i) {
        case 0: i = i + 1;
        case 1: i = i + 2; break;
        default: i = 9;
    }
    return i;
}
```

```text
    (eq, t0, 0, t1)  ; line 4
    (if, t1, .Lmain_0, -)  ; line 0
    (eq, t0, 1, t2)  ; line 5
    (if, t2, .Lmain_1, -)  ; line 0
    (goto, .Lmain_2, -, -)  ; line 0
.Lmain_0:
    ... case 0 的语句 ...
.Lmain_1:
    ... case 1 的语句 ...
    (goto, .Lmain_3, -)  ; break
.Lmain_2:
    (assign, 9, -, i)  ; default
.Lmain_3:
```

```text
    lw $t0, 4($fp)
    li $t1, 0
    xor $t2, $t0, $t1
    sltiu $t2, $t2, 1
    sw $t2, 8($fp)
    lw $t0, 8($fp)
    bne $t0, $zero, .Lmain_0
```

`eq` 的写法是“异或再判 0”：两个数相同，异或得 0；`sltiu $t2,$t2,1` 在“结果 < 1”时为 1，也就是等于 0。

三个现象：

- `i` 只物化一次（`t0`），后面每条 `case` 都拿它比较。
- `case 0` 的语句后面没有跳转，直接落进 `.Lmain_1`，这就是“落穿”。
- `case 1` 有 `break`，跳 `.Lmain_3`；`default` 的代码放在最后，跳转目标 `.Lmain_2` 按位置排。

> 落穿是 C 的语义：一个 `case` 执行完没有 `break`，就继续执行下一个 `case`。编译器不能自动加跳转，只能按源码顺序摆标签。
>
> `switch` 里的 `continue` 要找外层 `while`，所以 `break` 和 `continue` 必须分两个栈。合成一个的话，`continue` 会跳到 `switch` 结束，循环直接死。

## 第八步：`while` 与完整程序

把前面的零件拼起来，就是我回归用的那段：

```c
const int N = 4;
int g[4] = {1, 2};
char c = 'A';

int add(int a, int b) {
    return a + b;
}

int main() {
    int i = 0;
    int s = 0;
    while (i < N) {
        s = add(s, g[i]);
        i = i + 1;
    }
    printf("s=%d c=%c\n", s, c);
    char t = c + (char)1;
    s = s / 2;
    return s;
}
```

```text
func main : INT ()
    (assign, 0, -, i)
    (assign, 0, -, s)
.Lmain_0:                       ← 条件判断
    (assign, i, -, t0)
    (lt, t0, 4, t1)
    (if, t1, .Lmain_1, -)
    (goto, .Lmain_2, -)
.Lmain_1:                       ← 循环体
    (assign, s, -, t2)
    (load, g, i, t3)
    (call, add, -, t4; args: t2, t3)
    (assign, t4, -, s)
    (assign, i, -, t5)
    (add, t5, 1, t6)
    (assign, t6, -, i)
    (goto, .Lmain_0, -)         ← 回到条件
.Lmain_2:
```

```text
main:
    addiu $sp, $sp, -80
    sw $fp, 72($sp)
    sw $ra, 76($sp)
    move $fp, $sp
    ...
.Lmain_0:
    lw $t0, 0($fp)
    sw $t0, 12($fp)
    lw $t0, 12($fp)
    li $t1, 4
    slt $t2, $t0, $t1
    sw $t2, 16($fp)
    lw $t0, 16($fp)
    bne $t0, $zero, .Lmain_1
    j .Lmain_2
```

栈帧 80 字节的构成：3 个变量 `i`、`s`、`t` 占 12 字节，15 个临时值占 60 字节，加旧 `$fp`、`$ra` 8 字节。

> 80 = 12 + 60 + 8，这个式子能对上，说明栈帧分配没漏项。查汇编查不下去时，先数这个数。

循环体里数组和调用是这样连的：

```text
    la $t0, g
    lw $t1, 0($fp)          ← i
    sll $t1, $t1, 2
    addu $t0, $t0, $t1
    lw $t2, 0($t0)          ← g[i]
    sw $t2, 24($fp)
    addiu $sp, $sp, -8
    lw $t0, 20($fp)         ← s
    sw $t0, 0($sp)
    lw $t0, 24($fp)         ← g[i]
    sw $t0, 4($sp)
    jal add
    addiu $sp, $sp, 8
    sw $v0, 28($fp)
```

## 规则收口

上面七段程序把主要规则都用到了。这里集中列一遍，方便回头查。

四元式的操作码：

```text
(assign, 源, -, 目标)                 目标 = 源
(add/sub/mul/div/mod, 左, 右, 目标)    目标 = 左 op 右
(neg, 源, -, 目标)                    目标 = -源
(not, 源, -, 目标)                    目标 = (源 == 0 ? 1 : 0)
(eq/ne/lt/le/gt/ge, 左, 右, 目标)      目标 = 比较结果（0/1）
(cast, 源, -, 目标)                   按目标类型转换，int→char 取低 8 位
(load, 数组, 下标, 目标)               目标 = 数组[下标]
(store, 数组, 下标, 值)                数组[下标] = 值
(addr, 变量/数组, -, 目标)             目标 = 首地址
(label, 标签, -, -)                   标签:
(goto, 标签, -, -)                    无条件跳转
(if, 条件, 标签, -)                    条件 != 0 跳转
(ifz, 条件, 标签, -)                   条件 == 0 跳转
(call, 函数, -, 目标) ; args: ...      目标 = 函数(实参...)
(ret, 值, -, -)                       返回
```

操作数六种形态：

| Kind | 装什么 | 住哪 |
| --- | --- | --- |
| `TEMP` | `t0`、`t1`…… | 栈槽 |
| `VAR` | 源码名字、类型、数组长度、可选汇编标签 | 有标签在 `.data`，没标签在栈槽 |
| `CONST` | 数字，`char` 规整到 0~255 | 直接当立即数 |
| `LABEL` | 带函数名前缀的标签 | 不进内存 |
| `FUNC` | 函数名 | 只在 `call` 里用 |
| `STRING` | 汇编标签 + 已解码正文 | `.data` |

需要物化的五处：

| 位置 | 不物化会怎样 |
| --- | --- |
| 双目运算的左操作数 | `a + f()` 里 `f()` 改了 `a`，加法用了新值 |
| 函数实参 | `f(a, g())` 里 `g()` 改了 `a` |
| `printf` 实参 | 边算边输出，输出混进新值 |
| `switch` 表达式 | 后面比较链反复读它，中途被改 |
| 赋值语句的下标 | `a[i] = i + 1` 里右值改了 `i`，地址算错 |

指令选择：

| 四元式 | 生成的指令 |
| --- | --- |
| `assign` | 读源 → `$t0`，写 `$t0` → 目标 |
| `add` / `sub` | `addu` / `subu` |
| `mul` | `mult` + `mflo` |
| `div` / `mod` | `div` + `mflo` / `mfhi` |
| `neg` | `subu $t2, $zero, $t0` |
| `not` | `sltu` + `xori 1` |
| `eq` | `xor` + `sltiu 1` |
| `ne` | `xor` + `sltu` |
| `lt` / `gt` | `slt`（`gt` 交换操作数） |
| `le` / `ge` | `slt` 反向 + `xori 1` |
| `cast` → char | `andi 0xFF` |
| `load` | 基址 + 下标 `sll 2`（int）+ `lw` / `lbu` |
| `store` | 同上 + `sw` / `sb` |
| `addr` | `la` / `addiu $fp` / `lw`（数组形参取指针） |
| `if` / `ifz` | `bne $zero` / `beq $zero` |
| `ret` | 读进 `$v0` + `j .L函数名_end` |

> `le` / `ge` 要反向：`a <= b` 等价于 `!(b < a)`。MIPS 只有 `slt`，所以先算 `slt $t2,$t1,$t0`（`b < a`），再 `xori 1` 取反。写成 `slt` 加 `beq` 也行，但多一个标签，条件表达式里标签会成倍长。

## 目录与分工

```text

├── ir/                                  // 前半程：语法树 → 四元式
```

`mips` 读 `ir`，`ir` 不认识 `mips`。

> 方向反了，“先看四元式对不对”这条调试路径就没了。中间代码一旦依赖汇编细节，就没法单独检查。

## IrBuilder：作用域要重建

语义分析结束时，`SymbolTable` 已经逐层 `exitScope()` 弹干净了。代码生成需要“源码名字 → IR 值”的映射，所以另建一套作用域栈：

```java
private final ArrayDeque<HashMap<String, IrValue>> scopes = new ArrayDeque<>();
```

进 `Block` 压栈，离开弹栈。函数体是例外：形参和函数体共用一层，所以走 `visitBlockItems` 而不是 `visitBlock`。

> 两张表回答不同问题：符号表管“这个名字合不合法”，IR 环境管“这个名字翻译成哪个值”。用符号表代替不行，它已经空了，里存的也是符号信息，不是 IR 值。

名字解析出来只有五种归宿：

| 源码里的东西 | IR 里的形态 | 住在哪 |
| --- | --- | --- |
| 标量常量 | `CONST` | 不占存储 |
| 常量数组 | `VAR` + 标签 | `.data` |
| 全局 / `static` 局部 | `VAR` + 标签 | `.data` |
| 普通局部变量 / 数组 | `VAR` 无标签 | 栈槽 |
| 函数名 | `FUNC` | 只在 `call` 里 |

> 常量数组也进 `.data`，内容编译期就定了，不必每次进函数重新初始化。代价是标签必须全程序唯一，所以用 `.d函数名_变量名_序号`。

函数返回类型要预扫描：

```java
// 先登记所有函数的返回类型：允许函数体里调用“后面才定义”的函数。
for (int i = 0, n = funcDefs.size(); i < n; i++) {
    FuncDef def = funcDefs.get(i);
    if (def != null && def.getIdent() != null) {
        functionReturnTypes.put(def.getIdent().getName(), returnTypeOf(def.getFuncType()));
    }
}
```

> 调用表达式要知道返回类型，才能决定要不要开临时变量接 `$v0`。`main` 调 `add` 而 `add` 写在后面时，不预扫描就查不到。

## IrExpr：一层一值

每个 `visitXxx` 返回“存这个表达式值的操作数”。`a + b * 2`：

```text
(assign, a, -, t0)
(assign, b, -, t1)
(mul, t1, 2, t2)
(add, t0, t2, t3)
```

`LVal` 出现在取值位置时有四种情况：

| 目标 | 生成 | 说明 |
| --- | --- | --- |
| 标量常量 | 直接返回 `CONST` | 不生成指令 |
| 标量变量 | 直接返回 `VAR` | 由使用处读 |
| 数组带下标 | `load` | 结果类型是元素类型 |
| 数组不带下标 | `addr` | 首地址，用于传参和 `%s` |

> 这里的“单目形态”是文法上的说法，指这个节点只有一个孩子（`left == null`），跟 `-a` 那种一元运算不是一回事。`AddExp` 的文法是 `AddExp → MulExp | AddExp ('+'|'-') MulExp`，所以解析一个单独的 `1`，也会造出一个 `AddExp` 节点，只是它没有左孩子。碰到这种节点，直接把 `visitMulExp` 的结果原样还回去，不包 `assign`；不然 `int a = 1;` 会变成“先搬进 t0、再搬到 a”，满屏搬运。

## IrDecl：先决定住哪，再摊开初值

| 声明 | 存储 | 初始化时机 |
| --- | --- | --- |
| 标量常量 | 无 | 编译期求值 |
| 常量数组 | `.data` | 编译期写死 |
| 全局变量 | `.data` | 进程启动，无初值为 0 |
| `static` 局部 | `.data` | 只初始化一次 |
| 普通局部变量 | 栈槽 | 走到才赋值，无初值不清零 |
| 局部数组（有初值） | 栈槽 | 逐元素 `store` |

```java
if (init.isBraced()) {
    List<Exp> exps = init.getExps();
    for (int i = 0; i < count; i++) {
        IrValue value = i < exps.size() ? IrExpr.visitExp(ctx, exps.get(i))
                : zeroOf(baseType);
        storeElement(ctx, variable, i, value, line);
    }
}
```

`int a[5] = {1};` 生成 5 条 `store`：一条 1，四条 0。

> “没有初始化列表”和“列表没写满”是两回事。前者是不定值，不清零；后者按 C 规则补 0。混在一起处理，要么多清零，要么漏补。

`char[]` 用字符串初始化：

| 关系 | 行为 |
| --- | --- |
| L < N | 复制 L 字节，其余补 0 |
| L == N | 复制 N 字节，不补 `'\0'` |
| L > N | 只复制前 N 字节，不补 `'\0'` |

> 后两种不补结束符是 SysY 的规定。补了就多写一个字节，踩到相邻变量。

## IrStmt：只物化下标

```java
IrValue index = IrExpr.materialize(ctx, IrExpr.visitExp(ctx, lVal.getIndex()));
...
IrValue value = IrExpr.visitExp(ctx, stmt.getExp());
ctx.emit(Quad.store(value, target, index, stmt.getLineNum()));
```

> `a[i] = i + 1` 里右值会改 `i`。地址要用旧下标算，所以下标先物化，右值不物化。

## MipsGenerator：三段

序言：

```java
out.append(function.getName()).append(":\n");
out.append("    addiu $sp, $sp, -").append(frameSize).append('\n');
out.append("    sw $fp, ").append(frameSize - 8).append("($sp)\n");
out.append("    sw $ra, ").append(frameSize - 4).append("($sp)\n");
out.append("    move $fp, $sp\n");
```

随后把调用方压的实参搬进形参槽：

```java
int incoming = frameSize + 4 * i;
out.append("    lw $t0, ").append(incoming).append("($fp)\n");
out.append("    sw $t0, ").append(offset).append("($fp)\n");
```

> 数组形参搬的是指针，值本身就是地址，所以这里不分标量和数组，都搬 4 字节。

尾声统一出口：

```java
out.append(endLabel).append(":\n");
if (function.isMain()) {
    out.append("    li $v0, ").append(SYS_EXIT).append('\n');
    out.append("    syscall\n");
} else {
    out.append("    move $sp, $fp\n");
    out.append("    lw $ra, ").append(frameSize - 4).append("($sp)\n");
    out.append("    lw $fp, ").append(frameSize - 8).append("($sp)\n");
    out.append("    addiu $sp, $sp, ").append(frameSize).append('\n');
    out.append("    jr $ra\n");
}
```

栈帧分配：

```java
boolean paramArray = isArrayParam(local);
int size;
if (paramArray) {
    size = 4; // 数组形参只存首地址
} else if (local.getType() != null && local.getType().isArray()) {
    int count = Math.max(local.getArraySize(), 0);
    size = count * (local.elementType() == ValueType.CHAR ? 1 : 4);
} else {
    size = 4;
}
offsets.put(local, offset);
offset = align4(offset + Math.max(size, 0));
```

临时变量则扫全部四元式收集，每个一格，从不复用。

> 不复用保证“临时值什么时候重读都拿得到”。栈帧大一点无所谓，正确性优先，槽复用留给优化。

取地址三分支：

```java
case VAR:
    if (value.getStorageLabel() != null) {
        out.append("    la ").append(register).append(", ")
                .append(value.getStorageLabel()).append('\n');
    } else {
        Integer offset = offsets.get(value);
        int off = offset == null ? 0 : offset;
        if (isArrayParam(value)) {
            out.append("    lw ").append(register).append(", ")
                    .append(off).append("($fp)\n");
        } else {
            out.append("    addiu ").append(register).append(", $fp, ")
                    .append(off).append('\n');
        }
    }
    break;
```

> 数组形参的槽里存的是指针，不是数组本体，所以要再 `lw` 一次。`lw $t0,0($fp)` 和 `addiu $t0,$fp,0` 只差一个字符，语义差一次间接寻址。

调用与运行时库：

```java
if (isRuntime(name)) {
    emitRuntimeCall(name, args, out);
    ...
}
if (argCount > 0) {
    out.append("    addiu $sp, $sp, -").append(4 * argCount).append('\n');
}
for (int i = 0; i < argCount; i++) {
    emitLoad(args.get(i), "$t0", function, out);
    out.append("    sw $t0, ").append(4 * i).append("($sp)\n");
}
out.append("    jal ").append(name).append('\n');
if (argCount > 0) {
    out.append("    addiu $sp, $sp, ").append(4 * argCount).append('\n');

```

syscall 编号：`get_int`=5、`get_char`=12、`get_string`=`v0=8`（`a0` 缓冲区、`a1` 长度）、`put_int`=1、`put_char`=11、`put_string`=4。

> 压栈和回收要配成一对写。`addiu sp,sp,-4n` 之后忘了加回来，每调一次栈就掉一截，递归几层就爆。

# 自测方法

评测是黑盒的，但输出可以对着跑。

## 三层验证

1. 先看 `ir.txt`。`char` 加法后面有没有 `cast`、循环有没有回到条件标签、`printf` 实参是不是在调用前落好，肉眼都能看出来。
2. 再看 `mips.txt`。MARS 打开、汇编、运行，比对输出。报错会给行号。
3. 最后拿 C 对照。同一个程序手改成 C，`gcc` 跑一遍拿标准答案。`char` 回绕用 `unsigned char` 完全对得上。

> 先看 `ir.txt` 能省一半时间。汇编错了还要判断是翻译错还是生成错；四元式错了，范围就只剩前半程。

## 回归清单

- [ ] `char` 回绕：`255+1`、`0-1`、一元负号
- [ ] `char` 数组下标：元素 1 字节，不能加 `sll`
- [ ] 局部数组有初值但没写满：补 0
- [ ] `char[] = "..."` 三种长度
- [ ] 数组形参跨函数透传（`f(a)` 里再 `g(a)`）
- [ ] 全局数组只有部分初值
- [ ] `static` 跨调用保留
- [ ] 两个同名局部变量分处不同块
- [ ] `printf` 实参里有函数调用，且函数改了前面的实参
- [ ] `switch` 落穿、`switch` 里的 `continue`、`default` 在中间
- [ ] 短路：`f() || g()` 里 `g` 不该被调用
- [ ] 递归
- [ ] 多实参、嵌套调用
- [ ] `get_char` / `get_string` / `get_int` 混合输入
- [ ] 空语句、空循环体、空 `if` 分支
- [ ] `void` 函数、`void` 函数里的 `return;`

## 实测结果

- A/B/C 三套公共测试库共 60 组：59 组通过；
- 未通过的 B-5 是 MARS 4.5 命令行下 `get_char` 后接 `get_string` 触发 `SystemIO.readString` 的 `input is null`，属模拟器 stdin 限制，去掉这段输入序列后输出正确；
- 全量 `javac --release 17` 编译通过；
- `mips.txt` 用课程版 MARS 直接运行。

> “代码没错”和“评测全过”之间隔着模拟器。遇到后者，先确认是不是模拟器行为，别急着改代码。

# 踩坑记录

1. **栈槽表用变量名做 key。** 两个块里的同名 `a` 共用一个槽，前一个块的值被后一个块覆盖。改成 `IdentityHashMap`、用 `IrValue` 做 key 才对。

2. **`printf` 只记住变量名，没物化。** `printf("%d %d\n", x, f())` 里 `f()` 改了 `x`，输出读到新值。改成“先全部求值、再逐段输出”。

3. **数组形参直接 `addiu $fp, 偏移`。** 槽里存的是指针，当地址用读到的是垃圾。加 `isArrayParam` 分支。

4. **局部数组有初值但漏补 0。** `int a[5] = {1};` 只写了第一格。

5. **`switch` 里 `break` 跳错层。** `break` / `continue` 合成一个栈，`continue` 跳到 `switch` 结束。分成两个栈。

6. **`static` 变量放进栈帧。** 每次进函数重新初始化，`static` 的意义没了。一律进 `.data`。

7. **`main` 不是第一条指令。** 评测器按默认入口取第一条，前面先输出了用户函数就找不到 `main`。先输出 `main` 并加 `.globl main`。

8. **调用后忘记回收 `sp`。** 每调一次栈掉一截，递归几层就爆。这类错程序不报错，只能靠结构检查。

> 前七条都错得出来，最后一条错得看不出来：程序跑完正常，只是栈越跑越深。压栈和回收写在一起，就不容易漏。

# 留给代码生成二

优化只留了骨架：

```java
public interface IrPass {
    String name();
    void run(IrModule module);
}
```

`PASSES` 现在是空的，`OPTIMIZE` 打开也不改变输出。要接的话，按收益从易到难：常量折叠 → 复写传播 + 死代码删除 → 公共子表达式 → 强度削弱 → 控制流简化 → 窥孔。

两条红线：

- 不改变可观察行为：I/O 顺序、短路的副作用、`printf` 先求值后输出、`static` 状态；
- 不跨越 `call` 搬动读写。`call` 可能改全局变量和 `static` 变量。

> 这一版最明显的两处冗余都留给优化：临时值从不复用，栈帧偏大；`char` 的 `andi` 有时连着两条。前者靠寄存器分配或槽复用，后者一条窥孔就够。
