# 题目要求解读

前三个实验都在读源程序：切词、搭树、查符号表。这一个实验开始写能跑的东西——把语义分析确认无误的语法树，翻成模拟器里真正能执行的机器码。

作业把这件事拆成两半：

| 半程 | 输入 | 输出 | 评测 |
| --- | --- | --- | --- |
| 中间代码生成 | 语法树 | 四元式序列（`ir.txt`） | 不评分，但必须自己看得懂 |
| 目标代码生成 | 四元式 | MIPS 汇编（`mips.txt`） | 只认这个：丢进 MARS 跑，比对输出 |

中间代码不评分，却是后一半的唯一输入，也是出错时唯一能分层定位的地方。目标代码才进评测，所以整篇文章的重心在后半程。

配置文件里写死了语言和目标：

```json
{
  "programmingLanguage": "Java",
  "objectCode": "MIPS"
}
```

实现语言随便，目标代码在 `MIPS` 和 `PCode` 里挑一个。我挑 MIPS：`mips.txt` 是纯汇编，扔进课程版 MARS 就能跑，调试链路最短。PCode 还要额外处理 `--compile` / `--interp` 两个参数，跟这个实验想练的东西无关。

## 输入与输出

| 文件 | 谁写 | 说明 |
| --- | --- | --- |
| `testfile.txt` | 评测机 | 唯一输入，程序自己不许读标准输入 |
| `error.txt` | 我的编译器 | 前面阶段有错时的唯一输出 |
| `ir.txt` | 我的编译器 | 四元式，调试用 |
| `mips.txt` | 我的编译器 | 提交物，评测只看这个 |

有一条规定决定了后面所有代码的写法：`error.txt` 只要有内容，就什么文件都不生成。

```java
/* 有错误时只输出 error.txt，错误的源程序不进入后续阶段 */
if (!errorManager.getErrorArrayList().isEmpty()) {
    writeErrorFile();
    return;
}
```

提前返回之后，代码生成器拿到的语法树一定是干净的。于是 `IrExpr`、`IrStmt` 里可以直接假设名字查得到、类型对得上，不用写一堆防御分支。

> 把“查错”和“翻译”分在两个阶段，好处是每个函数都不用背兜底逻辑。一边翻译一边检查的话，主干代码会被“万一这个变量没声明”的 if 淹没，读起来很痛苦。

## 编译器必须兑现的语义

题目只给文法，语义细节散在指导书和测试点里。动手前先把这张表过一遍：

| 语义 | 具体要求 |
| --- | --- |
| `int` | 32 位有符号，除法向零截断，`%` 余数跟随被除数 |
| `char` | 无符号 8 位，任何算术结果模 256（255+1=0，0-1=255） |
| 数组 | `int` 元素 4 字节，`char` 元素 1 字节，下标从 0 开始，不查越界 |
| 数组传参 | 传首地址，形参长度未知 |
| `static` 局部变量 | 只初始化一次，跨调用保留，递归共享同一份 |
| 逻辑与 / 逻辑或 | 短路，右侧有副作用时求值顺序必须对 |
| `printf` | 先把所有实参求完，再逐段输出 |
| 运行时库 | `get_int` / `get_char` / `get_string` / `put_int` / `put_char` / `put_string` |

> 最后两条在 `ir.txt` 上就能看出来，所以评测器特别喜欢抓。短路写错，`f() || g()` 会多调一次 `g`；`printf` 顺序写错，输出会混进新值。这两处都不是“结果不对”那么明显，往往只在特定输入下暴露。

## 实验给的骨架

骨架比想象中完整：四元式的数据结构、操作码、字符串解码、格式串切分都写好了。真正要动手的是翻译规则。

| 文件 | 状态 | 作用 |
| --- | --- | --- |
| `ir/IrOp`、`Quad`、`IrValue`、`IrModule`、`IrFunction` | 现成 | 四元式的操作码、操作数、模块与函数结构 |
| `ir/IrConst`、`IrString`、`FormatString` | 现成 | 常量求值、字符串解码与转义、`printf` 格式串切段 |
| `ir/IrBuilder` | 现成 | 上下文：作用域栈、`break` / `continue` 栈、发射辅助 |
| `ir/IrDecl`、`IrExpr`、`IrStmt` | 要写 | 声明、表达式、语句的翻译规则 |
| `mips/MipsGenerator` | 要写 | 栈帧、指令选择、syscall |
| `opt/` | 骨架 | 优化 Pass 接口，留给竞速 |

> 建议先读 `IrOp` 的注释。每条指令的字段含义都写在里面，尤其 `STORE` 哪个字段是待存的值。这里记反，数组会全错，而且错得很像“数组没初始化”，容易往初始化方向查。

# 解题思路

## 为什么要多一道四元式

直接在语法树上生成汇编也能做，我试了十几行就退了。原因很实际：一棵 `AddExp` 里同时装着作用域、类型、控制流三件事，而一条四元式只描述两个输入、一个动作、一个输出。

一次只处理一件事，出错时才知道错在哪。

> 分层定位是最实在的好处。`ir.txt` 对、`mips.txt` 错，问题一定在后端；`ir.txt` 本身就错，问题在前端翻译。要是直接从语法树出汇编，某条 `lw` 的偏移偏了 4 字节，你没法判断是作用域绑错还是栈帧算错，两个原因指向完全不同的代码。
>
> 还有一层：优化要在中间代码上跑常量传播、复写传播、死代码删除。这些工作在四元式上做很轻松，在汇编上几乎没法下手。

主流程因此长这样：

```java
/* 词法 / 语法 / 语义（前三个实验） */
...
if (!errorManager.getErrorArrayList().isEmpty()) {
    writeErrorFile();
    return;
}

/* 中间代码生成（四元式）：此时程序已确认无错误 */
IrModule module = IrBuilder.build(compUnit);
if (OPTIMIZE) {
    module = Optimizer.optimize(module);
}
if (WRITE_IR_OUTPUT) {
    IrWriter.write(module, envInitializer.irPath);
}

/* 目标代码生成（MIPS）：评测机只读 mips.txt */
if (GENERATE_MIPS) {
    MipsGenerator.write(module, envInitializer.mipsPath);
}
```

三个布尔开关（`WRITE_IR_OUTPUT`、`GENERATE_MIPS`、`OPTIMIZE`）就是这一阶段全部的对外接口，调试时随手关掉哪个都行。

## 四元式长什么样

一条四元式固定四个字段 `(op, arg1, arg2, target)`。`op` 是动作，`arg1` / `arg2` 是输入，`target` 是输出。

```
(assign, 源, -, 目标)                 目标 = 源
(add/sub/mul/div/mod, 左, 右, 目标)    目标 = 左 op 右
(neg, 源, -, 目标)                    目标 = -源
(not, 源, -, 目标)                    目标 = (源 == 0 ? 1 : 0)
(eq/ne/lt/le/gt/ge, 左, 右, 目标)      目标 = 比较结果（0/1）
(cast, 源, -, 目标)                   按目标类型转换，int→char 取低 8 位
(load, 数组, 下标, 目标)               目标 = 数组[下标]
(store, 数组, 下标, 值)                数组[下标] = 值
(addr, 变量/数组, -, 目标)             目标 = 首地址
(label, 标签, -, -)                   标签:
(goto, 标签, -, -)                    无条件跳转
(if, 条件, 标签, -)                    条件 != 0 跳转
(ifz, 条件, 标签, -)                   条件 == 0 跳转
(call, 函数, -, 目标) ; args: ...      目标 = 函数(实参...)
(ret, 值, -, -)                       返回
```

三处约定跟平时的习惯不一样，写之前得先记住。

比较单独成一条指令，不和跳转融合；条件跳转另有 `IF` / `IFZ`。`STORE` 的 `target` 是待存的值，下标在 `arg2`。`CALL` 塞不下任意多实参，`Quad` 给它单开了一条 `List<IrValue>`，打印成 `args: ...`。

> 比较为什么不直接和跳转合并：条件表达式和普通表达式要复用同一套比较逻辑，合并写法会让短路求值的标签数量翻倍。代价是多一次“比较结果搬进临时变量”的搬运，这点冗余留给后面的复写传播和条件跳转优化去消。
>
> `STORE` 反过来，是因为它写内存、不产生结果，`target` 只能放被写的值。我第一版按习惯写成 `(store, 数组, 值, 下标)`，跑出来数组元素全被写成常量下标，看着特别像“数组没初始化”。

## 操作数的六种形态

`IrValue` 把“值”统一成六种 kind，避免到处传字符串再猜含义：

| Kind | 字段约定 | 用在哪 |
| --- | --- | --- |
| `TEMP` | `t0`/`t1`…，函数内唯一 | 表达式中间结果 |
| `VAR` | 源码名字 + 标量/数组类型 + 长度 +（可选）汇编标签 | 变量、形参、数组 |
| `CONST` | 数值，`char` 一律规整到 0~255 | 字面量、标量常量 |
| `LABEL` | 带函数名前缀的汇编标签 | 分支目标 |
| `FUNC` | 函数名 | `CALL` 的 `arg1` |
| `STRING` | 汇编标签 + 已解码正文 | `printf` 字面量、`%s` |

用对象做 key，写后端时会轻松很多：栈槽表可以直接拿 `IrValue` 当索引。

> 拿名字做 key 会出事。两个不同作用域里的同名 `a` 是两个不同的 `IrValue`，但名字一样，会共用同一个槽，前一个块的值被后一个块覆盖。这种 bug 只在“变量遮蔽”时出现，大部分程序都正常，很难靠跑测试发现。

`VAR` 里那个可选的汇编标签，是存储位置的唯一线索：有标签说明它住在 `.data`，没标签说明它住在栈帧里，由后端分配偏移。

## 作用域要自己重建

语义分析结束时，`SymbolTable` 已经逐层 `exitScope()` 弹干净了，局部符号一个不剩。代码生成却需要“源码名字 → IR 值”的映射，所以 `IrBuilder` 又维护了一套作用域栈。

```java
/** 作用域栈：栈顶为当前作用域，栈底为全局作用域。 */
private final ArrayDeque<HashMap<String, IrValue>> scopes = new ArrayDeque<>();
```

这套表有独立用途，它和符号表管的事不一样。

> 符号表管“这个名字合不合法”：声明了没有、类型对不对、作用域对不对，语义阶段用完就丢。IR 环境管“这个名字翻译成哪个值”：是常量、是变量还是函数，住 `.data` 还是栈帧。两者都按作用域分层，边界必须严格对齐，对不齐就会查错对象。

进 `Block` 压栈、离开弹栈。唯一例外是函数体：形参和函数体共用一层，所以函数体走 `visitBlockItems` 而不是 `visitBlock`，否则 `int f(int a)` 里的 `a` 在函数体里就查不到。

名字解析出来只有五种归宿：

| 源码里的东西 | IR 里的形态 | 住在哪 |
| --- | --- | --- |
| 标量常量 | `CONST` | 不占存储，直接当立即数 |
| 常量数组 | `VAR` + 标签 | `.data` |
| 全局变量 / `static` 局部变量 | `VAR` + 标签 | `.data` |
| 普通局部变量 / 局部数组 | `VAR` 无标签 | 函数栈帧 |
| 函数名 | `FUNC` | 只在 `CALL` 里用 |

> 常量数组也进 `.data`，因为它内容不可变，没必要每次进函数重新初始化一遍。代价是标签必须全程序唯一（不同作用域允许重名），所以走 `IrModule.newDataLabel` 生成 `.d函数名_变量名_序号` 这种带前缀的标签。

## 求值顺序：物化

先解释这个词：物化（materialize）就是把“这个操作数此刻的值”立刻读进一个临时变量。之后别的代码再改原变量，手里这份值也不会变。

```java
/**
 * 把“可能被后续副作用改掉”的操作数立即读进临时变量。
 * CONST/TEMP/STRING 本身稳定，直接返回；VAR 标量发 assign；VAR 数组取地址。
 */
public static IrValue materialize(IrBuilder ctx, IrValue value) {
    if (value == null) {
        return null;
    }
    if (value.getKind() == IrValue.Kind.VAR) {
        if (value.isArray()) {
            IrValue address = ctx.newTemp(value.getType());
            ctx.emit(Quad.address(address, value, 0));
            return address;
        }
        IrValue temp = ctx.newTemp(value.getType());
        ctx.emit(Quad.assign(temp, value, 0));
        return temp;
    }
    return value;
}
```

需要物化的位置只有五处：

| 位置 | 为什么 |
| --- | --- |
| 双目运算的左操作数 | 右操作数可能调函数改掉它：`a + f()` |
| 函数实参 | 后面的实参可能改掉前面的：`f(a, g())` |
| `printf` 实参 | 都要先求完再输出 |
| `switch` 表达式 | 只求值一次，后面比较链要反复读 |
| 赋值语句的下标 | 右值可能改掉下标变量：`a[i] = i + 1` |

> 每一处都对应一种具体的副作用。`a + f()` 里 `f()` 可能改 `a`，先读 `a` 才不会拿新值去加。`f(a, g())` 里 `g()` 可能改 `a`。`a[i] = i + 1` 里右值会改 `i`，地址得用旧下标算。不物化的话，结果取决于“求值顺序碰巧是哪个”，换台机器或改个写法就变。

代价是 `ir.txt` 里 `assign` 明显变多，读起来啰嗦。这笔开销花在正确性上，性能的账留给复写传播去还。

## char：无符号 8 位

`char` 看着像 `int`，因为 IR 里它确实用 `int` 承载。差别在落内存：它只占 1 字节，而且任何算术结果都要模 256。

整个实现靠两条约束撑着。

任何 `char` 类型的算术结果，后面紧跟一条 `cast` 回 `char`：

```java
private static IrValue emitBinary(IrBuilder ctx, IrOp op, IrValue left, IrValue right,
                                 ValueType type, int line) {
    IrValue result = ctx.newTemp(type);
    ctx.emit(Quad.binary(op, left, right, result, line));
    if (type == ValueType.CHAR) {
        return castTo(ctx, result, ValueType.CHAR, line); // 再 andi 0xFF
    }
    return result;
}
```

> `char c = 250; c = c + 10;` 应该得到 4。少了这条 `cast` 就是 260，用 `%c` 打出来是乱码。把 `cast` 塞进 `emitBinary` 一处，就不会漏；散在各个表达式里写，迟早漏一支。

第二条：读用 `lbu`，写用 `sb`。判断散在四个地方——标量读写、数组元素读写、`.data` 段初始化、栈帧大小计算——都要看元素的 `baseType()`。

> IR 里统一用 `int` 承载，是因为四元式只有 32 位整数这一种值。`char` 只是“落内存时占 1 字节”，所以类型信息不能在半路丢掉，必须一路带到生成指令的那一刻，由它决定 `lw`/`sw` 还是 `lbu`/`sb`。

`char` 和 `int` 不能混算。这条语义阶段已经拦掉了（错误码 e），所以 IR 里不会出现混合类型的二元运算，`resultType()` 只是兜底。

## 控制流：真 / 假两个标签

条件不产生 0/1 的值，直接跳到“成立”或“不成立”的标签：

```java
public static void visitCond(IrBuilder ctx, Cond cond, String trueLabel, String falseLabel) {
    if (cond == null || cond.getLOrExp() == null) {
        ctx.emitGoto(falseLabel);
        return;
    }
    visitLOrExp(ctx, cond.getLOrExp(), trueLabel, falseLabel);
}
```

短路就藏在这段递归里：

```java
private static void visitLOrExp(IrBuilder ctx, LOrExp lOrExp,
                                String trueLabel, String falseLabel) {
    ...
    // 左边为真直接成功；否则才求右边。
    String nextLabel = ctx.newLabel();
    visitLOrExp(ctx, lOrExp.getLeft(), trueLabel, nextLabel);
    ctx.emitLabel(nextLabel);
    visitLAndExp(ctx, lOrExp.getRight(), trueLabel, falseLabel);
}
```

左半部分为真就跳到 `trueLabel`，右半部分的代码根本没执行。

> 短路不需要专门写代码。写 `a || b` 时，先生成“a 为真就跳成功标签”的判断，再在它后面放 b 的判断；a 真的时候已经跳走了，b 的代码自然被跳过。`&&` 完全对称，左边为假直接跳 `falseLabel`。靠标签的位置实现语义，比在条件里塞标志位干净得多。

`if` 和 `while` 只是给这套机制配标签：

```java
private static void visitIf(IrBuilder ctx, Stmt stmt) {
    String thenLabel = ctx.newLabel();
    String endLabel = ctx.newLabel();
    String elseLabel = stmt.hasElse() ? ctx.newLabel() : endLabel;

    visitCond(ctx, stmt.getCond(), thenLabel, elseLabel);
    ctx.emitLabel(thenLabel);
    visitStmt(ctx, stmt.getThenStmt());

    if (stmt.hasElse()) {
        ctx.emitGoto(endLabel);
        ctx.emitLabel(elseLabel);
        visitStmt(ctx, stmt.getElseStmt());
    }
    ctx.emitLabel(endLabel);
}
```

没有 `else` 时把 `elseLabel` 直接指成 `endLabel`，省掉一个空标签和一个跳转。`while` 把条件标签登记成 `continue` 的目标——`continue` 要回到条件判断，不是循环体开头。

> `continue` 落到条件标签，这一条写错就是死循环：跳过条件判断直接回循环体，循环变量不更新，条件永远成立。

`switch` 稍微绕一点。实测的 IR 是这样（源码 `int i = 0; switch (i) { case 0: A; case 1: B; break; default: C; }`）：

```text
(assign, i, -, t0)
(eq, t0, 0, t1)
(if, t1, .Lmain_0, -)
(eq, t0, 1, t2)
(if, t2, .Lmain_1, -)
(goto, .Lmain_2, -)      ← 都没命中就去 default
.Lmain_0:
... A ...
.Lmain_1:
... B ...
(goto, .Lmain_3, -)      ← break 跳到结束
.Lmain_2:
... C ...                ← default 在中间，仍然落在最后
.Lmain_3:
```

三个要点都在里面：表达式只求值一次（物化成 `t0` 后反复比较）；标签按源码顺序输出，不自动跳结束；`default` 可以在任意位置。

> “落穿”是 C 的语义：一个 `case` 执行完没有 `break`，就顺着往下执行下一个 `case`。所以 `case` 之间不能自动加跳转，编译器只按源码顺序摆标签，跳不跳由 `break` 决定。上面 `A` 执行完直接落进 `.Lmain_1`，就是落穿。

`break` / `continue` 靠两个栈：

```java
/** break 目标（while 的循环出口 / switch 的结束标签），内层在栈顶。 */
private final ArrayDeque<String> breakTargets = new ArrayDeque<>();
/** continue 目标（while 的条件判断标签），内层在栈顶。 */
private final ArrayDeque<String> continueTargets = new ArrayDeque<>();
```

> `switch` 只压 `break`，不压 `continue`。于是 `switch` 里的 `continue` 会自然找到外层 `while`，这正是 C 的语义。图省事把两个栈合成一个，这个测试点必挂：`continue` 会跳到 `switch` 结束，而不是外层循环。

## printf：先算完，再输出

格式串先切成段，再把所有实参算完、逐个物化，最后才按段输出。

```java
List<FormatString.Segment> segments = FormatString.parse(raw);

List<IrValue> arguments = new ArrayList<>();
List<Exp> args = stmt.getArgs();
for (int i = 0, n = args.size(); i < n; i++) {
    IrValue value = IrExpr.materialize(ctx, IrExpr.visitExp(ctx, args.get(i)));
    ...
    arguments.add(value);
}
```

顺序反了会错在哪，这里有个现成的例子。

> `printf("a=%d b=%d\n", x, f())` 里 `f()` 改了 `x`。边输出边求值，第一个 `%d` 打的是调用 `f` 之前的值，第二个打的是新值；先全部求值再输出，两个都是调用前的值。C 的行为是后者。

段到调用的映射很直接：

| 段 | 生成 |
| --- | --- |
| 字面量 | `put_string`（空串跳过） |
| `%d` | `put_int` |
| `%c` | `put_char` |
| `%s` | `put_string`（实参是数组首地址） |

字面量走字符串常量池，相同内容自动复用同一个 `.strN` 标签。

## 从四元式到 MIPS：一套自己定的约定

MARS 只跑这个程序，不要求和外部 ABI 一致，调用约定可以自己定。我选了最省事的一种：不做寄存器分配，临时值全落栈槽，实参全走栈。

```text
fp + 0            局部变量 / 形参（数组按元素大小预留）
fp + ...          临时变量槽（每个 4 字节）
fp + frameSize-8  旧 $fp
fp + frameSize-4  $ra
fp + frameSize    调用方实参区（第 i 个实参在 fp+frameSize+4*i）
```

这个布局按“会用到的东西”顺序摆：局部量、临时量、保存现场，最后是实参区。

> 实参区放在 `frameSize` 之外，因为那块内存是调用方压出来的（`addiu sp,sp,-4n`），被调函数只按偏移去读。把“谁分配、谁释放”分清之后，递归和嵌套调用就自动正确：每层都有自己的 `fp`，临时值不跨 `call` 依赖寄存器，`$ra` 也存在自己的栈帧里，不用写保护。

代价是没有寄存器分配。带 `while` 和函数调用的样例里，`main` 的栈帧是 80 字节，大半是临时变量槽。

栈槽表用 `IdentityHashMap`，key 是 `IrValue` 对象本身：

```java
private static Map<IrValue, Integer> offsets = new IdentityHashMap<>();
```

> 用名字做 key 的后果前面提过：同名不同作用域的变量会撞槽。`IdentityHashMap` 比的是对象地址，两个 `IrValue` 永远不相等，天然分开。

## 指令选择

MIPS 没有三操作数乘法，也没有 `sgt` / `sle` / `sge`，每条四元式都得凑出来：

| 四元式 | 生成的指令 |
| --- | --- |
| `assign` | 读源 → `$t0`，写 `$t0` → 目标 |
| `add` / `sub` | `addu` / `subu` |
| `mul` | `mult` + `mflo` |
| `div` / `mod` | `div` + `mflo` / `mfhi` |
| `neg` | `subu $t2, $zero, $t0` |
| `not` | `sltu` + `xori 1` |
| `eq` | `xor` + `sltiu 1` |
| `ne` | `xor` + `sltu` |
| `lt` / `gt` | `slt`（`gt` 交换两个操作数） |
| `le` / `ge` | `slt` 反向 + `xori 1` |
| `cast` → char | `andi 0xFF` |
| `load` | 基址 + 下标 `sll 2`（int）+ `lw` / `lbu` |
| `store` | 同上 + `sw` / `sb` |
| `addr` | `la` / `addiu $fp` / `lw`（数组形参取指针） |
| `if` / `ifz` | `bne $zero` / `beq $zero` |
| `ret` | 读进 `$v0` + `j .L函数名_end` |

下面两处最容易写错。

`le` / `ge` 写成“反向 `slt` 再取反”。

> MIPS 只有 `slt rd, rs, rt`，判断 `rs < rt`。`a <= b` 等价于 `!(b < a)`，所以先算 `slt $t2, $t1, $t0`（`b < a`），再 `xori $t2, $t2, 1`。`ge` 同理。写成 `slt` 加 `beq` 也能做，但要多一个标签，条件表达式里标签会成倍膨胀。

`char` 的掩码可能出现两次：`CAST` 自己 `andi` 一次，写回 char 临时槽时 `emitStore` 又掩一次，真实输出里能看到连着两条 `andi $t0,$t0,0xFF`。

> 这是冗余，不影响正确性，属于窥孔优化该删的东西。知道它是冗余，比把它当成 bug 去“修”省事。

## 数据段

`.data` 里四类东西：全局变量、`static` 局部变量、常量数组、字符串常量。

```text
.align 2
g:
    .word 1, 2, 0, 0
.align 0
c:
    .byte 65
.align 0
.str0:
    .asciiz "s="
```

规则尽量简单：`int` 按 4 字节对齐（`.align 2`），`char` 按字节（`.align 0`）；数组无初值用 `.space` 预留；标量无初值写 `.word 0`（`char` 写 `.byte 0`）；有初值就整列写出来，未写到的元素补 0。全 0 的初值用空列表表示，后端看到空列表直接输出 `.space`，省数据段体积。

> 字符串要 `decode` 再 `escapeForAsciiz`，两次都不能省。`decode` 把 `\n` 变成真正的换行字节，供 `char[]` 初始化和 `%s` 使用；`escapeForAsciiz` 再把真字节变回 `\n` 这种转义写法，因为汇编器只认转义。只做前者，引号和反斜杠会把汇编器搞崩；做两次 `decode`，一个换行会变成两个。

## IrBuilder：三个栈和一次预扫描

`IrBuilder` 自己不翻译任何语法成分，只做四件事：遍历编译单元、维护作用域、发标签和临时变量、管 `break` / `continue`。

函数返回类型在动手翻译前就要扫一遍：

```java
// 先登记所有函数的返回类型：允许函数体里调用“后面才定义”的函数。
List<FuncDef> funcDefs = compUnit.getFuncDefs();
for (int i = 0, n = funcDefs.size(); i < n; i++) {
    FuncDef def = funcDefs.get(i);
    if (def != null && def.getIdent() != null) {
        functionReturnTypes.put(def.getIdent().getName(), returnTypeOf(def.getFuncType()));
    }
}
```

> 调用表达式得知道返回类型，才能决定要不要开一个临时变量接 `$v0`。只看当前函数的话，`f()` 调 `g()` 而 `g` 定义在后面，就查不到类型。运行时库（`get_int` 等）的符号早就没了，靠 `functionReturnType` 兜底。

函数名也要先登记再翻译函数体：

```java
String name = funcDef.getIdent().getName();
IrFunction fn = module.addFunction(name, returnType, false);
declare(name, IrValue.func(name)); // 全局作用域
```

顺序反了，递归调用自己就查不到自己。

## IrExpr：从下往上，一层一值

表达式部分的结构和语法树层级完全同构，每个 `visitXxx` 返回“存放这个表达式值的操作数”。以 `a + b * 2` 为例：

```text
(assign, a, -, t0)     ← 物化左操作数
(assign, b, -, t1)
(mul, t1, 2, t2)       ← b * 2
(add, t0, t2, t3)      ← 合并
```

`AddExp` / `MulExp` 是左递归，翻译时天然递归：

```java
public static IrValue visitAddExp(IrBuilder ctx, AddExp addExp) {
    if (addExp.isUnary()) {
        return visitMulExp(ctx, addExp.getRight());
    }
    IrValue left = materialize(ctx, visitAddExp(ctx, addExp.getLeft()));
    IrValue right = visitMulExp(ctx, addExp.getRight());
    ValueType type = resultType(left, right);
    IrOp op = operatorOf(addExp.getOperator(), "+");
    return emitBinary(ctx, op, left, right, type, addExp.getLineNum());
}
```

注意单目形态的判断：语法树里 `AddExp` 只有一个子节点时，直接透传下层，不额外生成 `assign`。

> 否则 `int a = 1;` 这种最简单的语句也会产生一串无意义的搬运，`ir.txt` 会膨胀得没法看。

`LVal` 出现在“取值”位置时有四种情况，分清这四种是数组部分的关键：

| 目标 | 生成 | 说明 |
| --- | --- | --- |
| 标量常量 | 直接返回 `CONST` | 不生成任何指令 |
| 标量变量 | 直接返回 `VAR` | 由使用处读，少一条 `assign` |
| 数组带下标 | `load` | 结果类型是元素类型 |
| 数组不带下标 | `addr` | 首地址，用于传参和 `%s` |

函数调用把实参从左到右逐个求值，并立刻物化：

```java
for (int i = 0, n = exps.size(); i < n; i++) {
    IrValue value = materialize(ctx, visitExp(ctx, exps.get(i)));
    ...
    args.add(value);
}
```

> 防的是 `f(x, g())` 里 `g()` 改了 `x`。题目对多实参的副作用顺序没提要求，但既然写了顺序，就别让它变成“看运气”。

## IrDecl：先决定住在哪，再摊开初值

声明部分的复杂度全在“这个东西该住在哪”和“初值怎么摊开”：

| 声明 | 存储 | 初始化时机 |
| --- | --- | --- |
| 标量常量 | 无 | 编译期求值，变成立即数 |
| 常量数组 | `.data` | 编译期求值，写进数据段 |
| 全局变量 | `.data` | 进程启动，无初值为 0 |
| `static` 局部变量 | `.data` | 只初始化一次 |
| 普通局部变量 | 栈帧 | 运行到这里时赋值，无初值不清零 |
| 局部数组（有初值） | 栈帧 | 运行到这里时逐元素 `store` |

局部数组的初始化是一段循环：

```java
if (init.isBraced()) {
    List<Exp> exps = init.getExps();
    for (int i = 0; i < count; i++) {
        IrValue value = i < exps.size() ? IrExpr.visitExp(ctx, exps.get(i))
                : zeroOf(baseType);
        ...
        storeElement(ctx, variable, i, value, line);
    }
}
```

`int a[5] = {1};` 会生成 5 条 `store`：一条 1，四条 0。

> “没有初始化列表”和“初始化列表没写满”是两件事。前者是局部变量的不定值，不清零；后者按 C 的规则，未覆盖部分视为 0，必须补。混在一起处理，要么多清零，要么漏补 0。

`char[]` 用字符串初始化，三条长度规则容易记混：

| 关系 | 行为 |
| --- | --- |
| 字符串长度 L < 数组长度 N | 复制 L 字节，其余补 0 |
| L == N | 复制 N 字节，不额外补 `'\0'` |
| L > N | 只复制前 N 字节，不补 `'\0'` |

> 后面两种情况不补结束符，看着像笔误，实际是 SysY 的规定。补了就会多写一个字节，踩到相邻变量上。

## IrStmt：一个 switch，一处例外

`visitStmt` 是一个 `switch`，赋值、表达式、块、`if`、`while`、`switch`、`break`、`continue`、`return`、`printf` 各一段。其中 `visitBlockItems` 故意不带作用域：

```java
/** 在当前作用域中生成块内容（函数体用这个，避免多开一层）。 */
public static void visitBlockItems(IrBuilder ctx, Block block) {
```

语义阶段函数体 Block 和形参就是一层，代码生成必须对齐，否则形参查不到。

赋值语句只物化下标，右值不物化：

```java
IrValue index = IrExpr.materialize(ctx, IrExpr.visitExp(ctx, lVal.getIndex()));
...
IrValue value = IrExpr.visitExp(ctx, stmt.getExp());
if (value != null) {
    ctx.emit(Quad.store(value, target, index, stmt.getLineNum()));
}
```

> `a[i] = i + 1` 里右值会改 `i`。地址必须用物化过的旧下标算，否则算出来的地址跟着 `i` 变了。

## MipsGenerator：序言、正文、尾声

函数输出分三段。序言：

```java
out.append(function.getName()).append(":\n");
out.append("    addiu $sp, $sp, -").append(frameSize).append('\n');
out.append("    sw $fp, ").append(frameSize - 8).append("($sp)\n");
out.append("    sw $ra, ").append(frameSize - 4).append("($sp)\n");
out.append("    move $fp, $sp\n");
```

接着把调用方压在栈上的实参搬进形参槽：

```java
int incoming = frameSize + 4 * i;
out.append("    lw $t0, ").append(incoming).append("($fp)\n");
out.append("    sw $t0, ").append(offset).append("($fp)\n");
```

> 数组形参搬过来的是指针，值本身就是地址，所以这里不区分标量和数组，都是搬一个 4 字节。

尾声里 `ret` 先把返回值放进 `$v0`，再跳到函数末尾的统一出口：

```java
case RET:
    if (quad.getArg1() != null) {
        emitLoad(quad.getArg1(), "$v0", function, out);
    }
    out.append("    j ").append(endLabel(function)).append('\n');
    break;
```

```java
out.append(endLabel).append(":\n");
if (function.isMain()) {
    out.append("    li $v0, ").append(SYS_EXIT).append('\n');
    out.append("    syscall\n");
} else {
    out.append("    move $sp, $fp\n");
    out.append("    lw $ra, ").append(frameSize - 4).append("($sp)\n");
    out.append("    lw $fp, ").append(frameSize - 8).append("($sp)\n");
    out.append("    addiu $sp, $sp, ").append(frameSize).append('\n');
    out.append("    jr $ra\n");
}
```

> 函数里有几个 `return` 都跳到同一个出口，保存和恢复现场只写一遍。入口写一次、出口写一次，中间无论怎么跳都不会漏。`main` 的出口是 `syscall 10`，MARS 跑完 `main` 就该结束。

栈帧分配按声明顺序往上堆：

```java
boolean paramArray = isArrayParam(local);
int size;
if (paramArray) {
    size = 4; // 数组形参只存首地址
} else if (local.getType() != null && local.getType().isArray()) {
    int count = Math.max(local.getArraySize(), 0);
    size = count * (local.elementType() == ValueType.CHAR ? 1 : 4);
} else {
    size = 4;
}
offsets.put(local, offset);
offset = align4(offset + Math.max(size, 0));
```

每个变量之后都重新 4 字节对齐，`char` 数组后面紧跟的 `int` 不会错位。临时变量则把全部四元式扫一遍收集：

```java
for (Quad quad : function.getQuads()) {
    offset = allocateTemp(quad.getTarget(), offset);
    offset = allocateTemp(quad.getArg1(), offset);
    offset = allocateTemp(quad.getArg2(), offset);
```

> 每个临时变量一个槽，从不复用。这个做法很笨，但保证“临时值在任何时候重读都拿得到”。栈帧大一点无所谓，正确性优先，槽复用留给优化阶段。

取地址的三分支是数组部分唯一的难点：

```java
case VAR:
    if (value.getStorageLabel() != null) {
        out.append("    la ").append(register).append(", ")
                .append(value.getStorageLabel()).append('\n');
    } else {
        Integer offset = offsets.get(value);
        int off = offset == null ? 0 : offset;
        if (isArrayParam(value)) {
            out.append("    lw ").append(register).append(", ")
                    .append(off).append("($fp)\n");
        } else {
            out.append("    addiu ").append(register).append(", $fp, ")
                    .append(off).append('\n');
        }
    }
    break;
```

全局和静态用 `la`，局部数组用 `addiu $fp, 偏移`，数组形参要再 `lw` 一次。

> 数组形参的槽里存的是指针，不是数组本体，所以要解一次引用。第三分支漏了，`sum(a, 3)` 会读到栈上的垃圾。`lw $t0, 0($fp)` 和 `addiu $t0, $fp, 0` 只差一个字符，语义差一次间接寻址，是最容易看漏的地方。

调用和运行时库分工明确：

```java
if (isRuntime(name)) {
    emitRuntimeCall(name, args, out);
    ...
}
if (argCount > 0) {
    out.append("    addiu $sp, $sp, -").append(4 * argCount).append('\n');
}
for (int i = 0; i < argCount; i++) {
    emitLoad(args.get(i), "$t0", function, out);
    out.append("    sw $t0, ").append(4 * i).append("($sp)\n");
}
out.append("    jal ").append(name).append('\n');
if (argCount > 0) {
    out.append("    addiu $sp, $sp, ").append(4 * argCount).append('\n');
}
```

syscall 编号：`get_int`=5、`get_char`=12、`get_string`=`v0=8`（`a0` 缓冲区、`a1` 长度）、`put_int`=1、`put_char`=11、`put_string`=4。

> 这几个数写反了就是“输出乱码但程序不崩”，特别难查。压栈和回收也要配成一对写：`addiu sp, sp, -4n` 之后忘了加回来，每调一次栈就往下掉一截，递归几层就爆。

```text
    sw $t0, 12($fp)         ← 物化 i
    lw $t0, 12($fp)
    li $t1, 4
    slt $t2, $t0, $t1
    sw $t2, 16($fp)
    lw $t0, 16($fp)
    bne $t0, $zero, .Lmain_1
    j .Lmain_2
```

`80 = 3 个局部量（12）+ 15 个临时变量（60）+ 旧 fp / ra（8）`，一算就对得上。数组寻址和调用：

```text
    la $t0, g
    lw $t1, 0($fp)
    sll $t1, $t1, 2
    addu $t0, $t0, $t1
    lw $t2, 0($t0)
    sw $t2, 24($fp)
    addiu $sp, $sp, -8
    lw $t0, 20($fp)
    sw $t0, 0($sp)
    lw $t0, 24($fp)
    sw $t0, 4($sp)
    jal add
    addiu $sp, $sp, 8
    sw $v0, 28($fp)
```

被调函数读到的实参偏移是 `fp+24`、`fp+28`，和调用方压的位置一一对应。数组形参可以对照 `sum`：

```text
# ---- sum ----
sum:
    addiu $sp, $sp, -52
    ...
    lw $t0, 52($fp)         ← arr 形参：拿到的是指针
    sw $t0, 0($fp)
    lw $t0, 56($fp)         ← n
    sw $t0, 4($fp)
    ...
.Lsum_1:
    lw $t0, 0($fp)          ← 解引用，取数组首地址
    lw $t1, 8($fp)
    sll $t1, $t1, 2
    addu $t0, $t0, $t1
    lw $t2, 0($t0)
```

# 自测方法

评测是黑盒的，但这一阶段比语法分析好自测，因为输出可以对着跑。

## 三层验证

1. 先看 `ir.txt`。它比汇编好读得多，翻译规则对不对，看四元式就能判断八分：`char` 加法后面有没有 `cast`、循环有没有回到条件标签、`printf` 的实参是不是在调用前就落好了。
2. 再看 `mips.txt` 能不能跑。课程版 MARS 打开、汇编、运行，比对预期输出。MARS 报错会给行号，比对着机器码猜强太多。
3. 最后拿 C 对照。同一个 SysY 程序手改成 C（几乎不用改），`gcc` 跑一遍拿标准答案，比自己算期望值可靠。`char` 的回绕用 `unsigned char` 语义完全对得上。

> 先看 `ir.txt` 是因为它能省掉一半调试时间。汇编错了，你还要判断是翻译错还是生成错；四元式错了，问题就在前半程，范围小得多。

## 逐条回归的边界清单

这份清单是我实际用过的，按“最容易漏”排序：

- [ ] `char` 回绕：`255+1`、`0-1`、`char` 的一元负号
- [ ] `char` 数组下标：元素 1 字节，`sll` 不能加
- [ ] 局部数组有初值但没写满：后面必须补 0
- [ ] `char[] = "..."` 三种长度：L<N、L==N、L>N
- [ ] 数组形参跨函数透传（`f(a)` 里再 `g(a)`）
- [ ] 全局数组只有部分初值
- [ ] `static` 跨调用保留（连续两次调用结果不同）
- [ ] 两个同名局部变量分处不同块（栈槽不能撞）
- [ ] `printf` 实参里有函数调用，且函数改了前面的实参
- [ ] `switch` 落穿、`switch` 里的 `continue`、`default` 在中间
- [ ] 短路：`f() || g()` 里 `g` 不该被调用
- [ ] 递归（斐波那契、阶乘）
- [ ] 多实参、嵌套调用（`f(g(1), h(2))`）
- [ ] `get_char` / `get_string` / `get_int` 混合输入
- [ ] 空语句、空循环体、空 `if` 分支
- [ ] `void` 函数、`void` 函数里的 `return;`

> 空语句、空循环体这类别觉得评测不会考。它们会暴露“标签配好了但中间没有指令”的结构问题，先在自己造的例子上过一遍，比在评测机上撞运气便宜。

## 我这一版的实测结果

- A/B/C 三套公共测试库共 60 组：59 组通过；
- 未通过的 B-5 是 MARS 4.5 命令行下 `get_char` 之后继续 `get_string` 触发 `SystemIO.readString` 的 `input is null`——模拟器 stdin 的限制，去掉这段输入序列后生成的代码输出正确；
- 全量 `javac --release 17` 编译通过；
- `mips.txt` 用课程版 MARS 打开可直接运行。

> 这组结果说明“代码没错”和“评测全过”之间还隔着模拟器。遇到后者，先确认是不是模拟器行为，别急着改代码生成。

# 踩坑记录

按被坑的先后顺序记，每条都对应一处具体实现。

1. **栈槽表用变量名做 key。** 两个块里的同名 `a` 共用一个槽，前一个块的值被后一个块覆盖。改成 `IdentityHashMap`、用 `IrValue` 对象做 key 才对。这个 bug 的特点是“大部分程序都对”，只有遮蔽的情形错。

2. **`printf` 只记住变量名，没物化。** `printf("%d %d\n", x, f())` 里 `f()` 改了 `x`，输出时读到的是新值。改成“先全部求值、再逐段输出”后消失。

3. **数组形参直接 `addiu $fp, 偏移`。** 槽里存的是指针，我把它当地址用，读到的是栈上的垃圾。`isArrayParam` 那个分支就是为它加的。

4. **`store` 的字段记反。** 写成 `(store, 数组, 值, 下标)`，结果数组元素全被写成常量下标，看起来像“数组没初始化”。

5. **局部数组有初值但漏补 0。** `int a[5] = {1};` 只写了第一格，后面四格是不定值。C 的规则是“初始化列表未覆盖部分为 0”，和“没有初始化列表”必须分开处理。

6. **`char` 忘了 `cast`。** `255+1` 得到 256，打印成 `%c` 就乱。这条不可能只漏一处，所以我把 `cast` 塞进了 `emitBinary`，只写一遍。

7. **`le` / `ge` 用 `slt` 写错方向。** `a <= b` 写成 `slt $t2,$t0,$t1`（`a < b`），差一个等号。正确是反向 `slt` 再 `xori`。

8. **`switch` 里 `break` 跳错层。** 我把 `break` / `continue` 合成了一个栈，`switch` 里的 `continue` 跳到了 `switch` 结束而不是外层循环。分成两个栈后消失。

9. **`static` 变量放进了栈帧。** 每次进函数都重新初始化，`static` 的意义全没了。凡是 `static` 一律进 `.data`，和全局变量同一套逻辑。

10. **`main` 不是第一条指令。** 评测器按默认入口取第一条指令，前面先输出了用户函数，`main` 就找不到。`emitText` 里先输出 `main`、再输出其余函数，并给它加 `.globl main`。

11. **字符串转两次或一次都没转。** `decode` 之后再 `decode`，`\n` 变两次；只 `decode` 不 `escape`，`.asciiz` 里的引号和反斜杠会把汇编器搞崩。正确顺序是 `decode` → `escapeForAsciiz`。

12. **调用后忘记回收 `sp`。** `addiu sp, sp, -4n` 之后没加回来，每调一次栈就往下掉一截，递归几层就爆。

> 前十一条都是“错得出来”，最后一条是“错得看不出来”：程序跑完不报错，只是栈越跑越深。这类问题只能靠盯代码结构，写的时候把压栈和回收配成一对。

# 留给代码生成二

优化部分这版只留了骨架：

```java
public interface IrPass {
    String name();
    void run(IrModule module);
}
```

```java
private static final List<IrPass> PASSES = new ArrayList<>();
public static IrModule optimize(IrModule module) {
    for (IrPass pass : PASSES) {
        pass.run(module);
    }
    return module;
}
```

`Compiler` 里用 `OPTIMIZE` 一个开关统一控制，现在的 `PASSES` 是空的，打开也不改变输出。

要接的话，按收益从易到难排：常量折叠 → 复写传播 + 死代码删除 → 局部公共子表达式 → 强度削弱（乘除常数改成移位）→ 控制流简化（常量条件跳转、不可达标签）→ 窥孔（相邻冗余 `load` / `store`）。

有两条红线，优化再激进也不能碰：

- 不能改变可观察行为：I/O 顺序、短路带来的副作用、`printf` 先求值后输出、`static` 状态；
- 不要跨越 `call` 随意搬动读写。`call` 可能改任何全局变量和 `static` 变量，把一次读提到 `call` 之前就是错的。

> 这一版最明显的两处冗余，都留给优化：临时变量从不多复用，栈帧偏大；`char` 的 `andi` 有时连着两条。前者靠寄存器分配或栈槽复用解决，后者一条窥孔就够。

代码生成没有“聪明”的地方：四元式一条一条翻，栈帧一次一次算，指令一条一条选。能过评测靠的是把每个边界都想到——`char` 的 256、数组的 1 字节、`static` 只初始化一次、`printf` 先算后印。
