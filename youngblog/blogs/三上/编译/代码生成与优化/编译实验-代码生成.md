# 题目要求解读

## 题目要求

前三个阶段都在“理解”源程序，这一阶段开始“生产”：把语义分析确认无误的语法树，翻译成能真正跑起来的机器码。

作业把这件事拆成两半：

| 半程 | 输入 | 输出 | 考核 |
| --- | --- | --- | --- |
| 中间代码生成 | AST | 四元式序列（`ir.txt`） | 不考核，但必须自己看得懂 |
| 目标代码生成 | 四元式 | MIPS 汇编（`mips.txt`） | 只认这个：丢进 MARS 跑，比对输出 |

`config.json` 里写的是：

```json
{
  "programmingLanguage": "Java",
  "objectCode": "MIPS"
}
```

实现语言随意（我用 Java），目标代码在 `MIPS` 和 `PCode` 里二选一。我选 MIPS：`mips.txt` 是纯汇编，丢进课程版 MARS 直接能跑，调试链路最短。PCode 那条路还要额外处理 `--compile` / `--interp` 两个参数，跟本实验的关注点无关。

一句话概括本题：**这一阶段只有一个标准——编译出来的程序能跑对。**

## 输入与输出

| 文件 | 谁写 | 说明 |
| --- | --- | --- |
| `testfile.txt` | 评测机 | 唯一输入，程序自己不许读标准输入 |
| `error.txt` | 我的编译器 | 前面阶段有错时**唯一**输出 |
| `ir.txt` | 我的编译器 | 四元式，调试用，评测不看 |
| `mips.txt` | 我的编译器 | 提交物，评测只看这个 |

规则和上一阶段一脉相承：**只要 `error.txt` 非空，就什么都不生成**。`Compiler` 里用一个提前 `return` 保证这件事，于是代码生成器永远看不到带错的语法树——`IrExpr` / `IrStmt` 里可以放心假设“名字一定查得到、类型一定对”，不用写一堆防御分支。

## 编译器必须兑现的语义

题目只给文法，语义细节散在指导书和测试点里。动手前先把下面这张表过一遍，每一条都是评分点，也都是坑点：

| 语义 | 具体要求 |
| --- | --- |
| `int` | 32 位有符号，除法向零截断，`%` 余数跟随被除数 |
| `char` | **无符号 8 位**，任何算术结果模 256（255+1=0，0-1=255） |
| 数组 | `int` 元素 4 字节，`char` 元素 1 字节，下标从 0 开始，不查越界 |
| 数组传参 | 传首地址，形参长度未知 |
| `static` 局部变量 | 只初始化一次，跨调用保留，递归共享同一份 |
| 全局 / 局部同名 | 允许，靠作用域绑定 |
| 逻辑与 / 逻辑或 | 短路，右侧有副作用时求值顺序必须对 |
| `printf` | **先把所有实参求完，再逐段输出** |
| 运行时库 | `get_int` / `get_char` / `get_string` / `put_int` / `put_char` / `put_string` |

最后两条属于“评测器用输出抓你”的类型。`printf` 那条我一开始就踩了，后面细讲。

骨架比预想的完整：四元式的数据结构和约定都定好了，真正要动手的是“翻译规则”。

| `ir/IrString.java` | 现成 | 字符串解码与 `.asciiz` 转义 |
| `ir/FormatString.java` | 现成 | `printf` 格式串切段 |

# 解题思路

## 为什么中间要过一道四元式

直接 AST → MIPS 也能做，但我试了十几行就放弃了，原因有三条。

**一是距离太远。** 一棵 `AddExp` 里有作用域、类型、控制流三件事，一条四元式只有“两个输入、一个动作、一个输出”。一次只解决一件事，错误才不会互相污染。

**二是能分层定位。** `ir.txt` 对而 `mips.txt` 错，问题一定在后端；`ir.txt` 本身就错，问题在前端翻译。直接 AST → 汇编时，某个 `lw` 偏了 4 字节，你根本不知道是作用域绑错了还是偏移算错了。

**三是优化必须在这一层做。** 后续竞速要在中间代码上跑常量传播、复写传播、死代码删除，没人想在 MIPS 上做这些。

于是主流程长这样：

```java
/* 词法 / 语法 / 语义（前三个实验） */
...
/* 有错误时只输出 error.txt，错误的源程序不进入后续阶段 */
if (!errorManager.getErrorArrayList().isEmpty()) {
    writeErrorFile();
    return;
}

/* 中间代码生成（四元式）：此时程序已确认无错误 */
IrModule module = IrBuilder.build(compUnit);
if (OPTIMIZE) {
    module = Optimizer.optimize(module);
}
if (WRITE_IR_OUTPUT) {
    IrWriter.write(module, envInitializer.irPath);
}

/* 目标代码生成（MIPS）：评测机只读 mips.txt */
if (GENERATE_MIPS) {
    MipsGenerator.write(module, envInitializer.mipsPath);
}
```

三个布尔开关（`WRITE_IR_OUTPUT`、`GENERATE_MIPS`、`OPTIMIZE`）就是这一阶段全部的“对外接口”，调试时随手关掉哪个都行。

## 四元式的约定

一条四元式是 (op, arg1, arg2, target)，各 op 的含义如下：

```
(assign, 源, -, 目标)                 目标 = 源
(add/sub/mul/div/mod, 左, 右, 目标)    目标 = 左 op 右
(neg, 源, -, 目标)                    目标 = -源
(not, 源, -, 目标)                    目标 = (源 == 0 ? 1 : 0)
(eq/ne/lt/le/gt/ge, 左, 右, 目标)      目标 = 比较结果（0/1，int）
(cast, 源, -, 目标)                   按目标类型转换，int→char 取低 8 位
(load, 数组, 下标, 目标)               目标 = 数组[下标]
(store, 数组, 下标, 值)                数组[下标] = 值
(addr, 变量/数组, -, 目标)             目标 = 首地址
(label, 标签, -, -)                   标签:
(goto, 标签, -, -)                    无条件跳转
(if, 条件, 标签, -)                    条件 != 0 跳转
(ifz, 条件, 标签, -)                   条件 == 0 跳转
(call, 函数, -, 目标) ; args: ...      目标 = 函数(实参...)，void 时目标为空
(ret, 值, -, -)                       返回；void 时值为空
```

有三处设计值得单独说一下，因为它们直接决定了后面怎么写。

**比较单独成一条指令，不和跳转融合。** 这是骨架里就定好的取舍：条件表达式（尤其短路求值）和普通表达式复用同一套比较逻辑，代价是多一条“比较结果 → 临时变量 → 再判断”的搬运。这部分冗余留给后续的复写传播和条件跳转优化去消。

**`STORE` 的 target 是“待存的值”。** 平时习惯 `target` 是结果，这里唯独 `store` 反过来。第一版我把 `store` 写成 `(store, 数组, 值, 下标)`，跑出来的数组全是常量下标。

**`CALL` 额外挂一个 args 列表。** 三个字段塞不下任意多实参，所以 `Quad` 给 `CALL` 单开了一条 `List<IrValue>`。

## 操作数的六种形态

`IrValue` 把所有“值”统一成六种 kind，而不是到处传字符串再猜含义：

| Kind | 字段约定 | 用在哪 |
| --- | --- | --- |
| `TEMP` | `t0`/`t1`…，函数内唯一 | 表达式中间结果 |
| `VAR` | 源码名字 + 标量/数组类型 + 长度 + （可选）汇编标签 | 变量、形参、数组 |
| `CONST` | 数值，`char` 一律规整到 0~255 | 字面量、标量常量 |
| `LABEL` | 带函数名前缀的汇编标签 | 分支目标 |
| `FUNC` | 函数名 | `CALL` 的 arg1 |
| `STRING` | 汇编标签 + 已解码正文 | `printf` 字面量、`%s` |

用对象而不是字符串的好处，在写后端时体现得特别明显：栈槽表可以用 `IrValue` 做 key，两个不同作用域的同名变量天然是两个 key，不会撞在一起。这个坑我在语义阶段就预判到了，后文“踩坑记录”里有实测。

`VAR` 里那个“可选汇编标签”是存储位置的唯一线索：有标签说明它住在 `.data`，没标签说明它住在栈帧里，由后端分配偏移。

## 作用域得自己重建

语义分析结束时，`SymbolTable` 已经逐层 `exitScope()` 弹干净了局部符号。而代码生成需要把“源码名字”映射到“IR 值”，所以 `IrBuilder` 又维护了一套自己的作用域栈：

```java
/** 作用域栈：栈顶为当前作用域，栈底为全局作用域。 */
private final ArrayDeque<HashMap<String, IrValue>> scopes = new ArrayDeque<>();
```

这套表有独立用途：两张表要回答的问题不一样，符号表回答“这个名字合不合法”，IR 环境回答“这个名字翻译成哪个值”。

进入 `Block` 压栈、离开弹栈，边界和语义分析严格对齐。唯一的例外是函数体：形参和函数体**共用一层**，所以函数体走 `visitBlockItems` 而不是 `visitBlock`，否则 `int f(int a)` 里就查不到形参 `a` 了。

名字解析出来只有五种归宿：

| 源码里的东西 | IR 里的形态 | 住在哪 |
| --- | --- | --- |
| 标量常量 | `CONST` | 不占存储，直接当立即数 |
| 常量数组 | `VAR` + 标签 | `.data` |
| 全局变量 / `static` 局部变量 | `VAR` + 标签 | `.data` |
| 普通局部变量 / 局部数组 | `VAR` 无标签 | 函数栈帧 |
| 函数名 | `FUNC` | 只在 `CALL` 里用 |

常量数组也进 `.data`，是因为它内容不可变，没必要每次进函数都初始化一遍。代价是标签必须全程序唯一（不同作用域允许重名），所以走 `IrModule.newDataLabel` 生成 `.d函数名_变量名_序号` 这种带前缀的标签。

## 求值顺序：materialize

这是全篇第二个容易翻车的地方：**什么时候必须把值“落到临时变量”。**

```java
/**
 * 把“可能被后续副作用改掉”的操作数立即读进临时变量。
 * CONST/TEMP/STRING 本身稳定，直接返回；VAR 标量发 assign；VAR 数组取地址。
 */
public static IrValue materialize(IrBuilder ctx, IrValue value) {
    if (value == null) {
        return null;
    }
    if (value.getKind() == IrValue.Kind.VAR) {
        if (value.isArray()) {
            IrValue address = ctx.newTemp(value.getType());
            ctx.emit(Quad.address(address, value, 0));
            return address;
        }
        IrValue temp = ctx.newTemp(value.getType());
        ctx.emit(Quad.assign(temp, value, 0));
        return temp;
    }
    return value;
}
```

需要物化的位置有五个：

| 位置 | 为什么 |
| --- | --- |
| 双目运算的左操作数 | 右操作数可能调函数改掉它：`a + f()` |
| 函数实参 | 后面的实参可能改掉前面的：`f(a, g())` |
| `printf` 实参 | 都要先求完再输出 |
| `switch` 表达式 | 只求值一次，后面比较链要反复读 |
| 赋值语句的下标 | 右值可能改掉下标变量：`a[i] = i + 1` |

代价是每条 `a + b` 都多两条 `assign`，`ir.txt` 会显得很啰嗦。这笔开销花在正确性上，性能的账留给复写传播去还。

## char 的两条铁律

`char` 是这个实验里唯一“看着简单、死得最惨”的类型。整个实现只靠两条约束撑着。

**第一，任何 char 类型的算术结果，后面紧跟一条 `cast` 回 char。**

```java
private static IrValue emitBinary(IrBuilder ctx, IrOp op, IrValue left, IrValue right,
                                 ValueType type, int line) {
    IrValue result = ctx.newTemp(type);
    ctx.emit(Quad.binary(op, left, right, result, line));
    if (type == ValueType.CHAR) {
        return castTo(ctx, result, ValueType.CHAR, line); // 再 andi 0xFF
    }
    return result;
}
```

于是 `char c = 250; c = c + 10;` 得到 4 而不是 260。测试点里专门有一组 `255+1` 回绕，漏了这条就直接挂。

**第二，读用 `lbu`，写用 `sb`。**

`int` 和 `char` 在 IR 里都由 `int` 承载（0~255 的无符号值），差别只在“落到内存时占几个字节”。所以后端遇到 char 变量必须是 `lbu` / `sb`，遇到 int 才是 `lw` / `sw`。这个判断散在四个地方：标量读写、数组元素读写、`.data` 段初始化、栈帧大小计算——都要看元素的 `baseType()`。

还有一条隐含约束：**char 和 int 不能混算**。这一条语义阶段就拦掉了（错误码 e），所以 IR 里不会出现混合类型的二元运算，`resultType()` 只是兜底，正常程序走不到。

## 控制流：真 / 假双标签

条件生成直接跳到两个标签之一，不产生“0/1”这样的值：

```java
public static void visitCond(IrBuilder ctx, Cond cond, String trueLabel, String falseLabel) {
    if (cond == null || cond.getLOrExp() == null) {
        ctx.emitGoto(falseLabel);
        return;
    }
    visitLOrExp(ctx, cond.getLOrExp(), trueLabel, falseLabel);
}
```

`LOrExp` / `LAndExp` 都是二元递归，短路就藏在这段递归里：

```java
private static void visitLOrExp(IrBuilder ctx, LOrExp lOrExp,
                                String trueLabel, String falseLabel) {
    ...
    // 左边为真直接成功；否则才求右边。
    String nextLabel = ctx.newLabel();
    visitLOrExp(ctx, lOrExp.getLeft(), trueLabel, nextLabel);
    ctx.emitLabel(nextLabel);
    visitLAndExp(ctx, lOrExp.getRight(), trueLabel, falseLabel);
}
```

左半部分为真就跳到 `trueLabel`，**根本不会落到 `nextLabel` 之后的右半部分**——短路不需要额外代码，标签布局天然会跳过它。`&&` 完全对称：左边为假直接跳 `falseLabel`。

`if` 和 `while` 都只是给这套机制配标签：

```java
private static void visitIf(IrBuilder ctx, Stmt stmt) {
    String thenLabel = ctx.newLabel();
    String endLabel = ctx.newLabel();
    String elseLabel = stmt.hasElse() ? ctx.newLabel() : endLabel;

    visitCond(ctx, stmt.getCond(), thenLabel, elseLabel);
    ctx.emitLabel(thenLabel);
    visitStmt(ctx, stmt.getThenStmt());

    if (stmt.hasElse()) {
        ctx.emitGoto(endLabel);
        ctx.emitLabel(elseLabel);
        visitStmt(ctx, stmt.getElseStmt());
    }
    ctx.emitLabel(endLabel);
}
```

没有 `else` 时把 `elseLabel` 直接指成 `endLabel`，省掉一个空标签和一个跳转。`while` 则把**条件标签**同时登记成 `continue` 的目标——`continue` 落到条件判断处，不是循环体开头，这一条错了就是死循环。

`switch` 稍微绕一点，我实测的 IR 是这样的（源码 `int i = 0; switch (i) { case 0: A; case 1: B; break; default: C; }`）：

```text
(assign, i, -, t0)
(eq, t0, 0, t1)
(if, t1, .Lmain_0, -)
(eq, t0, 1, t2)
(if, t2, .Lmain_1, -)
(goto, .Lmain_2, -)      ← 都没命中就去 default
.Lmain_0:
... A ...
.Lmain_1:
... B ...
(goto, .Lmain_3, -)      ← break 跳到结束
.Lmain_2:
... C ...                ← default 在中间，仍然落在最后
.Lmain_3:
```

三个要点都在里面了：**表达式只求值一次**（物化成 `t0` 后反复比较）；**标签按源码顺序输出，不自动跳结束**（`A` 自然落进 `.Lmain_1`，这就是落穿）；**`default` 可以在任意位置**，只是最后的 `goto` 目标跟着它走。

`break` / `continue` 靠两个栈：

```java
/** break 目标（while 的循环出口 / switch 的结束标签），内层在栈顶。 */
private final ArrayDeque<String> breakTargets = new ArrayDeque<>();
/** continue 目标（while 的条件判断标签），内层在栈顶。 */
private final ArrayDeque<String> continueTargets = new ArrayDeque<>();
```

`switch` 只压 `break`，不压 `continue`，于是 `switch` 里的 `continue` 会自然找到外层 `while`——这正是 C 的语义。如果图省事把两者合并成一个栈，这个测试点必挂。

## printf：先求值，再输出

格式串先切成段：

```java
List<FormatString.Segment> segments = FormatString.parse(raw);

List<IrValue> arguments = new ArrayList<>();
List<Exp> args = stmt.getArgs();
for (int i = 0, n = args.size(); i < n; i++) {
    IrValue value = IrExpr.materialize(ctx, IrExpr.visitExp(ctx, args.get(i)));
    ...
    arguments.add(value);
}
```

**先循环把所有实参算完、全部落进临时变量，再按段输出。** 顺序反了会怎样？`printf("a=%d b=%d\n", x, f())` 里 `f()` 改了 `x`，边输出边求值就会先打印旧的 `x`。

段到调用的映射很直接：

| 段 | 生成 |
| --- | --- |
| 字面量 | `put_string`（空串跳过） |
| `%d` | `put_int` |
| `%c` | `put_char` |
| `%s` | `put_string`（实参是数组首地址） |

字面量走的是字符串常量池，相同内容自动复用同一个 `.strN` 标签——`printf("%d %d\n", a, b)` 里两个空格只会有一份数据。

## 从四元式到 MIPS：栈帧与调用约定

后端最省事的做法是**不用寄存器**：所有临时变量都落栈槽，所有实参都走栈。MARS 只运行本程序，不要求和外部 ABI 一致，所以可以自己定约定。

```text
fp + 0            局部变量 / 形参（数组按元素大小预留）
fp + ...          临时变量槽（每个 4 字节）
fp + frameSize-8  旧 $fp
fp + frameSize-4  $ra
fp + frameSize    调用方实参区（第 i 个实参在 fp+frameSize+4*i）
```

这个布局按“三个都会用到的东西”顺序摆出来：局部量、临时量、保存现场。实参区放在 `frameSize` 之外，是因为那块内存属于**调用方**（`addiu sp,sp,-4n` 压出来的），被调函数只是按偏移去读。

好处是递归、多参数、嵌套调用全都自动正确：临时值不跨 `call` 依赖寄存器，就不用写寄存器保护；`$ra` 存在自己栈帧里，嵌套调用随便打。

代价也很直接——**没有任何寄存器分配**。我那个带 `while` 和函数调用的样例，`main` 的栈帧是 80 字节，里面绝大多数是临时变量槽。这是留给竞速优化的空间。

栈槽表用 `IdentityHashMap`，key 是 `IrValue` 对象本身：

```java
private static Map<IrValue, Integer> offsets = new IdentityHashMap<>();
```

用名字做 key 会出大事：`{ int a; } { int a; }` 两块里的 `a` 是两个不同的 `IrValue`，但名字一样，会共用同一个槽，前一个块的值被后一个块覆盖。这个坑我实测过，见后文。

## 指令选择

MIPS 没有三操作数乘法，也没有 `sgt` / `sle` / `sge`，所以每条四元式都得“凑”出来：

| 四元式 | 生成的指令 |
| --- | --- |
| `assign` | 读源 → `$t0`，写 `$t0` → 目标 |
| `add` / `sub` | `addu` / `subu` |
| `mul` | `mult` + `mflo` |
| `div` / `mod` | `div` + `mflo` / `mfhi` |
| `neg` | `subu $t2, $zero, $t0` |
| `not` | `sltu` + `xori 1` |
| `eq` | `xor` + `sltiu 1` |
| `ne` | `xor` + `sltu` |
| `lt` / `gt` | `slt`（`gt` 交换两个操作数） |
| `le` / `ge` | `slt` 反向 + `xori 1` |
| `cast` → char | `andi 0xFF` |
| `load` | 基址 + 下标 `sll 2`（int）+ `lw` / `lbu` |
| `store` | 同上 + `sw` / `sb` |
| `addr` | `la` / `addiu $fp` / `lw`（数组形参取指针） |
| `if` / `ifz` | `bne $zero` / `beq $zero` |
| `ret` | 读进 `$v0` + `j .L函数名_end` |

两个细节值得记：

**`le` 为什么是“反向 slt 再取反”。** MIPS 只有 `slt rd,rs,rt`（rs < rt）。`a <= b` 等价于 `!(b < a)`，所以先算 `slt $t2,$t1,$t0`（`b < a`），再 `xori $t2,$t2,1`。`ge` 同理。写成 `slt` 加 `beq` 也能做，但会多一个标签，条件表达式里标签会成倍膨胀。

**`char` 的掩码可能出现两次。** `CAST` 自己 `andi` 一次，写回 char 临时槽时 `emitStore` 又掩一次。真实输出里能看到连着两条 `andi $t0,$t0,0xFF`。这不影响正确性，属于后续窥孔优化该删的冗余——知道它是冗余，比以为它是 bug 去“修”要省事得多。

## 数据段

`.data` 里四类东西：全局变量、`static` 局部变量、常量数组、字符串常量。

```text
.align 2
g:
    .word 1, 2, 0, 0
.align 0
c:
    .byte 65
.align 0
.str0:
    .asciiz "s="
```

规则尽量简单：`int` 按 4 字节对齐（`.align 2`），`char` 按字节（`.align 0`）；数组无初值用 `.space` 预留；标量无初值写 `.word 0`（`char` 则是 `.byte 0`）（`.data` 段在进程启动时本来就是零）；有初值就整列写出来，未写到的元素补 0。

字符串要先 `decode`（把 `\n` 之类变成真字符）、再 `escapeForAsciiz`（把真字符变回 `\n` 这类汇编转义）再塞进 `.asciiz`。两次转换不能省任何一次，也不能合并——解码是为了 `char[]` 初始化时拿到正确的字节，转义是为了汇编器能读懂。

## IrBuilder：三个栈与一次预扫描

`IrBuilder` 自己不翻译任何语法成分，只做四件事：遍历编译单元、维护作用域、发标签和临时变量、管 `break` / `continue`。

有一个容易被忽略的细节——**函数返回类型要预扫描**：

```java
// 先登记所有函数的返回类型：允许函数体里调用“后面才定义”的函数。
List<FuncDef> funcDefs = compUnit.getFuncDefs();
for (int i = 0, n = funcDefs.size(); i < n; i++) {
    FuncDef def = funcDefs.get(i);
    if (def != null && def.getIdent() != null) {
        functionReturnTypes.put(def.getIdent().getName(), returnTypeOf(def.getFuncType()));
    }
}
```

调用表达式需要知道返回类型才能决定“要不要开一个临时变量接 `$v0`”。如果只看当前函数，`f()` 调 `g()` 而 `g` 定义在后面，就查不到类型了。运行时库（`get_int` 等）在 `functionReturnType` 里兜底，因为它们的符号早就没了。

函数名本身也要先登记再翻译函数体：

```java
String name = funcDef.getIdent().getName();
IrFunction fn = module.addFunction(name, returnType, false);
declare(name, IrValue.func(name)); // 全局作用域
```

顺序反了，递归调用自己就查不到自己。

## IrExpr：从下往上，一层一值

表达式部分的结构和语法树的层级完全同构，每个 `visitXxx` 返回“存放这个表达式值的操作数”。以 `a + b * 2` 为例：

```text
(assign, a, -, t0)     ← 物化左操作数
(assign, b, -, t1)
(mul, t1, 2, t2)       ← b * 2
(add, t0, t2, t3)      ← 合并
```

`AddExp` / `MulExp` 是左递归，翻译时天然递归：

```java
public static IrValue visitAddExp(IrBuilder ctx, AddExp addExp) {
    if (addExp.isUnary()) {
        return visitMulExp(ctx, addExp.getRight());
    }
    IrValue left = materialize(ctx, visitAddExp(ctx, addExp.getLeft()));
    IrValue right = visitMulExp(ctx, addExp.getRight());
    ValueType type = resultType(left, right);
    IrOp op = operatorOf(addExp.getOperator(), "+");
    return emitBinary(ctx, op, left, right, type, addExp.getLineNum());
}
```

注意单目形态的判断：语法树里 `AddExp` 只有一个子节点时，直接透传下层，**不额外生成一条 `assign`**。否则 `int a = 1;` 都会产生一串无意义的搬运。

`LVal` 出现在“取值”位置时有四种情况，分清这四种是数组部分的关键：

| 目标 | 生成 | 说明 |
| --- | --- | --- |
| 标量常量 | 直接返回 `CONST` | 不生成任何指令 |
| 标量变量 | 直接返回 `VAR` | 由使用处 `load`，少一条 `assign` |
| 数组带下标 | `load` | 结果类型是元素类型 |
| 数组不带下标 | `addr` | 首地址，用于传参和 `%s` |

函数调用把实参**从左到右逐个求值并立刻物化**：

```java
for (int i = 0, n = exps.size(); i < n; i++) {
    IrValue value = materialize(ctx, visitExp(ctx, exps.get(i)));
    ...
    args.add(value);
}
```

这行代码防的是 `f(x, g())` 里 `g()` 改了 `x`。题目对多实参的副作用顺序没提要求，但既然写了顺序，就别让它变成“看运气”。

## IrDecl：四种存储域

声明部分的复杂度全在“这个东西该住在哪”和“初值怎么摊开”：

| 声明 | 存储 | 初始化时机 |
| --- | --- | --- |
| 标量常量 | 无 | 编译期求值，变成立即数 |
| 常量数组 | `.data` | 编译期求值，写进数据段 |
| 全局变量 | `.data` | 进程启动，无初值为 0 |
| `static` 局部变量 | `.data` | 只初始化一次 |
| 普通局部变量 | 栈帧 | 运行到这里时赋值，无初值不清零 |
| 局部数组（有初值） | 栈帧 | 运行到这里时逐元素 `store` |

局部数组的初始化是一段循环：

```java
if (init.isBraced()) {
    List<Exp> exps = init.getExps();
    for (int i = 0; i < count; i++) {
        IrValue value = i < exps.size() ? IrExpr.visitExp(ctx, exps.get(i))
                : zeroOf(baseType);
        ...
        storeElement(ctx, variable, i, value, line);
    }
}
```

`int a[5] = {1};` 会生成 5 条 `store`：一条 1，四条 0。**没写到的元素必须补 0**，这一条对局部数组同样成立（C 的规则是“初始化列表未覆盖的部分视为 0”，跟“没写初始化列表”是两件事）。

`char[]` 用字符串初始化，三条长度规则容易记混：

| 关系 | 行为 |
| --- | --- |
| 字符串长度 L < 数组长度 N | 复制 L 字节，其余补 0 |
| L == N | 复制 N 字节，**不额外补 `'\0'`** |
| L > N | 只复制前 N 字节，**不补 `'\0'`** |

后面两种情况“不补结束符”看着像笔误，实际是 SysY 的规定。补了就会多写一个字节，越界改到相邻变量。

静态数据那边还有个省体积的技巧：全 0 的初值用空列表表示。

```java
/** 全 0 用空列表表示，减少数据段体积。 */
private static List<Integer> compact(List<Integer> values) {
```

后端看到空列表就输出 `.space`，而不是 `.word 0, 0, 0, 0...`。

## IrStmt：五类语句

`visitStmt` 是一个 `switch`，`ASSIGN` / `EXP` / `BLOCK` / `IF` / `WHILE` / `SWITCH` / `BREAK` / `CONTINUE` / `RETURN` / `PRINTF` 各一段。其中 `visitBlockItems` 故意不带作用域：


语义阶段函数体 Block 和形参是一层，代码生成必须对齐，否则形参查不到。

赋值语句的下标要物化，右值不用：

```java

...
```

`a[i] = i + 1` 里右值会改 `i`，地址已经算好，用物化过的旧下标才正确。

## MipsGenerator：序言、正文、尾声

函数输出分三段，序言部分是这样的：

```java
out.append(function.getName()).append(":\n");
out.append("    addiu $sp, $sp, -").append(frameSize).append('\n');
out.append("    sw $fp, ").append(frameSize - 8).append("($sp)\n");
out.append("    sw $ra, ").append(frameSize - 4).append("($sp)\n");
out.append("    move $fp, $sp\n");
```

接着把调用方压在栈上的实参搬进形参槽：

```java
int incoming = frameSize + 4 * i;
out.append("    lw $t0, ").append(incoming).append("($fp)\n");
out.append("    sw $t0, ").append(offset).append("($fp)\n");
```

**数组形参搬过来的是指针**（值本身就是地址），所以这里不区分标量和数组，都是“搬一个 4 字节”。

尾声里 `ret` 先把返回值放进 `$v0`，再跳到函数末尾的统一出口，由出口负责恢复现场并返回：

```java
case RET:
    if (quad.getArg1() != null) {
        emitLoad(quad.getArg1(), "$v0", function, out);
    }
    out.append("    j ").append(endLabel(function)).append('\n');
    break;
```

```java
out.append(endLabel).append(":\n");
if (function.isMain()) {
    out.append("    li $v0, ").append(SYS_EXIT).append('\n');
    out.append("    syscall\n");
} else {
    out.append("    move $sp, $fp\n");
    out.append("    lw $ra, ").append(frameSize - 4).append("($sp)\n");
    out.append("    lw $fp, ").append(frameSize - 8).append("($sp)\n");
    out.append("    addiu $sp, $sp, ").append(frameSize).append('\n');
    out.append("    jr $ra\n");
}
```

这样函数里有几个 `return` 都只有一个出口，保存/恢复现场只需写一遍。`main` 的出口是 `syscall 10`，因为 MARS 跑完 `main` 就该结束。

栈帧分配按声明顺序往上堆：

```java
boolean paramArray = isArrayParam(local);
int size;
if (paramArray) {
    size = 4; // 数组形参只存首地址
} else if (local.getType() != null && local.getType().isArray()) {
    int count = Math.max(local.getArraySize(), 0);
    size = count * (local.elementType() == ValueType.CHAR ? 1 : 4);
} else {
    size = 4;
}
offsets.put(local, offset);
offset = align4(offset + Math.max(size, 0));
```

每个变量之后都重新 4 字节对齐，所以 `char` 数组后面紧跟的 `int` 不会错位。临时变量则是把全部四元式扫一遍收集的：

```java
for (Quad quad : function.getQuads()) {
    offset = allocateTemp(quad.getTarget(), offset);
    offset = allocateTemp(quad.getArg1(), offset);
    offset = allocateTemp(quad.getArg2(), offset);
```

这个做法很笨——**每个临时变量一个槽，从不复用**——但保证“临时值在任何时候重读都拿得到”。栈帧大一点无所谓，正确性优先。

取地址的三分支是数组部分唯一的难点：

```java
case VAR:
    if (value.getStorageLabel() != null) {
        out.append("    la ").append(register).append(", ")
                .append(value.getStorageLabel()).append('\n');
    } else {
        Integer offset = offsets.get(value);
        int off = offset == null ? 0 : offset;
        if (isArrayParam(value)) {
            out.append("    lw ").append(register).append(", ")
                    .append(off).append("($fp)\n");
        } else {
            out.append("    addiu ").append(register).append(", $fp, ")
                    .append(off).append('\n');
        }
    }
    break;
```

全局/静态 `la`，局部数组 `addiu $fp + 偏移`，数组形参**要再解一次引用**（槽里存的是指针，不是数组本体）。第三分支漏了，`sum(a, 3)` 会读到栈上的垃圾。

调用和运行时库是这个分工：

```java

    emitRuntimeCall(name, args, out);
    ...
}
if (argCount > 0) {
    out.append("    addiu $sp, $sp, -").append(4 * argCount).append('\n');
}
for (int i = 0; i < argCount; i++) {
    emitLoad(args.get(i), "$t0", function, out);
    out.append("    sw $t0, ").append(4 * i).append("($sp)\n");
}
out.append("    jal ").append(name).append('\n');
if (argCount > 0) {
    out.append("    addiu $sp, $sp, ").append(4 * argCount).append('\n');
}
```

syscall 编号：`get_int`=5、`get_char`=12、`get_string`=`v0=8`（`a0` 缓冲区、`a1` 长度）、`put_int`=1、`put_char`=11、`put_string`=4。这几个数写反了就是“输出乱码但程序不崩”，特别难查。

```text
    addiu $sp, $sp, -52
    ...
    lw $t0, 52($fp)         ← arr 形参：拿到的是指针
    sw $t0, 0($fp)
    lw $t0, 56($fp)         ← n
    sw $t0, 4($fp)
    ...
.Lsum_1:
    lw $t0, 0($fp)          ← 解引用，取数组首地址
    lw $t1, 8($fp)
    sll $t1, $t1, 2
    addu $t0, $t0, $t1
    lw $t2, 0($t0)
```

`lw $t0, 0($fp)` 和 `addiu $t0, $fp, 0` 只差一个字符，语义差一次间接寻址，这就是最容易看漏的地方。

# 自测方法

评测是黑盒的，但这一阶段比语法分析好自测，因为**输出可以对着跑**。

## 三层验证

1. **先看 `ir.txt`。** 它比汇编好读得多：翻译规则对不对，看四元式就能判断八成。`char` 加法后面有没有 `cast`、循环有没有回到条件标签、`printf` 的实参是不是在调用前就落好了——全是肉眼可见的。
2. **再看 `mips.txt` 能不能跑。** 课程版 MARS 打开、汇编、运行，比对预期输出。MARS 的好处是出错会给行号，比对着机器码猜强太多。
3. **最后拿 C 对照。** 同一个 SysY 程序手改成 C（几乎不用改），`gcc` 跑一遍拿到标准答案，比自己算期望值可靠。`char` 回绕这类算术用 C 的 `unsigned char` 语义完全对得上。

## 逐条回归的边界清单

这份清单是我实际用过的，按“最容易漏”排序：

- [ ] `char` 回绕：`255+1`、`0-1`、`char` 的一元负号
- [ ] `char` 数组的下标：元素 1 字节，`sll` 不能加
- [ ] 局部数组有初值但元素没写满：后面必须补 0
- [ ] `char[] = "..."` 三种长度：L<N、L==N、L>N
- [ ] 数组形参跨函数透传（`f(a)` 里再 `g(a)`）
- [ ] 全局数组只有部分初值
- [ ] `static` 跨调用保留（连续两次调用结果不同）
- [ ] 两个同名局部变量分处不同块（栈槽不能撞）
- [ ] `printf` 实参里有函数调用，且函数改了前面的实参
- [ ] `switch` 落穿、`switch` 里的 `continue`、`switch` 的 `default` 在中间
- [ ] 短路：`f() || g()` 里 `g` 不该被调用
- [ ] 递归（斐波那契、阶乘）
- [ ] 多实参、嵌套调用（`f(g(1), h(2))`）
- [ ] `get_char` / `get_string` / `get_int` 混合输入
- [ ] 空语句、空循环体、空 `if` 分支
- [ ] `void` 函数、`void` 函数里的 `return;`

最后一类（空语句、空循环体）不要觉得“评测不会考”：它们会暴露“标签配好了但中间没有指令”这种结构问题，先在自己造的例子上过一遍，比在评测机上撞运气便宜。

## 我这一版的实测结果

- A/B/C 三套公共测试库共 60 组：59 组通过；
- 未通过的 B-5 是 MARS 4.5 命令行下 `get_char` 之后继续 `get_string` 触发 `SystemIO.readString` 的 `input is null`——这是模拟器 stdin 的限制，把这段输入序列去掉后生成的代码输出正确；
- 全量 `javac --release 17` 编译通过；
- `mips.txt` 用课程版 MARS 打开可直接运行。

这套结论说明“代码没错”和“评测全过”之间还隔着模拟器的坑。遇到后者，先确认是不是模拟器行为，别急着改代码生成。

# 踩坑记录

按被坑的先后顺序记，每条都对应一处具体实现。

1. **栈槽表用变量名做 key。** 两个块里的同名 `a` 共用一个槽，前一个块的值被后一个块覆盖。改成 `IdentityHashMap`、用 `IrValue` 对象做 key 才对。这个 bug 的特点是“大部分程序都对”，只有遮蔽的情形错。

2. **`printf` 只记住变量名，没物化。** `printf("%d %d\n", x, f())` 里 `f()` 改了 `x`，输出时读到的是新值。改成“先全部求值、再逐段输出”后消失。教训是：**输出语句要拆成两步——先求值，再输出**。

3. **数组形参直接 `addiu $fp, 偏移`。** 槽里存的是指针，我把它当地址用，读到的是栈上的垃圾。`isArrayParam` 那个分支就是为它加的。

4. **`store` 的字段记反。** 写成 `(store, 数组, 值, 下标)`，结果数组元素全被写成常量下标，看起来像“数组没初始化”。

5. **局部数组没初值时清零了。** 反过来更常见：有初值但漏了补 0。C 的规则是“初始化列表未覆盖部分为 0”，“没有初始化列表”才是不定值。两者必须分开处理。

6. **`char` 忘了 `cast`。** `255+1` 得到 256，打印成 `%c` 就乱。这条不可能只漏一处——每处算术都要想着，所以我把 `cast` 塞进了 `emitBinary`，只写一遍。

7. **`le` / `ge` 用 `slt` 写错方向。** `a <= b` 写成 `slt $t2,$t0,$t1`（`a < b`），差一等号。正确是反向 `slt` 再 `xori`。

8. **`switch` 里 `break` 跳错层。** 我把 `break` / `continue` 合成了一个栈，于是 `switch` 里的 `continue` 跳到了 `switch` 结束而不是外层循环继续。分成两个栈后消失。

9. **`static` 变量放进了栈帧。** 每次进函数都重新初始化，`static` 的意义全没了。凡是 `static` 一律进 `.data`，和全局变量同一套逻辑。

10. **`main` 不是第一条指令。** 评测器按默认入口取第一条指令，若前面先输出了用户函数，`main` 就找不到。`emitText` 里先输出 `main`、再输出其余函数，并给它加 `.globl main`。

11. **字符串转了两次或一次都没转。** `decode` 之后再 `decode`，`\n` 变两次；只 `decode` 不 `escape`，`.asciiz` 里的引号和反斜杠会把汇编器搞崩。正确顺序是 `decode` → `escapeForAsciiz`。

12. **调用后忘记回收 `sp`。** `addiu sp, sp, -4n` 之后没加回来，每调用一次栈就往下掉一截，递归几层就爆。

前十一条都是“错得出来”，第十二条是“错得看不出来”——程序跑完不报错，只是栈越跑越深。这类问题只能靠盯代码结构，写的时候把压栈/回收配成一对来写。

# 留给代码生成二

优化部分这版只留了骨架：

```java
public interface IrPass {
    String name();
    void run(IrModule module);
}
```

```java
private static final List<IrPass> PASSES = new ArrayList<>();
public static IrModule optimize(IrModule module) {
    for (IrPass pass : PASSES) {
        pass.run(module);
    }
    return module;
}
```

`Compiler` 里用 `OPTIMIZE` 一个开关统一控制，现在的 `PASSES` 是空的，打开也不会改变输出。

要接的话，按收益从易到难排：常量折叠 → 复写传播 + 死代码删除 → 局部公共子表达式 → 强度削弱（乘除常数改成移位）→ 控制流简化（常量条件跳转、不可达标签）→ 窥孔（相邻冗余 `load` / `store`）。

有两条红线，优化再激进也不能碰：

- **不能改变可观察行为**：I/O 顺序、短路带来的副作用、`printf` 先求值后输出、`static` 状态；
- **不要跨越 `call` 随意搬动读写**。`call` 可能改任何全局变量和 `static` 变量，把一次读提到 `call` 之前就是错的。

顺便说一下我这一版最明显的两处冗余，都是留给优化的：临时变量从不多复用（栈帧偏大），以及 `char` 的 `andi` 有时连着两条。前者靠寄存器分配或栈槽复用解决，后者一条窥孔就够。

代码生成的整个流程其实没有“聪明”的地方：四元式一条一条翻，栈帧一次一次算，指令一条一条选。能过评测靠的是**把每个边界情况都想到**——`char` 的 256、数组的 1 字节、`static` 的一生只初始化一次、`printf` 的先算后印。这些坑踩遍之后，剩下的就是把 `ir.txt` 和 `mips.txt` 摊开对照，一条一条确认。
