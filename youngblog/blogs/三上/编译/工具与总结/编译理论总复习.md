# 编译理论总复习

这门课的考点分布很稳定：概念填空与判断、正则与自动机、FIRST/FOLLOW 与 LL(1)、算符优先、LR、符号表与运行栈、数组地址、基本块与数据流。按教材章节逐条背，容易把“短语”和“素短语”、“SLR”和“LALR”搅在一起；按编译流程串一遍，每块知识都能找到它解决的问题。

本文按“概论与文法 → 词法 → 语法 → 语义与中间代码 → 运行时存储 → 优化”组织。每章先讲知识点，概念类真题紧跟对应知识点；有固定解法的话题型用 h3 单列，同一题型的真题统一落在该 h3 下、排在自编例题之后。知识点里的解释放在引用块中；真题用站点的习题块，年份写在题干里。高度相似的题合并，只保留较晚的一道，年份标注同时列出被合并的年份。

# 一、编译过程与形式语言

## 编译过程的五个阶段

### 五个阶段的职责

| 阶段 | 输入 | 输出 | 主要理论 |
| --- | --- | --- | --- |
| 词法分析 | 字符流 | token 序列 | 正则文法、有穷自动机 |
| 语法分析 | token 序列 | 语法树 / 抽象语法树 | 上下文无关文法、下推自动机 |
| 语义分析 | 语法树、符号表 | 带语义信息的中间表示 | 属性文法、类型系统 |
| 中间代码生成与优化 | 中间表示 | 优化后的中间表示 | 数据流分析、图论 |
| 目标代码生成 | 中间表示 | 汇编或机器码 | 指令选择、寄存器分配 |

> 这五个阶段像流水线：前一段的输出就是后一段的输入。词法只管“切词”，语法只管“句子结构”，语义才判断“变量有没有声明、类型对不对”。所以标识符拼错但形式合法时，词法阶段发现不了；括号不匹配则通常在语法阶段报错。

符号表管理和出错处理贯穿全部阶段，所以典型的编译程序常被划分为七个逻辑部分组成。

### 前端、后端与“遍”

- 前端：词法、语法、语义分析、中间代码生成，依赖源语言。
- 后端：优化、目标代码生成，依赖目标机器。
- 一遍：从头到尾扫描源程序一次并完成相应加工。完成编译最少需要两遍：第一遍处理声明、建立符号表，第二遍才能生成引用这些名字的代码。

> “遍”按扫描次数算，不按阶段数算。把词法、语法、语义压缩在一次扫描里完成，仍然叫一遍编译。

## 错误的分类与局部化

### 错误类型与发现阶段

| 错误类型 | 典型例子 | 常见发现阶段 |
| --- | --- | --- |
| 词法错误 | 非法字符、注释/字符串未闭合 | 词法分析 |

### 错误局部化与恢复

错误局部化：发现错误后，把影响限制在局部，跳过一段输入恢复到可继续分析的状态。常用恢复方式有panic mode（丢弃符号直到同步符）、短语级恢复（补一个分号）、错误产生式。

## 符号表

### 符号表项

符号表登记名字及其属性，常见字段：

| 名字 | 种类 | 类型 | 维数 | 地址/值 | 层号 |
| --- | --- | --- | --- | --- | --- |
| x | var | int | 0 | 104 | 1 |
| a | var | double | 2 | 模板地址 | 1 |
| f | func | int | — | 入口地址 | 0 |

栈式符号表用“分程序索引表”记录每层第一个登记项。进入分程序压入一个索引，退出时弹掉该层全部登记项。

> 符号表像图书馆的目录：名字是书名，种类是图书类别，类型是内容分类，地址是书架位置，层号是分馆。查找时从最内层往外找，内层同名声明会遮蔽外层。

## 文法、推导与语言

### 文法与推导

文法 $G=(V_N,V_T,P,S)$：

- $V_N$：非终结符集合。
- $V_T$：终结符集合。
- $P$：产生式集合，形式为 $\alpha\to\beta$。
- $S$：开始符号，$S\in V_N$。

推导：把产生式左部替换为右部，记 $\Rightarrow$；多步为 $\Rightarrow^*$。最左推导每次替换最左非终结符，最右推导每次替换最右非终结符。

### 句型、句子与语言

- 句型：从 $S$ 出发能推导出的符号串，允许含非终结符。
- 句子：只含终结符的句型。
- 语言：$L(G)=\{x\mid S\Rightarrow^*x,\ x\in V_T^*\}$。

> 句子一定是句型，句型不一定是句子。文法的语言是 $V_T^*$ 的子集，通常不是全部 $V_T^*$；一个语言可以由多个文法产生，语言和文法的关系是多对一。

规范推导就是最右推导；规范归约是最左归约，正好是规范推导的逆过程。

## 语法树、二义性

语法树的叶子从左到右读，就是推导出的句型。二义性：存在某个句子有两棵不同的语法树，等价于存在两个不同的最左推导（或两个不同的最右推导）。

> 二义性是“文法”的性质，不是“语言”的性质。同一个语言可以有一个二义文法，也可以有一个无二义文法。考试说“该文法有二义性”，指的是存在句子能画出两棵树。

### 题型：证明二义性

**解法**

1. 选一个短句子，最好含两个优先级不同的运算符。
2. 给出两棵语法树，或两个不同的最左推导。
3. 结论：该句子有两棵树，所以文法二义。

**自编例题** 文法 $E\to E+E\mid E*E\mid i$，证明 `i+i*i` 二义。

按 `+` 先结合：$E\Rightarrow E+E\Rightarrow i+E\Rightarrow i+E*E\Rightarrow i+i*i$，即 `i+(i*i)`。

按 `*` 先结合：$E\Rightarrow E*E\Rightarrow E+E*E\Rightarrow i+i*i$，即 `(i+i)*i`。

两棵语法树不同，句子相同，文法二义。

> 这个文法二义，但运算符优先级可以人为规定，所以实际编译器仍能用它（配合优先级声明）。二义文法不等于不能用，只是不能直接做 LL(1)。

## 短语、简单短语、句柄与素短语

### 短语与简单短语

设句型 $w$ 的一棵语法树中，某个非终结符结点（至少展开过一次）的子树叶子串为 $u$，则 $u$ 是 $w$ 的一个短语。

简单短语：高度为 1 的子树对应的叶子串，也就是产生式右部全是叶子的子树。

### 句柄与素短语

| 概念 | 判定方法 | 用途 |
| --- | --- | --- |
| 短语 | 任意一棵子树的叶子串 | 归约的基本单位 |
| 简单短语 | 高度为 1 的子树（产生式右部全是叶子） | 直接可归约 |
| 句柄 | 最左的简单短语 | 规范归约每次归约的对象 |
| 素短语 | 至少含一个终结符，且不含更小的素短语（单个终结符视为原子，不算“更小的素短语”） | 算符优先每次归约的对象 |
| 最左素短语 | 最左边的素短语 | 算符优先的归约对象 |

> 把语法树想成一棵实际的树，摘下一棵子树，叶子从左到右排就是短语。高度只有一层的子树是简单短语。素短语的要求更严：自己得带终结符，内部不能再藏一个更大的素短语（单个终结符是原子，不挡住外层）。句柄一定是最左简单短语，但不一定是素短语；素短语也不一定是简单短语。

### 题型：推导、语法树与短语类

**解法**

1. 从开始符号画语法树，按产生式一步步展开到目标句型。
2. 把每个“展开过的非终结符结点”圈出来，读出它下面的叶子串，得到全部短语。
3. 只含一层的子树给简单短语；最左的简单短语是句柄。
4. 在短语里筛“至少含一个终结符、内部不含更小素短语”的，得到素短语；最左的一个是最左素短语。

**自编例题** 文法：

```text
E ::= E + T | T
T ::= T * F | F
F ::= ( E ) | i
```

句型 `i + i * i`，求短语、简单短语、句柄、素短语。

语法树：

```text
        E
┌───┴───┼───┐
E   +       T
│       ┌───┼───┐
T       T   *   F
│       │       │
F       F       i
│       │
i       i
```

更准确地说，顶层是 $E\to E+T$，左 $E\to T\to F\to i$，右 $T\to T*F$，三个 $F$ 都推出 $i$。

- 短语：`i`、`i*i`、`i+i*i`。

- 句柄：`i`。
- 素短语：`i`、`i*i`；最左素短语是 `i`。

> `i+i*i` 不是素短语，因为里面已经含有 `i` 和 `i*i` 两个更小的素短语。素短语的判断从最小的短语往上做，先看单终结符，再看含运算符的小串。

## 乔姆斯基分类

| 类型 | 名称 | 产生式限制 | 识别器 |
| --- | --- | --- | --- |
| 0 型 | 短语结构文法 | $\alpha\to\beta$，$\alpha$ 至少含一个非终结符 | 图灵机 |
| 1 型 | 上下文有关文法 | $\alpha A\beta\to\alpha\gamma\beta$，$\gamma\neq\varepsilon$ | 线性界限自动机 |
| 2 型 | 上下文无关文法 | $A\to\beta$，$A$ 为单个非终结符 | 下推自动机 |
| 3 型 | 正则文法 | $A\to aB$ 或 $A\to a$（右线性） | 有穷自动机 |

## 消除左递归与 EBNF

直接左递归：

$$
A\to A\alpha_1\mid A\alpha_2\mid\beta
$$

改写为：

$$
A\to\beta A'\\
A'\to\alpha_1 A'\mid\alpha_2 A'\mid\varepsilon
$$

用 EBNF 写就是 $A\to\beta\{\alpha_1\mid\alpha_2\}$。

> 左递归会让自顶向下分析陷入“用 A 匹配 A”的死循环。消除的办法是把左递归改成右递归，让每展开一次至少消耗一个终结符。间接左递归要先代入，把间接变成直接，再按上式处理。

EBNF 常用记号：

| 记号 | 含义 |
| --- | --- |
| `{ X }` | X 重复零次或多次 |
| `[ X ]` | X 出现零次或一次 |
| `( X )` | 分组 |
| `X \| Y` | 选择 |

### 题型：消除左递归与 EBNF 表示

**解法**

1. 把产生式整理成 $A\to A\alpha_1\mid\cdots\mid A\alpha_n\mid\beta_1\mid\cdots\mid\beta_m$。
2. 改写为 $A\to\beta_1A'\mid\cdots\mid\beta_mA'$，$A'\to\alpha_1A'\mid\cdots\mid\alpha_nA'\mid\varepsilon$。
3. 若要求 EBNF，把递归尾写成 `{...}`。

**自编例题** $A\to Aa\mid Ab\mid c$。

改写：$A\to cA'$，$A'\to aA'\mid bA'\mid\varepsilon$。

EBNF：$A\to c\{a\mid b\}$。

> 改写后语言不变，但推导方向从“先长左边”变成“先长右边”。检查时用几个短串验证，比如 `c`、`ca`、`cab`，都能由新文法推出。

## 词法分析的任务

词法分析的任务是把字符流切成 token 序列，顺带过滤空白与注释。

### token 的组成

输入字符流，输出 token 序列。每个 token 通常写成 `(种别码, 属性值)`：

- 关键字、运算符、界符：种别码即可区分，属性值可空。
- 标识符：种别码为“标识符”，属性值是它在符号表中的入口或名字。
- 常量：种别码为“整型/浮点/字符”，属性值是具体值。

### 最长匹配与关键字

词法分析还要跳过空白、换行和注释，处理最长匹配，并在读入标识符时查关键字表。

> 词法分析只认“词形”，不认“词义”。`int` 拼成 `intt` 仍然是合法标识符，词法阶段不会报错；等到语义分析查符号表，才发现没有这个变量。

## 正则表达式与正则文法

### 正则表达式的运算

正则表达式：

| 运算 | 写法 | 含义 |
| --- | --- | --- |
| 连接 | `ab` | a 后接 b |
| 选择 | `a\|b` | a 或 b |
| 闭包 | `a*` | a 重复零次或多次 |
| 正闭包 | `a+` | a 重复一次或多次 |
| 可选 | `a?` | a 出现零次或一次 |
| 分组 | `(ab)*` | ab 作为一个整体重复 |

优先级：`*`、`+`、`?` 最高，连接次之，`|` 最低。

常用恒等式：

- $(r^*)^*=r^*$，$(r^*)^+=r^*r$。
- $(r|s)^*=(r^*s^*)^*$。
- `(ab)*a = a(ba)*`。
- `a|a = a`，`εa = aε = a`。

## NFA 与 DFA

### NFA 与 DFA 的区别

| 项 | NFA | DFA |
| --- | --- | --- |
| 转移 | $\delta:Q\times(\Sigma\cup\{\varepsilon\})\to 2^Q$ | $\delta:Q\times\Sigma\to Q$ |
| ε 转移 | 允许 | 不允许 |
| 同一状态同一字符 | 可有多条 | 最多一条 |
| 接受状态 | 可多个 | 可多个 |
| 开始状态 | 通常一个 | 一个 |

> NFA 的“不确定”来自两处：同一字符可走多条边，以及可以不读字符走 ε 边。确定化就是把这两种不确定性都消掉：用状态集合表示“同时可能在的所有状态”。

### ε-closure 与 move

- $\varepsilon\text{-closure}(S)$：从集合 $S$ 出发只走 ε 边能到达的所有状态（含 $S$ 本身）。
- $\text{move}(S,a)$：从 $S$ 中每个状态读字符 $a$ 后到达的状态集合。

子集构造：

$$
\delta_{DFA}(S,a)=\varepsilon\text{-closure}(\text{move}(S,a))
$$

### DFA 最小化

1. 删除不可达状态。
2. 初分：终态一组，非终态一组。
3. 对每组按“读每个字符后落到哪组”划分；同组内落点组相同的继续同组。
4. 重复到不再分裂，每组选一个代表，合并转移。

> 最小化的本质是找“行为完全一样”的状态：从这两个状态出发，读任何字符串，接受/拒绝的结果都相同。初始只分终态和非终态，随后用转移落点不断细分。

## 正则表达式、NFA、DFA、右线性文法的互化

| 从 | 到 | 方法 |
| --- | --- | --- |
| 正则表达式 | NFA | Thompson 构造：连接、选择、闭包分别搭积木 |
| NFA | DFA | 子集构造 |
| DFA | 最小 DFA | 划分 refinement |
| DFA | 右线性文法 | 每个状态设一个非终结符，转移 $q\xrightarrow{a}p$ 写成 $A_q\to aA_p$，终态加 $A_q\to\varepsilon$ |
| 右线性文法 | NFA | $A\to aB$ 画 $A\xrightarrow{a}B$，$A\to a$ 画到终态 |

> Thompson 构造里，每个正则运算符都对应一小块固定的 NFA 片段，首尾用 ε 边拼接。子集构造则把“同时可能的状态”打包成一个 DFA 状态。两种方法都不需要灵光一现，照着表格填即可。

### 题型：正则表达式转右线性文法

**解法**

1. 先按正则表达式画出 NFA（或直接设状态）。
2. 给每个状态起一个非终结符名，开始状态就是开始符号。
3. 每条转移 $q\xrightarrow{a}p$ 写成 $A_q\to aA_p$。
4. 每个终态 $q$ 加 $A_q\to\varepsilon$。
5. 若有多个终态，允许同一非终结符有多条 ε 产生式。

**自编例题** 正则表达式 `a(b|c)*d`。

NFA 状态：0 开始，读 a 到 1；1 上 b/c 自环；1 读 d 到 2（终态）。

右线性文法：

```text
S → aA
A → bA | cA | d
```

其中 S 对应状态 0，A 对应状态 1。读到 d 后到终态，直接写 $A\to d$。

> 右线性文法里，非终结符一定在最右边。写成 `A → Ab` 就变成左线性，方向反了，不能直接套这个模板。

### 题型：NFA 确定化

**解法**

1. 从开始状态的 ε-closure 出发，记为 $I_0$。
2. 对每个未处理集合 $I$ 和每个输入字符 $a$，算 $\varepsilon\text{-closure}(\text{move}(I,a))$。
3. 得到的新集合若没出现过，编号入队。
4. 含原 NFA 终态的集合标为 DFA 终态。
5. 填转移表，画状态图。

**自编例题** NFA：

| 状态 | a | b | ε |
| --- | --- | --- | --- |
| 0 | 0 | 1 | — |
| 1 | — | 2 | — |
| 2 | 2 | — | — |

终态 2。

从 $I_0=\{0\}$ 开始：

- $I_0$ 读 a 到 $\{0\}$，还是 $I_0$。
- $I_0$ 读 b 到 $\{1\}$，记 $I_1$。
- $I_1$ 读 b 到 $\{2\}$，记 $I_2$（终态）。
- $I_2$ 读 a 到 $\{2\}$，还是 $I_2$。

DFA：

| 状态 | a | b | 终态 |
| --- | --- | --- | --- |
| $I_0$ | $I_0$ | $I_1$ | 否 |
| $I_1$ | — | $I_2$ | 否 |
| $I_2$ | $I_2$ | — | 是 |

> 确定化时最容易漏掉 ε-closure：算出 move 后必须再把 ε 边走一遍。终态判断看“集合里有没有原终态”，不是看集合编号。

### 题型：DFA 最小化

**解法**

1. 去掉不可达状态。
2. 按终态/非终态分成两组。
3. 对每组逐个字符看落点组；落点组不同的拆开。
4. 重复到稳定，合并同组状态。

**自编例题** DFA：

| 状态 | 0 | 1 | 终态 |
| --- | --- | --- | --- |
| A | B | C | 否 |
| B | B | D | 否 |
| C | B | C | 否 |
| D | B | C | 是 |

初分：{A,B,C} 非终态，{D} 终态。

看非终态组：

- A：0→B（非终），1→C（非终）。
- B：0→B（非终），1→D（终）。
- C：0→B（非终），1→C（非终）。

A 与 C 的落点组相同，B 不同。拆成 {A,C} 和 {B}。

再看 {A,C}：A 的 0→B，1→C；C 的 0→B，1→C，落点组相同，保持。

最小 DFA 状态：{A,C}、{B}、{D}。A 与 C 合并。

> 最小化不是“看起来像就合并”，必须按转移落点组判断。两个状态即使自身终态属性相同，只要读某个字符后落到不同组，就必须拆开。

### 题型：DFA 写正则表达式

**解法**

1. 解状态方程组：每个状态 $q_i$ 对应一个语言 $L_i$，$L_i=\sum_{a} a L_{\delta(q_i,a)}$，终态加 ε。
2. 用 Arden 引理 $X=AX+B\Rightarrow X=A^*B$ 消元。
3. 从开始状态解出正则表达式。

**自编例题** 接受“偶数个 a”的 DFA：状态 0（偶，终态）、1（奇），0 读 a 到 1，读 b 留在 0；1 读 a 到 0，读 b 留在 1。

方程：

```text
L0 = b L0 | a L1 | ε
L1 = b L1 | a L0
```

由第二式 $L1=b^*aL0$，代入第一式：

```text
L0 = (b | a b* a) L0 | ε
L0 = (b | a b* a)*
```

所以正则表达式为 `(b|ab*a)*`。

> 状态方程法适合状态少、结构对称的 DFA。状态多时，直接观察“从开始到终态要经过哪些字符块”更快，但方程法不会漏。

# 三、语法分析

语法分析要回答两件事：给定的 token 串是不是文法的句子；如果是，按哪棵语法树理解。自顶向下从开始符号往下推，自底向上从输入串往开始符号归约。

## 自顶向下分析

### 基本过程

从开始符号出发，反复用产生式右部替换非终结符，试图匹配输入串。匹配失败时可能需要回溯，效率低。递归下降给每个非终结符写一个子程序，按当前 lookahead 选择产生式。

> 自顶向下像“先猜句子结构，再往下填词”。猜错就要退回重猜，所以左递归和回溯是两个天然障碍。LL(1) 的作用就是保证每一步只看一个 lookahead 就能唯一猜对，不需要回溯。

### FIRST 与 FOLLOW

$FIRST(\alpha)$：$\alpha$ 能推导出的所有可能的开头终结符；若 $\alpha\Rightarrow^*\varepsilon$，还要把 $\varepsilon$ 放进去。

计算规则：

1. 若 $\alpha$ 以终结符 $a$ 开头，$a\in FIRST(\alpha)$。
2. 若 $\alpha$ 以非终结符 $A$ 开头，把 $FIRST(A)\setminus\{\varepsilon\}$ 加入；若 $A$ 可空，继续看下一个符号。
3. 若所有符号都可空，$\varepsilon\in FIRST(\alpha)$。

$FOLLOW(A)$：在所有句型中，紧跟在 $A$ 后面的终结符集合；输入结束符 `#` 属于 $FOLLOW(S)$。

计算规则：

1. `#` ∈ $FOLLOW(S)$。
2. 对产生式 $B\to\alpha A\beta$，把 $FIRST(\beta)\setminus\{\varepsilon\}$ 加入 $FOLLOW(A)$。
3. 若 $\beta\Rightarrow^*\varepsilon$，把 $FOLLOW(B)$ 也加入 $FOLLOW(A)$。

> FIRST 看“开头能是什么”，FOLLOW 看“后面能跟什么”。FOLLOW 只在产生式右部某个非终结符的后面找，不要从产生式左部反推。

### 题型：FIRST/FOLLOW

**解法**

2. 按定义求 FIRST，遇到可空非终结符继续往后看。
3. FOLLOW 从开始符号的 `#` 出发，按产生式右部逐个传播。
4. 用 LL(1) 条件检查候选式。

**自编例题** 文法：

```text
S → A B | a
A → ε | b A
B → c B | ε
```

求各非终结符的 FIRST、FOLLOW，并判断是否 LL(1)。

可空：A、B、S 都可空。

- $FIRST(S)=\{a,b,c,\varepsilon\}$。
- $FIRST(A)=\{b,\varepsilon\}$。
- $FIRST(B)=\{c,\varepsilon\}$。

FOLLOW：

- $FOLLOW(S)=\{\#\}$。
- $S\to AB$：A 后是 B，$FIRST(B)\setminus\{\varepsilon\}=\{c\}$；B 可空，把 $FOLLOW(S)$ 并入 $FOLLOW(A)$，得 $\{c,\#\}$。
- B 在 $S\to AB$ 末尾，$FOLLOW(B)=FOLLOW(S)=\{\#\}$。

LL(1) 检查：

- $S\to AB$ 的 FIRST 为 $\{b,c,\varepsilon\}$，$S\to a$ 为 $\{a\}$；交集为空。AB 可空，$FOLLOW(S)=\{\#\}$ 与 $\{a\}$ 不交。
- $A\to\varepsilon$ 的 FOLLOW 为 $\{c,\#\}$，$A\to bA$ 的 FIRST 为 $\{b\}$，不交。
- $B\to\varepsilon$ 的 FOLLOW 为 $\{\#\}$，$B\to cB$ 的 FIRST 为 $\{c\}$，不交。

所以是 LL(1)。

> 这个文法每个非终结符都能推出空串，FOLLOW 的传播要格外小心：A 的 FOLLOW 不只来自直接跟在 A 后的 B 的 FIRST，还要在 B 可空时并入 S 的 FOLLOW。

这道题的关键是 FOLLOW(F)：F 在 `T→aFP` 中后面跟着 P，所以 FIRST(P) 的 `b` 要进入 FOLLOW(F)；P 可空时，FOLLOW(P) 的 `#`、`a` 也要进入 FOLLOW(F)。因此 FOLLOW(F)={b,#,a}。

> 判断 LL(1) 时，先看同一左部的候选式 FIRST 是否相交，再看“可空候选式”和 FOLLOW 是否相交。两步都过，才是 LL(1)。

### LL(1) 的充要条件

对每个非终结符 $A$ 的任意两个不同候选式 $\alpha_i,\alpha_j$：

1. $FIRST(\alpha_i)\cap FIRST(\alpha_j)=\varnothing$。
2. 若 $\alpha_i\Rightarrow^*\varepsilon$，则 $FIRST(\alpha_j)\cap FOLLOW(A)=\varnothing$。

等价说法：LL(1) 分析表的每个表项至多一条产生式。

> 第 2 条最容易被忘：候选式能推出空串时，选择依据要从 FIRST 换成 FOLLOW。如果 FOLLOW(A) 和另一个候选式的 FIRST 重叠，分析器就不知道是展开另一个候选式，还是用空串结束 A。

### LL(1) 分析表与分析过程

对每个产生式 $A\to\alpha$：

- 对每个 $a\in FIRST(\alpha)$，填 $M[A,a]=A\to\alpha$。
- 若 $\alpha\Rightarrow^*\varepsilon$，对每个 $b\in FOLLOW(A)$，填 $M[A,b]=A\to\alpha$。

分析过程用栈：

1. 栈底放 `#`，压入开始符号。
2. 栈顶 $X$ 与输入 $a$：
   - $X=a=\#$：接受。
   - $X=a\neq\#$：弹出，读下一个。
   - $X$ 是非终结符：查 $M[X,a]$，把产生式右部逆序压栈。
   - 无表项或终结符不匹配：报错。

> 压栈要逆序：产生式右部从左到右展开，栈是后进先出，所以最左符号最后压，压完栈顶正好是最左符号。本文的分析过程表统一写成“栈底在左、栈顶在右”，`#` 永远在最左端，最右边的符号才是当前栈顶。

## 自底向上分析

### 句柄、活前缀与项目

- 句柄：当前句型的最左简单短语，规范归约每次归约它。
- 活前缀：规范句型的一个前缀，且不超过句柄的右端。
- 项目：产生式加上一个圆点，表示“已识别到圆点前的位置”，如 $A\to\alpha\cdot\beta$。

项目集闭包：若 $A\to\alpha\cdot B\beta$ 在集合中，且 $B\to\gamma$ 是产生式，则把 $B\to\cdot\gamma$ 加入。

$goto(I,X)$：把 $I$ 中所有圆点前为 $X$ 的项目，圆点右移一位，再求闭包。

> 项目就是“归约进度条”。圆点在末尾表示可以归约；圆点在中间表示还要继续移进。闭包补的是“接下来可能用哪些产生式”，goto 走的是“吃掉一个符号后进度条推进到哪”。

### LR(0)、SLR(1)、LR(1)、LALR(1)

| 方法 | 项目形式 | 归约条件 | 状态数 | 能力 |
| --- | --- | --- | --- | --- |
| LR(0) | $A\to\alpha\cdot\beta$ | 圆点在末尾就归约，不看 lookahead | 最少 | 最弱 |
| SLR(1) | 同 LR(0) | 圆点在末尾，且 lookahead ∈ FOLLOW(A) | 同 LR(0) | 较强 |
| LR(1) | $[A\to\alpha\cdot\beta,\ a]$ | 圆点在末尾，且 lookahead 精确等于 $a$ | 最多 | 最强 |
| LALR(1) | 合并同心 LR(1) 项目集 | 合并后 lookahead 取并集 | 同 LR(0) 量级 | 介于 SLR 和 LR(1) |

> SLR 用 FOLLOW 集“一刀切”，把同一个非终结符在所有上下文中的后继混在一起。LR(1) 给每个项目单独记 lookahead，精度更高但状态爆炸。LALR 把核心相同的 LR(1) 状态合并，保留 LR(1) 的精度，状态数压到 LR(0) 水平。

- LR(0) 冲突：移进-归约、归约-归约。
- SLR 冲突：用 FOLLOW 缩小归约范围后仍冲突。
- LR(1) 合并同心集：只可能产生归约-归约冲突，不会产生移进-归约冲突（原 LR(1) 无移进-归约冲突，合并后移进动作相同，归约 lookahead 只会增多）。
- 有效项目集：识别某个活前缀后到达的状态中的项目集合。

### 题型：LR(1) 与 LALR 合并同心集

**解法**

1. 按 LR(1) 项目 $[A\to\alpha\cdot\beta,a]$ 求闭包：对 $B\to\gamma$，lookahead 取 $FIRST(\beta a)$。
2. 构造 LR(1) 项目集规范族。
3. 核心（圆点位置和产生式）相同的状态合并，lookahead 取并集。
4. 合并后检查冲突；LALR 表的状态数通常与 LR(0) 相同。
5. 分析过程与 SLR 相同，按 ACTION/GOTO 表驱动。

> 合并同心集只合并“核心相同、lookahead 不同”的状态。合并后可能出现归约-归约冲突，因为两个归约的 lookahead 被并到一起；不会出现移进-归约冲突，因为移进动作只看圆点后的终结符，与原 LR(1) 状态一致。

**自编例题** 文法：

```text
S → a A d | b B d | a B e | b A e
A → c
B → c
```

先看 LR(1)：读完 `a c` 后得到两个项目 `A→c·, d` 和 `B→c·, e`，展望符不同，可以共存；读完 `b c` 后得到 `A→c·, e` 和 `B→c·, d`，也能共存。所以原文法是 LR(1)。

再看合并同心集：`a c` 和 `b c` 后面的两个状态核心相同，都是 `{A→c·, B→c·}`，只是展望符互换。合并后变成 `A→c·, {d,e}` 与 `B→c·, {d,e}`，在 `d`、`e` 上都同时可归约为 A 或 B，出现归约-归约冲突。因此它不是 LALR(1)。

> 判断“LR(1) 但不是 LALR(1)”就看合并后的同一核心状态里，两个不同归约项目的展望符是否相交。相交就冲突；本题正好相交，所以只能停在 LR(1)。

## 算符优先分析

### 算符文法与算符优先文法

算符文法：产生式右部没有两个相邻的非终结符，且没有空产生式。

算符优先文法：算符文法，且任意两个终结符之间至多一种优先关系（`⋖`、`≐`、`⋗` 不冲突）。

> 算符优先不按“句柄”归约，而按“最左素短语”归约。它不要求文法无二义，只要求终结符之间的优先关系唯一。关系表冲突就说明不是算符优先文法。

### FIRSTVT 与 LASTVT

$FIRSTVT(U)$：$U$ 推导出的串中，可能最先出现的终结符；若 $U\to V\ldots$，还要并入 $FIRSTVT(V)$。

$LASTVT(U)$：$U$ 推导出的串中，可能最后出现的终结符；若 $U\to\ldots V$，还要并入 $LASTVT(V)$。

计算口诀：

- $U\to a\ldots$ 或 $U\to V a\ldots$：$a\in FIRSTVT(U)$。
- $U\to\ldots a$ 或 $U\to\ldots aV$：$a\in LASTVT(U)$。
- $U\to V\ldots$：$FIRSTVT(V)\subseteq FIRSTVT(U)$。
- $U\to\ldots V$：$LASTVT(V)\subseteq LASTVT(U)$。

### 优先关系

| 关系 | 产生式形态 | 含义 |
| --- | --- | --- |
| $a\doteq b$ | $U\to\ldots ab\ldots$ 或 $\ldots aVb\ldots$ | 相邻，同时处理 |
| $a\lessdot b$ | $U\to\ldots aV\ldots$，$b\in FIRSTVT(V)$ | a 在 b 前，b 先归约 |
| $a\gtrdot b$ | $U\to\ldots Vb\ldots$，$a\in LASTVT(V)$ | a 先归约 |
| $a\gtrdot b$ | $U\to\ldots VW\ldots$，$a\in LASTVT(V)$，$b\in FIRSTVT(W)$ | 两个非终结符相邻时 |

另外 `# ⋖ FIRSTVT(S)`，`LASTVT(S) ⋗ #`。

> `⋖` 表示右边优先，先移进；`⋗` 表示左边优先，先归约；`≐` 表示两边同时处理，通常用于括号。

### 题型：FIRSTVT/LASTVT 与优先矩阵

**解法**

1. 确认是算符文法：无相邻非终结符、无 ε 产生式。
2. 求 FIRSTVT：看右部第一个符号；若为非终结符，还要并入它的 FIRSTVT。
3. 求 LASTVT：看右部最后一个符号；若为非终结符，并入它的 LASTVT。
4. 按产生式的相邻符号填关系表。
5. 检查每个格子是否唯一。

**自编例题** 文法：

```text
E → E + T | T
T → i
```

FIRSTVT：

- $FIRSTVT(T)=\{i\}$。
- $FIRSTVT(E)$：$E\to E+T$ 给出 `+`（E 后跟 +），$E\to T$ 给出 `i`，所以 $\{+,i\}$。

LASTVT：

- $LASTVT(T)=\{i\}$。
- $LASTVT(E)$：$E\to E+T$ 中 `+` 紧挨在末尾非终结符 T 前，所以 `+` 属于 $LASTVT(E)$；$E\to T$ 给出 $LASTVT(T)=\{i\}$。合计 $\{+,i\}$。

关系：

- $E\to E+T$：$LASTVT(E)\gtrdot +$，即 $i\gtrdot +$、$+\gtrdot +$；$+\lessdot FIRSTVT(T)$，即 $+\lessdot i$。
- 开始符：`# ⋖ FIRSTVT(E)`，`# ⋖ +`、`# ⋖ i`；`LASTVT(E) ⋗ #`，即 `i ⋗ #`、`+ ⋗ #`。

优先矩阵：

| 栈内 \ 栈外 | i | + | # |
| --- | --- | --- | --- |
| i | — | ⋗ | ⋗ |
| + | ⋖ | ⋗ | ⋗ |
| # | ⋖ | ⋖ | — |

无冲突，是算符优先文法。

> 这个文法只能生成 `i+i+...+i`。`LASTVT(E)` 里既有 `i` 也有 `+`：`+` 是紧挨在末尾非终结符 T 前的终结符，按规则要算进去。若只把 `LASTVT` 当成“最后一个字符”，就会漏掉 `+`。

# 四、语义分析与中间代码

语法分析只保证结构合法，语义分析还要回答“名字指哪个声明、类型是否匹配、值怎么算”。这一章的知识点集中在属性文法、翻译文法、中间表示和声明处理，题型以“给表达式写后缀/四元式”“给翻译文法求活动序列”“给基本块画 DAG 并优化”为主。

## 属性文法

### 综合属性与继承属性

属性是附着在文法符号上的值。产生式 $A\to X_1X_2\cdots X_n$ 可以带语义规则：

$$
b:=f(c_1,c_2,\ldots)
$$

- 综合属性：$A$ 的属性由子节点 $X_i$ 的属性计算，沿语法树自下而上。
- 继承属性：$X_i$ 的属性由父节点 $A$ 或左兄弟的属性计算，沿语法树自上而下或从左到右。

| 类别 | 允许的属性 | 求值方式 |
| --- | --- | --- |
| S 属性文法 | 只有综合属性 | 自下而上，可边归约边求值 |
| L 属性文法 | 综合属性 + 受限继承属性（只依赖父节点和左兄弟） | 深度优先、从左到右 |

> 综合属性像“孩子把结果交给父亲”，继承属性像“父亲把上下文传给孩子”。S 属性最省事，因为归约时孩子的值已经算好；L 属性稍复杂，但仍在一次从左到右的遍历中完成。

## 翻译文法与活动序列

### 活动序列与动作序列

翻译文法在产生式右部嵌入动作符号，通常写成 `@a`。动作符号不消耗输入，只执行语义动作或输出。

对输入串做推导，把推导过程中出现的终结符和动作符号按从左到右排列，得到活动序列。去掉终结符，只剩动作符号的序列就是动作序列；执行这些动作产生的输出串就是翻译结果。

> 活动序列像“做菜的步骤清单”：终结符是食材，动作符号是“切、炒、装盘”。推导树确定后，按叶子从左到右读，就知道先做什么后做什么。

### 题型：翻译文法的活动序列

**解法**

1. 按文法推导输入串，画出语法树。
2. 把动作符号当作叶子，按从左到右的顺序抄下来。
3. 终结符不执行动作；只保留 `@...` 得到动作序列。
4. 每个动作按它的定义输出字符或做计算。

**自编例题** 翻译文法：

```text
S → a S @p | b
```

输入 `aab`，求活动序列和输出（设 `@p` 输出 `a`）。

推导：

```text
S ⇒ a S @p ⇒ a a S @p @p ⇒ a a b @p @p
```

活动序列：`@p @p`；输出：`aa`。

> 动作符号的位置由它在产生式右部的位置决定。写在 S 后面的动作，要等 S 的整棵子树处理完才执行，所以输出顺序与叶子从左到右一致。

## 中间表示

### 四元式、三元式与后缀式

| 形式 | 结构 | 特点 |
| --- | --- | --- |
| 后缀式（逆波兰） | 操作数在前，运算符在后 | 不用括号，栈式求值 |
| 三元式 | `(op, arg1, arg2)`，结果用序号引用 | 间接引用，删除/移动指令麻烦 |
| 四元式 | `(op, arg1, arg2, result)` | 结果用临时变量显式表示，优化方便 |
| 语法树 | 运算符为内部结点 | 保留结构，便于语义检查 |
| DAG | 相同子表达式共享结点 | 直接支持公共子表达式删除 |

四元式的常见操作：

```text
(+, A, B, t1)
(*, t1, C, t2)
(=, t2, _, X)
```

> 四元式像“三地址码”：每条最多一个运算符，结果放在临时变量里。三元式把结果位置省掉，用指令编号代替，所以后面的指令一改，前面的引用就要跟着改；四元式用临时变量名，优化时更灵活。

### 后缀式的转换

中缀转后缀：

1. 操作数直接输出。
2. 运算符入栈前，先弹出栈顶优先级不低于它的运算符；左括号入栈。
3. 右括号弹出到左括号为止。
4. 扫描完弹出剩余运算符。

> 后缀式不需要括号，因为运算符的位置已经决定了计算顺序。转换时“优先级不低于”包括左结合的同级运算符，保证 `a-b-c` 先算左边的减。

### 题型：后缀式与四元式

**解法**

1. 按优先级和结合性加括号，或直接用运算符栈转后缀。
2. 后缀式里操作数顺序不变，运算符出现在它的两个操作数之后。
3. 四元式按后缀式的计算顺序逐条生成，每个中间结果起一个临时变量。
4. 赋值语句最后用 `=` 四元式写回左部。

**自编例题** 表达式 `a*(b+c)-d/e`，写后缀式和四元式。

后缀式：

```text
a b c + * d e / -
```

四元式：

```text
(+, b, c, t1)
(*, a, t1, t2)
(/, d, e, t3)
(-, t2, t3, t4)
```

若要赋给 X，再加 `(=, t4, _, X)`。

> 后缀式里 `b+c` 先变成 `b c +`，再与 a 乘；`d/e` 先算，最后做减。四元式的顺序与后缀式完全一致，照抄即可。

### DAG 与公共子表达式

DAG 的构造：

1. 叶子（变量、常量）建结点，相同名字共享。
2. 每个运算建结点，先查是否已有相同运算符和相同左右操作数的结点；有就复用。
3. 赋值语句把左部变量作为标签加到结果结点上。
4. 变量被重新赋值时，旧结点上的该变量标签失效。

> DAG 把“算过一次的东西”记住。`a=b*c; d=b*c` 的第二条不用再乘，直接让 d 指向第一个乘法结点。重导代码时要注意：如果某个中间结点被多个父结点使用，不能提前覆盖它的操作数。

### 题型：DAG 与公共子表达式

**解法**

1. 按语句顺序建 DAG，变量和常量作叶子。
2. 每个运算先查重；相同运算符、相同左右操作数就复用结点。
3. 赋值给变量加标签；变量重定义时旧标签失效。
4. 按拓扑序重导代码，先算被依赖的结点。
5. 删除死代码和重复赋值。

**自编例题** 基本块：

```text
a = b + c
d = b + c
e = a * d
```

DAG：

```text
n0: b
n1: c
n2: n0 + n1   （标签 a、d）
n3: n2 * n2   （标签 e）
```

### 内情向量

声明语句通常不生成可执行代码，只把名字和属性填入符号表。数组声明要建立“内情向量”（数组模板），常见内容：

| --- | --- |

## 静态分配与动态分配

### 两种分配方式的对比

| 项 | 静态分配 | 动态分配 |
| --- | --- | --- |
| 分配时间 | 编译时确定 | 运行时确定 |

## 活动记录

### 活动记录的组成

一次过程调用对应的栈帧（活动记录）通常包含：

| 内容 | 作用 |
| --- | --- |
| 实参 | 调用者传入的参数 |
| 返回地址 | 被调过程返回后继续执行的位置 |
| 旧的基址指针 abp | 指向上一个活动记录的基址 |
| 局部变量 | 过程内部声明的变量 |
| 临时变量 | 表达式计算的中间结果 |
| 保存的寄存器 | 调用前后需要恢复的寄存器 |
| display / 静态链 | 访问外层作用域 |

栈通常从高地址向低地址增长。申请帧时把栈指针 SP 减小；释放时 SP 增大。

> 活动记录像“一次函数调用的行李箱”：参数、返回地址、旧基址、局部变量都装在里面。函数返回时整个箱子弹出，局部变量随之消失，所以局部变量的地址不能带回调用者。

### 参数传递

- 值传递：把实参的值复制到形参，形参修改不影响实参。
- 引用传递：把实参地址传给形参，形参修改影响实参。
- 名传递：用文本替换，每次访问重新求值（了解即可）。

### 嵌套作用域与 display

嵌套过程访问非局部名字时，需要沿静态链找到外层活动记录。display 是一个数组，`display[i]` 指向第 i 层最近的活动记录，访问外层变量时直接查表，避免沿链爬。

> 静态链按“定义环境”连，动态链按“调用环境”连。递归过程中两者可能不同；display 存的是静态链上的层地址。

### 题型：运行栈与活动记录

**解法**

1. 按调用顺序画栈帧，先调用的在栈底，后调用的在栈顶。
2. 每帧填参数、返回地址、旧 abp、局部变量、临时变量。
3. 被调返回时，整帧弹出，返回值放到调用者的约定位置。
4. 递归时同一过程可能出现多帧，注意区分。

**自编例题** 过程 `f(n)` 递归调用 `f(n-1)`，在 `f(2)` 即将返回时，画出栈帧。

```text
栈顶（低地址）
f(2): n=2, 返回地址→main, 旧 abp→main
f(1): n=1, 返回地址→f(2), 旧 abp→f(2)
f(0): n=0, 返回地址→f(1), 旧 abp→f(1)
main
栈底（高地址）
```

`f(0)` 返回后弹出，`f(1)` 继续；`f(1)` 返回后弹出，`f(2)` 继续。

> 栈帧的画法不要求真实地址，关键是顺序和每帧内容。返回地址指向调用者的下一条指令，旧 abp 指向调用者的帧底，这两个指针把栈帧串起来。

## 符号表的分程序结构

### 栈式符号表

栈式符号表：

- 每进入一个分程序，压入一个分程序索引，记录该层第一个符号表项的位置。
- 本层声明的名字依次插入。
- 退出分程序时，弹掉该层全部登记项。
- 查找时从栈顶往下找，先找到的是最内层声明，实现遮蔽。

| 层号 | 名字 | 类型 | 地址 |
| --- | --- | --- | --- |
| 0 | x | int | 100 |
| 0 | f | func | 入口 |
| 1 | y | float | 104 |
| 2 | x | int | 108 |

分程序索引表：`[0, 1, 2]` 分别指向第 0、1、2 层的起始项。

> 第 2 层的 x 会遮蔽第 0 层的 x。退出第 2 层后，索引表弹掉 2，再查 x 就回到第 0 层。符号表栈的结构天然支持这种“内层优先”的查找。

### 题型：符号表与作用域

**解法**

1. 按分程序层次画符号表栈，每层一个索引。
2. 声明按出现顺序登记；同名内层覆盖外层。
3. 查找从栈顶往下，第一次命中即结果。
4. 退出分程序，弹掉该层全部项和索引。

**自编例题** 程序：

```text
0: int x;
1: { float y;
2:   { int x; ... }
   }
```

符号表：

| 层 | 名字 | 类型 |
| --- | --- | --- |
| 0 | x | int |
| 1 | y | float |
| 2 | x | int |

在层 2 中查 x，命中层 2 的 int x；退出层 2 后再查 x，命中层 0 的 int x。

> 符号表栈的“栈”体现在退出分程序时整层弹出，不必每声明一个名字弹一次。

## 数组地址计算

### 行优先地址公式

设数组 $A[L_1:U_1,\ldots,L_n:U_n]$，元素大小为 $E$，按行优先存放。

维度大小：

$$
P_n=1,\qquad P_i=\prod_{j=i+1}^{n}(U_j-L_j+1)
$$

地址：

$$
ADDR(A[V_1,\ldots,V_n])=LOC+RC+E\sum_{i=1}^{n}V_iP_i
$$

其中常数偏移：

$$
RC=-E\sum_{i=1}^{n}L_iP_i
$$

> 行优先像“按行翻书”：最后一维变化最快，第一维变化最慢。$P_i$ 是第 i 维“跳一格”要跨过多少个元素；RC 把下标从下界开始平移，使最低下标对应的偏移为 0。

### RC 与数组模板

数组模板所需空间常用 $3n+2$ 个字：n 维，每维 3 项，再加首地址和元素大小 2 项。

> 若题目问“数组模板需要多少字”，n 维就是 $3n+2$。若问“数组本身占多少字节”，则用元素个数乘 E。

### 题型：数组地址与 RC

**解法**

1. 写出每维下界 $L_i$、上界 $U_i$、元素大小 E。
2. 从最后一维往前算 $P_i$：$P_n=1$，$P_i=(U_{i+1}-L_{i+1}+1)P_{i+1}$。
3. 算 $RC=-E\sum L_iP_i$。
4. 把目标下标代入 $ADDR=LOC+RC+E\sum V_iP_i$。
5. 若给的是地址差，RC 会抵消，只剩下标偏移差。

**自编例题** 数组 $A[-1:2,0:3,1:4]$，E=4，求 RC 和 $A[0,2,3]$ 相对 LOC 的地址。

n=3：

```text
P3 = 1
P2 = (4-1+1) * 1 = 4
P1 = (3-0+1) * 4 = 16
RC = -4 * ((-1)*16 + 0*4 + 1*1)
   = -4 * (-16 + 1)
   = 60
```

$A[0,2,3]$ 的偏移：

```text
E*(0*16 + 2*4 + 3*1) = 4*(8+3) = 44
ADDR = LOC + 60 + 44 = LOC + 104
```

> 先算 RC 再算地址，比直接展开公式不容易错。RC 只由下界决定，同一数组的所有元素共享同一个 RC。

[analysis]
维度大小从右往左算：

流图：基本块为结点，控制转移为有向边。`goto` 和条件跳转的 true/false 出口都要连边。

B1: i = 0
B2: L1: if i < 10 goto L2

```text
B1 → B2
B2 → B4（true）
B2 → B3（false）
B4 → B2
B3 → exit
```

## 局部优化

### 基本块内的优化手段

| 优化 | 做法 | 注意 |
| --- | --- | --- |
| 常量折叠 | 编译时算 `2*3` 为 6 | 溢出和浮点精度要按语言规则 |
| 常量传播 | 把已知常量代入后续使用 | 变量被重新赋值后失效 |
| 公共子表达式删除 | 相同运算只算一次 | 操作数不能被中途改写 |
| 复写传播 | `a=b` 后把 a 替换成 b | 只在没有新赋值时有效 |
| 死代码删除 | 删除结果永不被使用的赋值 | 可能连锁删除 |
| 强度削弱 | 乘法换成加法/移位 | 只对特定常数和类型安全 |
| 代数化简 | `x*1`、`x+0` 化简 | 注意浮点和溢出语义 |

> 局部优化在基本块内做，信息完整、风险小。公共子表达式删除和死代码删除经常一起用：先发现重复计算，再发现某些结果根本没人用。

## DAG

### DAG 的构造与重导

DAG 的结点表示变量、常量和运算；相同运算且操作数相同的结点共享。赋值语句给结点加变量标签；变量重新赋值时，旧标签失效。

### DAG 的用途

DAG 的用途：

- 发现公共子表达式。
- 发现死代码（没有标签、也没有被使用的结点）。
- 为重导代码提供拓扑序。

> DAG 画得对称没有用，目标就是同一个表达式只留一个结点。重导代码时，如果某个结点有多个父结点，先算它，并保证它的操作数在最后一次使用前不被覆盖。

## 循环优化

### 循环不变量外提

循环体里值不变的表达式，可以移到循环外只算一次。判断标准是它的操作数在循环内没有被重新赋值。

> 外提的前提是“循环内不改变值，且外提不会改变异常/副作用顺序”。除数、可能越界的数组访问不能随便外提。

## 数据流分析

### 到达定义

`GEN[B]`：块内生成、且未被块内后续定义杀死的定义。
`KILL[B]`：块内被杀死的定义。

$$
IN[B]=\bigcup_{P\in pred(B)}OUT[P]\\
OUT[B]=GEN[B]\cup(IN[B]-KILL[B])
$$

### 活跃变量

`USE[B]`：块内先使用后定义（use before def）的变量。
`DEF[B]`：块内定义的变量。

$$
IN[B]=USE[B]\cup(OUT[B]-DEF[B])\\
OUT[B]=\bigcup_{S\in succ(B)}IN[S]
$$

从后往前迭代，直到不动点。

> 活跃变量回答“这个变量以后还会不会被用”。`USE` 只算“在块内定义之前就被使用”的变量；如果先定义后使用，这个使用不算 USE，因为块内已经有值了。

## 冲突图与图着色

### 冲突图的构造

冲突图：两个变量如果在某个程序点同时活跃，就连一条边。更常用的判定是：在变量 B 的定义点，若变量 A 活跃，则 A 与 B 冲突。

### 图着色分配寄存器

图着色分配寄存器：

1. 设可用寄存器数为 k。
2. 反复删除度小于 k 的结点，压入栈。
3. 若没有度小于 k 的结点，选一个 spill 候选。
4. 按栈逆序染色，每个结点选一个与邻居不同的颜色。
5. 染不上的结点溢出到内存，插入 load/store。

> 图着色像给地图上相邻国家涂不同颜色，颜色就是寄存器。度小于 k 的结点一定还有空颜色，所以可以先删；删不动了就说明可能需要溢出。

### 题型：活跃变量与冲突图

**解法**

1. 对每块算 USE、DEF。
2. 从出口块开始，按 $IN=USE\cup(OUT-DEF)$、$OUT=\cup IN[succ]$ 迭代。
3. 在定义点看 OUT，给定义变量与 OUT 中其它变量连边。
4. 去掉不参与全局分配的变量，得到冲突图。

**自编例题** 代码：

```text
B1: a = 1
    b = 2
    goto B2
B2: c = a + b
    d = b
    if c > 0 goto B3
B3: e = c + d
    return e
```

活跃变量：

| 块 | USE | DEF | IN | OUT |
| --- | --- | --- | --- | --- |
| B3 | {c,d} | {e} | {c,d} | ∅ |
| B2 | {a,b} | {c,d} | {a,b} | {c,d} |
| B1 | ∅ | {a,b} | ∅ | {a,b} |

冲突：

- B1 定义 a、b，OUT 有 a、b，所以 a-b 冲突。
- B2 定义 c、d，OUT 有 c、d，所以 c-d 冲突。
- B2 定义 c 时，a、b 已经不再活跃（OUT 只有 c、d），所以 c 不与 a、b 冲突。

冲突图两条边：`a—b`、`c—d`。两个寄存器即可：a、c 用 X1，b、d 用 X2。

> 这题容易错在“B2 用了 a、b，所以 c 与 a、b 冲突”。冲突看的是定义点之后还活不活，a、b 在 c 定义后已经死了，不构成冲突。

基本块划分先标 leader：第一条 j=0；跳转目标 L1、L2、L3、L4、L5；每条跳转的下一条语句（r=0、i=0、write t7、write i,j、return r 等）。按 leader 切开后得到 B1～B8。注意 B1 只含 `j=0; r=0`，因为 L1 是跳转目标，必须是新块的开头；B2 从 L1 开始，到 `if i<8 goto L3` 结束。

流图按每条跳转连边。B2 的 true 出口是 L3（B4），false 出口是下一条 L2（B3）；B4 的 true 出口是 L4（B6），false 出口是下一条 `write t7`（B5）；B6 的 true 出口是 L2（B3），false 出口是 L5（B7）；B7 的 true 出口是 L1（B2），false 出口是 `return r`（B8）。

DAG 里要注意 `t3`、`t4` 被重新赋值。第一条 `t4=a+t3` 形成 n8；第二条 `t4=a+t4` 用的是 n8，不是新 `t3`，所以 n11=n3+n8。第二个 `t3=4*t2` 形成 n10，但没有任何结点引用 n10，因此 n10 死；n6（t2）只被 n10 引用，也死。删除 n6、n10 后，代码从 10 条降到 7 条。

活跃变量的迭代从出口 B8 开始。B8 的 IN 是 {r}；B7 的 OUT 是 IN[B2]∪IN[B8]，IN 是 {j}∪(OUT-{j})；B6 的 OUT 是 IN[B3]∪IN[B7]，IN 是 {i,j,r,t7}∪(OUT-{r,i})；依次往前推到 B1。x、y、a 在 B3 被使用，所以一路活跃到 B1；t7 在 B5/B6 被使用，也活跃到 B1。

冲突图按“定义变量与 OUT 中其它变量连边”：

- B1 定义 j、r，OUT 有 j、r、t7，得到 j-r、j-t7、r-t7。
- B2 定义 i，OUT 有 j、r、t7，得到 i-j、i-r、i-t7。

- B7 定义 j，OUT 有 r、t7，补上 j-r、j-t7。

六条边正好组成 K4，四个寄存器一人一个颜色，不需要溢出。

### 题型：图着色

**解法**

1. 数每个结点的度。
2. 度 < k 的结点入栈并删除，更新邻居度。
3. 全部入栈后逆序染色。
4. 若某结点无颜色可选，标记 spill，插入访存。

**自编例题** 冲突图：三角形 a-b-c，k=2。

三个结点度都是 2，没有度 < 2 的结点，必须 spill 一个。选 c 溢出，删除 c 后 a-b 度都为 1，依次入栈；染色 a=X1、b=X2，c 溢出到内存。

> k=2 时三角形就是不可 2 染色的典型。实际分配时选溢出代价最小的结点，不一定是 c；考试写出“选一个 spill，剩余可染”即可。

# 附：公式与易错点

## 常用公式

| 任务 | 公式/判定 |
| --- | --- |
| 数组地址 | $ADDR=LOC+RC+E\sum V_iP_i$ |
| 维度乘积 | $P_n=1$，$P_i=(U_{i+1}-L_{i+1}+1)P_{i+1}$ |
| 常数偏移 | $RC=-E\sum L_iP_i$ |
| 数组模板 | $3n+2$ 个字 |
| 活跃变量 | $IN=USE\cup(OUT-DEF)$，$OUT=\cup IN[succ]$ |
| 到达定义 | $IN=\cup OUT[pred]$，$OUT=GEN\cup(IN-KILL)$ |
| LL(1) | 各候选式 FIRST 不交；可空候选式的 FOLLOW 与其它 FIRST 不交 |
| 算符优先 | `a⋖b` 看 FIRSTVT，`a⋗b` 看 LASTVT，`a≐b` 看相邻 |

## 高频易错点

1. **句子与句型**：句子只含终结符；句型可以含非终结符。语言的元素是句子。
2. **语言与文法**：一个语言可由多个文法产生；文法二义不等于语言二义。
3. **短语与素短语**：短语是任意子树的叶子串；简单短语是高度 1 的子树；句柄是最左简单短语；素短语至少含一个终结符，且不含更小的素短语。
4. **句柄**：句柄一定是最左简单短语，但不一定是素短语。算符优先归约的是最左素短语，不是句柄。
5. **消除左递归**：$A\to A\alpha\mid\beta$ 改成 $A\to\beta A'$、$A'\to\alpha A'\mid\varepsilon$。间接左递归先代入。
6. **NFA 确定化**：先 move 再 ε-closure；DFA 终态看集合是否含原终态；不可达状态要删。
7. **DFA 最小化**：先分终态/非终态，再按转移落点组细分；不是看状态图形是否对称。
8. **FIRST/FOLLOW**：FOLLOW 只在非终结符后面找；右部末尾可空时要并入左部 FOLLOW；可空候选式的 LL(1) 冲突看 FOLLOW。
9. **FIRSTVT/LASTVT**：不是简单看串首/串尾字符。`U→V a...` 的 a 进 FIRSTVT，`U→...a V` 的 a 进 LASTVT。
10. **LR 系列**：LR(0) 圆点在末尾就归约；SLR 用 FOLLOW 限制；LR(1) 用项目 lookahead；LALR 合并同心集，lookahead 取并集，只可能产生归约-归约冲突。
11. **LALR 合并**：合并的是“核心相同”的状态，不是编号相同；合并后状态数通常与 LR(0) 相同。
12. **基本块**：leader 包括第一条、跳转目标、跳转的下一条；`return` 前有跳转时也要单独成块。
13. **活跃变量**：USE 只算“先使用后定义”；先定义后使用不算 USE；OUT 是后继 IN 的并集。
14. **冲突图**：在定义点看 OUT，定义变量与 OUT 中其它变量连边；不要把所有同时出现在块里的变量都连边。
15. **四元式赋值**：后缀式里赋值写成 `X ... =`；四元式 `(=, t, _, X)` 的结果字段是 X。
16. **静态/动态分配**：静态分配不支持递归和动态数组；动态分配的活动记录随调用压栈、返回弹栈。
17. **数组 RC**：RC 由下界产生，通常是负数；地址是 LOC+RC+偏移，不能只写偏移。
18. **算符优先过程**：`⋖` 移进，`≐` 移进，`⋗` 归约最左素短语；无关系报错。

## 答题顺序建议

综合题先做自动机和 LL(1)，因为步骤固定、分值高；再做 LR 和算符优先，注意检查冲突；最后做符号表/运行栈和优化，画表比写长段文字稳。

填空判断遇到不确定的概念，回到定义找反例：句子/句型、短语/素短语、LR(0)/SLR、静态/动态，这几组最容易混。

> 复习时不必把每道真题从头到尾背下来。把每类题的“第一步做什么、表怎么填、冲突怎么判断”练熟，换一道题仍然能按同一套动作做出来，这才是这类考试真正考的东西。
