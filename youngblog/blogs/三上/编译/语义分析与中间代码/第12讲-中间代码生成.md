# 声明处理与中间代码生成

## 栈式抽象机模型

### 运行时存储结构

- **运行栈**：三个指针
  - `BP`（Base Pointer）：当前活动记录基址
  - `SP`（Stack Pointer）：当前活动记录栈顶
  - `NP`（New Pointer）：新记录栈顶（分配空间时用）
- **程序指令存储器**：存放目标代码，`PC` 为程序计数器
- **操作数栈**：表达式求值用的栈

### 常用指令

| 指令 | 功能 |
|------|------|
| `LOD` | 取变量值到操作数栈顶 |
| `LDC` | 取常量到操作数栈顶 |
| `LDA` | 取变量地址到操作数栈顶 |
| `STO` | 栈顶值存入指定地址（弹出两个操作数） |
| `ST` | 栈顶值存入指定地址（弹出一个操作数） |
| `STN` | 带类型转换的存储 |
| `ADD/SUB/MUL/DIV` | 算术运算 |
| `EQL/NEQ/LSS/LEQ/GTR/GEQ` | 关系运算 |
| `JMP/JMF` | 无条件/条件转移 |
| `JSR` | 转子程序（压返回地址+跳转） |
| `ALC` | 分配活动记录空间 |

## 声明处理

### 简单变量声明

输入文法：

```
<var decl> $\to$ <type> <id list>
<id list> $\to$ <id> | <id>, <id list>
```

ATG 文法中的关键动作：
- `@svardef`：将变量名、类型填入符号表
- `@allocsv`：为变量分配相对地址（ON），填入符号表

### 常量声明

- `@insert`：检查常量名是否重复、类型是否匹配，然后填入符号表
- 常量的值在编译时已知，可直接用于常量折叠优化

### 变长字符串

- 字符串长度可变，不能在编译时确定存储空间
- 采用动态申请堆存储：变量单元中存放指向字符串的指针
- 赋值时复制字符串内容到新的堆空间

## 数组声明

### 数组分类

| 类型 | 特点 |
|------|------|
| 静态数组（常界数组） | 编译时上下界已知，大小可在编译时确定 |
| 动态数组（变异数组） | 上下界含变量，运行时才知道大小 |

### 数组元素地址计算公式

设 n 维数组，各维上下界为 $L(i)$ 和 $U(i)$，下标为 $V(1)\ldots V(n)$，元素大小为 $E$：

$$ADR = LOC + \sum_{i=1}^{n} [V(i) - L(i)] \times P(i) \times E$$

其中：
- $P(i) = 1$（当 $i = n$ 时）
- $P(i) = \prod_{j=i+1}^{n} [U(j) - L(j) + 1]$（当 $1 \leq i < n$ 时）

### 地址公式的分解

$$ADDR = LOC + \underbrace{\sum V(i) \times P(i) \times E}_{\text{可变部分}} + \underbrace{RC}_{\text{不变部分}}$$

$RC = -\sum L(i) \times P(i) \times E$ 可在编译时提前计算。

### P(i) 的递推计算

由于 $P(i)$ 依赖 $P(i+1)$，实际计算时从最后一维向前反填：

$$P(i) = [U(i+1) - L(i+1) + 1] \times P(i+1)$$

### 数组模板（信息向量表）

大小为 $3n+2$，结构如下（从高维到低维排列）：

| 域 | 含义 |
|----|------|
| $U(n), L(n), P(n)$ | 第 n 维上界、下界、计算常量 |
| ... | ... |
| $U(1), L(1), P(1)$ | 第 1 维上界、下界、计算常量 |
| $n$ | 维数 |
| $RC$ | 地址计算常量 |

功能：
1. 用于计算下标变量地址
2. 检查下标是否越界

> 常界数组的模板在编译时构造；变异数组的模板在目标程序运行时构造，编译程序需生成相应指令。

### 数组声明的 ATG 动作

- `@init`：在数组模板区保留 RC 和 n 两个单元，维数计数器 j 清零
- `@dimen#`：j := j+1，统计维数
- `@bands`：省略下界时 $L(i)$ 取隐含值（如 1），计算 $P(i)$
- `@lowerbnd`：l $\to$ $L(i)$
- `@upperbnd`：u $\to$ $U(i)$，计算 $P(i)$
- `@symbinsert`：数组名、维数、类型、标志填入符号表，分配存储空间

## 过程与函数声明

### 符号表登记

过程名和形参名依次填入符号表：
- 过程名：kind=procedure，dim=形参个数
- 形参：kind=parameter，记录类型和顺序

### ATG 关键动作

- `@tblinsert`：将过程名/形参名填入符号表（检查重名）
- `@upcnt`：形参个数计数
- `@emitstores`：生成将操作数栈顶实参存入活动记录形参单元的指令
- `@initcnt`：形参计数器初始化

过程体头部生成指令：`ALC` 分配活动记录空间，`STO` 保存返回地址和各形参值。

> 实际 ALC 指令分配的空间应在所有局部变量定义处理完后，考虑固定空间大小，反填回去。

中间代码生成的声明处理围绕符号表填表加存储分配展开：简单变量直接分配相对地址，数组通过模板（信息向量表，$3n+2$）和地址公式管理，过程声明登记形参并生成活动记录分配指令。
