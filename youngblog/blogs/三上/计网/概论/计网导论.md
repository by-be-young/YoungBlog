# 什么是计算机网络？

> 本章介绍计算机网络的基本概念、互联网发展历史、网络组成，以及协议分层与服务模型。

## 定义与要点

### 计算机网络

#### 计算机网络是相互连接的自治计算机集合。

由单一技术互连的自治计算机集合。大型计算机连接许多终端、服务整个组织计算需求的旧模型已完全过时。

### 分布式系统

#### 分布式系统是建立在网络之上的软件系统。

例如 WWW。

### 资源共享

#### 计算机网络是计算机的集合。

通过通信链路连接，目标是共享资源。资源包括：计算机硬件、软件、信息（数据）以及对他人有用的东西。在网络中，计算机是集合的元素。

## 软件、服务、接口

### 协议

#### 协议描述通信双方如何交换信息。

### 服务

#### 服务描述网络向希望通信的各方提供什么。

### 接口

#### 接口描述客户端如何使用网络服务，即服务如何被访问。

软件才是真正构成计算机网络的部分，而不是硬件。

# 协议分层、服务模型

## 什么是协议？

#### 网络协议定义网络实体之间发送和接收消息的格式、顺序，以及发送/接收消息时采取的动作。

### 协议要素

| 要素 | 说明 |
| :--- | :--- |
| Syntax | 语法 |
| Semantics | 语义 |
| Timing | 时序关系 |
| Actions | 动作 |

## 人类协议与计算机网络协议

人类协议示例：问好、询问时间、回答时间。  
计算机网络协议示例：TCP 连接请求、TCP 连接响应、获取 URL、返回文件。

## 分层设计

### 设计目标

#### 降低设计复杂度

将通信问题分成子问题，为每个子问题设计单独协议，使每个协议更易于设计、分析和实现。

#### 独立性

每一层可以独立设计，只要记住下层为其提供的服务以及它应为上层提供的服务。

#### 灵活性

允许按需使用协议子集，并允许任一协议被替换或更新。

## OSI 七层模型与 TCP/IP 四层模型

| 模型 | 层数 | 地位 |
| :--- | :--- | :--- |
| ISO/OSI（OSI/RM）开放式系统互联参考模型 | 七层 | 合法标准 |
| TCP/IP（TCP/IP 协议族）传输控制协议和互联网协议族 | 四层 | 事实上的标准 |

### OSI 七层模型

| 层 | 功能 | PDU | 协议 |
| :--- | :--- | :--- | :--- |
| 应用层 | 网络进程到应用 | APDU | Application protocol |
| 表示层 | 加密、解密和数据转换 | PPDU | Presentation protocol |
| 会话层 | 管理应用之间的会话 | SPDU | Session protocol |
| 传输层 | 端到端连接和可靠性 | TPDU | Transport protocol |
| 网络层 | 路径确定和逻辑寻址 | Packet | Network layer host-router protocol |
| 数据链路层 | 物理寻址 | Frame | Data link layer host-router protocol |
| 物理层 | 信号和二进制传输 | Bit | Physical layer host-router protocol |

### TCP/IP 四层模型

| 层 | 功能 | 协议例子 |
| :--- | :--- | :--- |
| 应用层 | 支持网络应用 | FTP, SMTP, HTTP |
| 传输层 | 进程到进程数据传输 | TCP, UDP |
| 互联网层 | 数据报路由 | IP, routing protocols |
| 链路层 | 相邻网络元素之间数据传输 | PPP, Ethernet |

### OSI 与 TCP/IP 比较

| 共同点 | 差异 |
| :--- | :--- |
| 独立协议栈；层功能大致相似。 | OSI 中服务、接口和协议是核心概念；TCP/IP 不区分这些概念，不是通用模型。OSI 先定义模型后定义协议；TCP/IP 相反。OSI 模型/协议太复杂耗时；TCP/IP 简单且不全面。层数不同。OSI 模型对讨论计算机网络非常有用，但 OSI 协议不流行；TCP/IP 模型实际上不存在，但协议广泛使用、根深蒂固、难以替换。 |

## 封装

#### 封装是设计模块化通信协议的方法，其中网络中逻辑上独立的功能通过包含或信息隐藏在更高层对象中，从其底层结构抽象出来。

| 层 | 数据单元 |
| :--- | :--- |
| 应用层 | Data |
| 传输层 | UDP header + UDP data |
| 互联网层 | IP header + IP data |
| 链路层 | Frame header + Frame data + Frame footer |

## 数据单元

| 层 | 功能 | 数据单元 |
| :--- | :--- | :--- |
| 应用层 | 网络进程到应用 | Data |
| 表示层 | 加密、解密和数据转换 | - |
| 会话层 | 管理应用之间的会话 | - |
| 传输层 | 端到端连接和可靠性 | Segments |
| 网络层 | 路径确定和逻辑寻址 | Packets (datagrams) |
| 数据链路层 | 物理寻址 | Frame |
| 物理层 | 信号和二进制传输 | Bit |

## 各层本质

### 物理层

#### 本质：描述原始比特的传输，涉及机械和电气问题。

例子：用导线连接两台计算机：导线上设置 -3 V 对应二进制 1；+4 V 对应二进制 0。导线长度不超过 15 米。电压每秒最多变化 20,000 次。

### 数据链路层

#### 本质：将原始传输设施转变为对网络层看来无未检测传输错误的线路 => 以帧发送比特，添加冗余以检测错误。

提供机制使快速发送方不会淹没慢速接收方（流量控制）。广播网络在数据链路层有额外问题：如何控制对共享信道的访问。

### 网络层

#### 本质：描述如何进行路由（和拥塞控制），并允许异质网络互连。

问题：如何找出网络中有哪些计算机/路由器？如何计算从 A 到 B 的最佳路由？计算机/路由器宕机时会发生什么？是否应支持多播/广播？如果路由器过载并开始丢弃分组会发生什么？能否检测和避免“热点”？

### 传输层

#### 本质：规定如何处理可靠传输的细节，该层为应用提供实际网络接口。

通常通过套接字（UNIX、Windows）提供网络接口。允许建立到另一个应用的连接，并随后可靠地、按发送顺序交付数据。还支持数据报：基于每条消息的不可靠消息传递。

### 会话层与表示层

#### 会话层：告诉应用如何建立“长期”通信，例如允许突然中断时重新建立连接（想想下载大文件）。

#### 表示层：描述以平台无关方式交换数据所需的一切。例子：不同计算机中的字节序，或通过电子邮件传递“二进制”数据。

Internet 协议栈“缺少”这些层！这些服务如果需要，必须在应用中实现。需要吗？

### 应用层

#### 本质：包含用户常用的一系列协议。

| 类别  | 协议                                                                      |
| :-- | :---------------------------------------------------------------------- |
| 传统  | 名称服务（DNS）、安全、电子邮件（SMTP）、新闻（NNTP）、Web（HTTP）                              |
| 现代  | 所有类型的中间件协议以支持分布式系统：RMI（远程方法调用）、CORBA（IIOP，公共对象请求代理体系结构）、DCOM（分布式组件对象模型） |
