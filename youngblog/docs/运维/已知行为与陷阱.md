# 已知行为与陷阱

以下是当前实现中**有意保留或尚未修复**的行为。改动前先读完对应条目，
不要以「看起来是 bug」为由直接修改，否则可能改变线上视觉或破坏旧链接。

## 1. 背景图清单恒为空

- 现象：`public/data/background-images.json` 内容为 `{"images": []}`。
- 原因：`generate.js` 扫描的是仓库根目录的 `assets/images/background`，
  实际图片位于 `public/assets/images/background`，该根目录不存在。
- 结果：`resolveBackgroundImages` 回退到 `DEFAULT_BACKGROUND_IMAGES`（三张默认图）。
- 约束：直接「修好」路径会让站点突然加载全部背景图，首屏体积与视觉都会变化。
  若要启用清单，需同时评估 preload、压缩与加载器进度。

## 2. `series.json` 不是系列页的数据源

- 生成器输出 `series.json`，入场加载器也会预取它；
- 但 `SeriesView` 使用 `useSeries` 从 `blogStore.blogs` 派生系列结构。
- 因此只改 `series.json` 不会改变系列页展示；系列数据以 `blogs.json` 为准。

## 3. `articles.json` 是历史快照

- 与 `blogs.json` 同结构，但代码中没有任何引用。
- 保留用于对照历史数据；不要把它接回数据流，避免两份索引不一致。

## 4. 习题块结束标记使用反斜杠

- 正确写法：`[\task]`、`[\options]`、`[\answer]`、`[\analysis]`、`[\question]`。
- 写成 `[/task]` 不会被识别，整块会按普通文本渲染。
- 这是历史实现；修改前需确认没有存量内容依赖该行为。

## 5. 分类规则在两处不完全一致

- `generate.js` 的学习标签集合：`二上/二下/三上/三下/四上/四下/大三`。
- `blogStore.getCategoryKey` 的兜底集合只有 `二上/二下`。
- 正常情况下 `blogs.json` 已带 `category`，以它为准；只有数据缺失时兜底才生效。
- 若未来移除生成数据中的 `category`，两处必须统一。

## 6. 日期会被「保留」

- 构建时优先沿用旧 `blogs.json` 中同路径文章的日期。
- 因此只改正文不会更新发布日期；只有改 frontmatter `date` 才会。
- `lastEditedDate` 仅在文件 mtime 晚于上次生成时间时写入，并非严格的编辑历史。

## 7. 移动文章会换 ID

- 自动 ID 来自 `contentFile` 的哈希。
- 重命名、移动目录都会让 `/blog/<id>` 失效；旧链接无法自动恢复。
- 如需稳定，请在 frontmatter 固定 `id`。

## 8. `postbuild` 复制整个 `blogs/`

- 包括 `.obsidian/` 配置、插件、主题与 `模板/`。
- 这会让 `dist/blogs/` 变大，但保证 Markdown 内的相对资源可用。
- 若未来要精简，需先确认文章是否引用了这些文件。

## 9. 两处背景轮播计时器

- `App.vue` 用本地 `currentBgIndex` + 5 秒定时器驱动实际渲染。
- `backgroundStore.setImages()` 也会启动自己的 5 秒定时器。
- 当前两者不会互相取消，但页面只读取 `App.vue` 的索引；新增逻辑时不要重复推进。

## 10. 入库的 Obsidian 工作区文件

- `blogs/.obsidian/workspace.json` 会随 Obsidian 打开而变化，容易产生噪音 diff。
- 团队约定：不把这类变更混进功能提交；必要时单独提交 `chore(obsidian): ...`。

## 11. Hash 路由与旧链接

- 路由为 `createWebHashHistory`，地址形如 `/#/blog/123`。
- 旧链接 `/blog-detail.html?id=xxx` 会被重定向到 `/blog/xxx`。
- 不要改为 History 模式，静态托管无 404 回退会直接白屏。

## 12. 字体体积

- 原 `仓耳今楷01-W04.ttf` 约 18 MB，但已不再被 CSS 引用；首屏使用 `canger-ui.woff2` 子集（约 408 KB），文章页再按需加载 `canger-content.woff2`（约 255 KB）。
- 它不是错误，但任何替换都应先做子集化或改用 WOFF2，并同步加载器阶段。

## 13. 空 Markdown 文件也会被收录

- `generate.js` 对任何 `.md` 都会生成条目，标题回退为文件名。
- 草稿请放入 `blogs/模板/`（整体跳过），或使用非 `.md` 扩展名。

## 14. 正文按需搜索的成本

- 开启「搜索正文」会逐篇 fetch `contentFile`。
- 文章多时请求数线性增长；这是当前设计的取舍，不是缺陷。
- 若要优化，应引入构建期全文索引，而不是在组件里加缓存补丁。

## 15. `postbuild.js` 不使用 `fs.cpSync`

- 在部分 Windows + Node 22 环境中，`fs.cpSync` 复制包含中文名的目录（如 `blogs/模板`）
  会以 `0xC0000409` 崩溃，且不产生任何产物。
- 因此 `postbuild.js` 改为逐层 `readdir` + `copyFileSync`。输出与 `cpSync` 相同
  （仍会复制整个 `blogs/`，包括 `.obsidian/`）。
- 不要为了「简洁」改回 `cpSync`；如需改动，先在 Windows 上运行一次 `npm run build` 验证。

## 16. lint 基线尚未清零

- `npm run lint` 会依次执行 oxlint 与 ESLint，两者都带 `--fix`。
- 存量代码仍有历史问题（如未使用的参数 / catch 变量），因此 lint 当前**不能阻断构建**；
  CI 中该步骤为 `continue-on-error: true`。
- `blogs/**` 已在 `.oxlintrc.json` 与 `eslint.config.js` 中忽略，避免扫描 Obsidian
  第三方插件与主题脚本；否则会出现大量与本站无关的错误，`--fix` 还可能改写这些文件。
- 清理存量告警应单独提交，并与功能改动分开。
