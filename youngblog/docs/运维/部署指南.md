# 部署指南

站点是纯静态产物：部署 = 上传 `dist/`。差异只在「站点根路径」与「是否提供额外统计文件」。

## 1. 构建产物检查

```bash
npm run build          # 根路径
# 或
npm run build:github   # /YoungBlog/ 子路径
```

确认 `dist/` 包含：

```text
dist/index.html
dist/assets/
dist/data/
dist/blogs/        ← 缺失会导致详情页与正文搜索 404
```

`dist/blogs/` 由 `scripts/postbuild.js` 生成；只上传 `index.html + assets` 是不完整的。

## 2. GitHub Pages

### 2.1 前置条件

- 仓库名为 `YoungBlog`（`vite.config.js` 中 `mode=github` 的 base 写死为 `/YoungBlog/`）。
  若仓库名不同，先改 `base`，再构建。
- Pages 的发布源选择「GitHub Actions」或部署分支。

### 2.2 手动发布

```bash
npm run build:github
# 将 dist/ 推到 Pages 使用的分支，或使用仓库工作流
```

### 2.3 工作流发布

仓库提供 `.github/workflows/deploy-pages.yml`，默认 **手动触发**（`workflow_dispatch`），
避免与已有 Pages 配置冲突。确认 Pages 源为「GitHub Actions」后，可把触发条件改为 push：

```yaml
on:
  push:
    branches: [main]
```

工作流步骤：`npm ci` → `npm run build:github` → 上传 `dist` → `actions/deploy-pages`。

### 2.4 为什么用 Hash 路由

Pages 无法为任意深链接返回 `index.html`。Hash 路由（`/#/blog/123`）把路径留在 `#` 之后，
服务器只看到 `index.html`，因此刷新与直接访问都不会 404。

## 3. 自建服务器（Nginx 示例）

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/youngblog/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 构建产物带 hash，可长期缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 数据与文章每次发布可能变化
    location /data/ {
        add_header Cache-Control "no-cache";
    }

    location /blogs/ {
        add_header Cache-Control "no-cache";
    }

    gzip on;
    gzip_types text/css application/javascript application/json text/markdown image/svg+xml;
}
```

要点：

- `try_files` 回退到 `index.html` 是良好实践，即使使用 Hash 路由。
- `index.html` 不要长缓存，否则用户会一直拿到旧入口。
- 若启用 HTTPS，确保字体与图片没有混合内容。

## 4. 访问量统计（可选）

服务器可定期从访问日志生成 `dist/stats.json`：

```json
{ "site_pv": 12345 }
```

页脚每 5 分钟读取一次（`cache: no-store`）。GitHub Pages 无此文件时静默隐藏，不影响其他功能。

## 5. 本地验收

```bash
node scripts/preview-server.mjs --port 4180
```

它同时服务 `dist/` 与仓库根目录，可验证：

- `/#/blog/<id>` 能读到 `/blogs/**/*.md`
- `/assets`、`/data` 路径正确
- 子路径模式下前缀无误（构建时已写入产物）

## 6. 部署检查清单

- [ ] `dist/blogs/` 存在。
- [ ] `base` 与访问路径一致。
- [ ] `index.html` 的 preload 图片在 `dist/assets` 中存在。
- [ ] 刷新详情页不 404。
- [ ] 移动端能正常退出沉浸模式。
- [ ] 若使用 CDN，已刷新入口 HTML 缓存。

## 7. 回滚

静态站点回滚成本低：重新上传上一版 `dist/` 即可。
若使用工作流，重新运行上一个成功的部署任务。

## 8. 常见部署错误

| 现象 | 原因 |
| --- | --- |
| 页面空白、控制台 404 `/YoungBlog/assets/...` | 用根路径构建却部署到子路径 |
| 页面空白、404 `/assets/...` | 子路径构建却部署到根路径 |
| 首页正常、详情页空 | 未上传 `dist/blogs/` |
| 旧页面持续出现 | CDN / 浏览器缓存了 `index.html` |
| 字体加载失败 | 字体未随 `src/assets` 打包，或服务器禁止大文件 |
