# 可访问性

站点不是「无障碍认证」项目，但已有若干基础支持。新增 UI 时请至少保持同等水平。

## 1. 现状

| 方面 | 现状 |
| --- | --- |
| 键盘 | 导航、搜索、目录、选项、弹窗基本可用键盘操作；图片查看器支持方向键与 Esc |
| 语义 | 页面使用 `<main>` / `<header>` / `<article>` / `<footer>`；弹窗使用 `role="dialog"` + `aria-modal` |
| 标签 | 搜索、设置、公告、图片查看器等控件带 `aria-label` / `aria-hidden` |
| 动效 | 入场加载屏在 `prefers-reduced-motion: reduce` 时跳过 |
| 焦点 | 弹窗打开时聚焦内部控件，关闭后归还触发元素（各弹窗实现略有差异） |
| 对比度 | 深色背景配浅色文字；浅色卡片配深色文字，整体可读 |

## 2. 已知不足

- 部分装饰元素仍可能被屏幕阅读器读到（未统一 `aria-hidden`）。
- 焦点陷阱并非所有弹窗都完整实现。
- 文章内的习题反馈主要依赖颜色与图标，缺少统一的文本播报。
- 动态加载的内容（搜索正文、图表）没有统一的加载状态播报。

## 3. 新增 UI 的检查项

### 键盘

- [ ] Tab 能到达所有可操作元素，顺序合理。
- [ ] Enter / Space 能触发按钮与选项。
- [ ] Esc 能关闭弹窗与查看器。
- [ ] 焦点不会被困在已关闭的弹层里。

### 语义与标签

- [ ] 图标按钮必须有 `aria-label`。
- [ ] 纯装饰元素加 `aria-hidden="true"`。
- [ ] 弹窗声明 `role="dialog"`、`aria-modal="true"`，并提供标题。
- [ ] 图片有有意义的 `alt`；纯装饰图用空 `alt`。

### 视觉

- [ ] 正文对比度不低于 4.5:1（大字 3:1）。
- [ ] 不只用颜色表达状态（对/错同时给图标或文字）。
- [ ] 200% 缩放时布局不横向滚动。

### 动效

- [ ] `prefers-reduced-motion` 下关闭非必要动画。
- [ ] 加载动画不会无限阻塞内容（有超时或回退）。

## 4. 快速自测

1. 只用键盘从首页走到一篇文章并打开目录。
2. 打开搜索、设置、公告、图片查看器，逐个 Esc 关闭。
3. 系统开启「减少动态效果」，刷新首页，确认直接进入内容。
4. 浏览器缩放 200%，检查导航与卡片是否溢出。

## 5. 修改原则

- 不引入会改变现有键盘行为的全局快捷键。
- 新增弹层优先复用现有弹窗的焦点处理模式。
- 若无法完整支持某场景，在本文档「已知不足」中登记，而不是假装支持。
