# 验证与测试

仓库目前**没有**单元测试框架，也没有端到端测试套件。现有验证由「静态检查 + 构建 + 脚本断言 + 人工抽查」组成。
本文档明确区分「已自动化」与「靠人工」，避免误以为有覆盖。

## 1. 已自动化的检查

| 检查 | 命令 | 覆盖 |
| --- | --- | --- |
| oxlint | `npm run lint:oxlint` | 语法与 correctness 类问题 |
| ESLint | `npm run lint:eslint` | Vue / JS 规则与格式冲突 |
| 生产构建 | `npm run build` | 模块解析、CSS、资源打包、`dist/blogs/` 复制 |
| 文档链接 | `npm run check:docs` | 相对链接是否存在 |
| 图片画质 | `npm run check:images` | 原图 / WebP 的 PSNR、MAE |
| 移动端几何 | `node scripts/verify-detail-mobile.mjs --id <id>` | 详情页关键布局断言 |

CI（`.github/workflows/ci.yml`）执行安装、lint（不阻断）、构建与文档链接检查。

> lint 基线当前仍有存量告警，属于已知状态；CI 中不阻断。详见
> [已知行为与陷阱](已知行为与陷阱.md) 第 16 条。

## 2. 未自动化的部分

- 页面视觉回归（无截图基线）。
- 路由跳转与交互流程。
- 搜索、目录、习题、导出等行为。
- 多语言文案完整性。
- 子路径部署的端到端验证。

这些目前依赖发布前人工抽查。

## 3. 人工验证矩阵

| 维度 | 取值 |
| --- | --- |
| 宽度 | 1440 / 1280 / 1024 / 900 / 768 / 480 / 375 |
| 页面 | 首页、归档、分类、系列、详情、关于、公告、快捷链接 |
| 模式 | 根路径构建、`build:github` 子路径构建 |
| 设置 | 沉浸 / 宽屏、四种习题模式、三种代码块模式 |
| 语言 | 中文、English、日本語 |
| 动效 | 正常、`prefers-reduced-motion` |

至少覆盖：首页 + 一篇文章 + 一个系列 + 移动端详情。

## 4. 手工回归清单

- [ ] 入场加载屏能正常揭幕，刷新两次结果一致。
- [ ] 背景轮播、萤火虫、导航抽屉正常。
- [ ] 详情页目录高亮跟随滚动，点击可跳转。
- [ ] 代码块复制、折叠、全屏（Mermaid）可用。
- [ ] 图片查看器可缩放、切换、Esc 关闭。
- [ ] 任务清单勾选后刷新仍保留。
- [ ] 习题选择、提交、对错反馈正常。
- [ ] 上一篇 / 下一篇跳转正确。
- [ ] 搜索标题与正文都能命中。
- [ ] 导出文件内容可读。

## 5. 引入自动化测试的建议

若未来补测试，优先级建议：

1. **单元测试（Vitest）**：`generate.js` 的 frontmatter 归一化、`useSeries` 的排序、
   `resolveUrl` 的 base 拼接、`useMarkdown` 的纯函数部分。
2. **组件测试**：`TOC`、`PostNav`、`SearchPanel` 的输入输出。
3. **端到端（Playwright）**：首页 → 文章 → 目录 → 搜索 → 移动端布局。

引入前先补 ADR，说明测试范围与 CI 成本。不要为了覆盖率引入大量脆弱快照。
