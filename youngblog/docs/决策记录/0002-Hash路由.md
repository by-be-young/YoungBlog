# 0002 · 路由使用 Hash 模式

- 状态：已采纳

## 背景

站点部署在 GitHub Pages 与自建静态目录两种环境。前者无法配置 404 回退，
深链接（`/blog/123`）直接访问会返回 404。需要一种不依赖服务端配置的路由形态。

## 决策

使用 `createWebHashHistory`，地址形如 `/#/blog/123`。

- 服务器始终只请求 `index.html`，刷新与深链接天然可用。
- 配合 `base` 可在 `/` 与 `/YoungBlog/` 下工作。
- 旧链接 `/blog-detail.html?id=xxx` 通过路由重定向到 `/blog/xxx`。

## 后果

- URL 带 `#`，不利于部分分享场景与 SEO。
- 站内跳转与滚动行为需要自行处理（`scrollBehavior`）。
- 若未来改用 History 模式，必须同时提供 404 回退与重定向规则。

## 备选

- History 模式：URL 更干净，但 Pages 不支持；自建服务器可以，但两种部署会分裂。
- 生成静态 HTML 页面：需要完整的预渲染管线，超出当前范围。

## 失效条件

托管平台支持 SPA 回退，且 SEO 成为主要目标时，可重新评估。
