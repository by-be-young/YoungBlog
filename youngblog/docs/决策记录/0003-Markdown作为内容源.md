# 0003 · 以 Markdown 作为唯一内容源

- 状态：已采纳

## 背景

文章需要长期维护、可离线编辑、支持公式 / 图表 / 双链，并且能随仓库版本管理。
曾出现过 HTML 片段与 JSON 混用的方案，维护成本高且难以迁移。

## 决策

`blogs/` 下的 Markdown 是唯一内容源：

- 文章元数据写在 frontmatter。
- 目录层级承担分类与标签。
- 图片放在文章同级目录或 `blogs/图片/`。
- Obsidian 可直接打开 `blogs/` 作为仓库。

运行时只读取构建产出的索引与原始 Markdown，不做二次编辑。

## 后果

- 需要构建步骤生成 `blogs.json` 与 `series.json`。
- 内容结构（目录层级）成为契约，移动目录会改变标签与 ID。
- 写作体验依赖 Obsidian 配置，仓库需接受 `.obsidian` 的噪音变更。

## 备选

- 数据库 / CMS：引入服务端，违背静态托管目标。
- 直接在 Vue 中维护文章数组：不可扩展，版本对比困难。

## 失效条件

若需要多人协作编辑、草稿审核或非技术人员写作，才考虑引入内容管理层。
