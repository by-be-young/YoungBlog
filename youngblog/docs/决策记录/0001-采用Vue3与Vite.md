# 0001 · 采用 Vue 3 + Vite 作为站点框架

- 状态：已采纳
- 日期：2026-11（记录重构时的既有事实）

## 背景

站点需要承载大量 Markdown 文章、复杂交互（目录、习题、图片查看器、Mermaid）
以及高度定制的视觉。候选方案有三类：

1. 静态站点生成器（Hugo / Hexo / Astro）——生态成熟，但交互定制受模板限制。
2. 原生 HTML + 手写 JS——自由，但状态与组件复用成本高。
3. Vue 3 + Vite——单文件组件、组合式 API、成熟的构建链。

## 决策

采用 **Vue 3（`<script setup>`）+ Vite 8**，路由使用 Vue Router，状态使用 Pinia。

理由：

- 现有交互（TOC 滚动同步、习题判定、导出、图片查看器）需要组件级状态，Vue 的组合式 API 最贴合。
- Vite 的开发启动与按需加载适合「大字体 + 大图片 + 多文章」的站点。
- 纯前端方案不引入服务端，符合静态托管目标。

## 后果

- 需要自行维护构建脚本（内容索引、后处理）。
- 没有类型系统，依赖 ESLint / oxlint / 约定保证质量。
- 大依赖（Mermaid、KaTeX）必须动态导入，否则首屏体积不可控。

## 备选

- Astro：内容优先，但把现有交互迁移到岛屿架构成本高。
- 纯静态模板：无法支持站点现有的交互密度。

## 失效条件

如果站点转向「内容为主、交互为辅」，或需要服务端渲染 / 多端复用，
应重新评估本决策。
