# 0005 · 采用功能域 + 共享层的目录结构

- 状态：已采纳
- 日期：2026-11-17

## 背景

重构前 `src/` 采用「按类型分层」：`views/`、`components/{home,blog-detail,common,layout}`、
`composables/`、`stores/`、`utils/`、`css/`。随着页面增多，出现两个问题：

1. 页面与其私有组件分散在两层，修改一个页面需要跨目录跳转。
2. `components/home` 与 `views/HomeView` 的归属关系只能靠命名猜测。

## 决策

按**功能域**组织视图与其私有组件，跨域复用下沉到 `shared`：

```text
src/
├── app/          App.vue
├── assets/       字体与全局样式
├── features/     home / blog-detail / archive / categories / series / about / announcements / quick-links
├── router/
├── shared/       components / layout / composables / stores / utils
└── main.js
```

依赖规则：`app → features → shared`，禁止反向与跨域互相引用。

## 后果

- 页面相关文件集中，定位成本降低。
- 导入路径变长，但统一使用 `@/` 别名后差异可控。
- 需要判断「共享还是私有」，判断标准写入贡献指南。
- 现有唯一的跨域引用（关于页复用详情页 `BlogContent`）需要显式记录，
  出现第三处复用时应上移。

## 备选

- 保持按类型分层：改动成本最低，但页面归属会继续模糊。
- 按原子设计分层（atoms/molecules/organisms）：对本项目过重。

## 失效条件

若某个功能域膨胀为独立子应用，应拆分为单独的包，而不是继续在 `features` 内堆叠。
