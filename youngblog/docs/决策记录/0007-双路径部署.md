# 0007 · 同一份代码支持双 base 部署

- 状态：已采纳

## 背景

站点同时部署在 GitHub Pages 的项目子路径（`/YoungBlog/`）与自建服务器的根路径（`/`）。
若在代码中写死资源路径，二者必有一方 404；若维护两份源码，则会产生分叉。

## 决策

1. `vite.config.js` 通过构建模式切换 `base`：
   - 默认 `/`
   - `--mode github` → `/YoungBlog/`
2. 所有运行时资源请求统一经 `shared/utils/url.js` 的 `resolveUrl`，
   由它拼接 `import.meta.env.BASE_URL`。
3. 资源引用统一使用不带前导斜杠的相对写法（`assets/...`），由 `resolveUrl` 或
   Markdown 资源重写补齐前缀。
4. 路由使用 Hash 模式，避免路径层面的 base 差异。

## 后果

- 同一份代码产出两种产物，部署时只需选择正确的构建命令。
- 新增资源请求时若忘记 `resolveUrl`，只会在子路径部署下暴露，容易漏测。
- `base` 与仓库名绑定；仓库改名必须同步修改配置。

## 备选

- 只用根路径 + 反向代理：GitHub Pages 无法配合。
- 两个分支维护两份源码：不可接受的分叉。

## 失效条件

若迁移到支持自定义域名与根路径的托管平台，可移除 `mode=github` 分支，
但 `resolveUrl` 仍应保留，作为单一入口。
