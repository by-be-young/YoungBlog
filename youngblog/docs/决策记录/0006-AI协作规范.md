# 0006 · 将 AI Agent 协作纳入仓库规范

- 状态：已采纳
- 日期：2026-11-17

## 背景

仓库会由不同的人与 AI 辅助工具共同修改。此前的约束（不能动生成产物、不能移动文章、
`base` 与 Hash 路由的约束、构建命令）只存在于个人经验中，新加入的 Agent 容易误改。
同时，不同工具读取不同的入口文件（`AGENTS.md`、`CLAUDE.md`、Copilot 指令、Cursor 规则），
需要一份**单一事实来源**，避免多份说明逐渐分叉。

## 决策

1. 根目录 `AGENTS.md` 作为唯一事实来源，包含：
   - 仓库事实与命令；
   - 硬性约束（不可改动项）；
   - 目录职责；
   - 任务配方；
   - 交付前检查清单。
2. `CLAUDE.md`、`.github/copilot-instructions.md`、`.cursor/rules/` 只做**摘要 + 指回** `AGENTS.md`，
   不复制完整规则。
3. `docs/智能协作/` 存放上下文地图、任务配方、提示词库与自检清单。
4. 结构与命令变化时，同步更新 `AGENTS.md` 与对应文档。

## 后果

- Agent 的行为可以被审查与版本化。
- 文档维护成本增加，但低于「每次重新解释约束」的成本。
- 需要防止文档与实现漂移：`check-docs` 校验链接，人工审查校验语义。

## 备选

- 只写 README：信息密度不足，Agent 容易漏读关键约束。
- 每个工具维护一份完整规则：必然分叉。

## 失效条件

若引入自动化规则执行（如自定义 lint 规则、CI 约束检查），可逐步把文字约束转为机器校验，
但 `AGENTS.md` 仍保留为人类可读的总览。
