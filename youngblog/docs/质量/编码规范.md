# 编码规范

本规范以「与现有代码一致」为第一原则。新增代码应先找同类实现模仿，再考虑改进。

## 1. 语言与工具

- JavaScript（ESM），不使用 TypeScript。
- Vue 3 单文件组件，统一 `<script setup>`。
- 2 空格缩进、单引号、无分号、行宽 100（Prettier）。
- 提交前 `npm run lint`，不要绕过规则（`eslint-disable` 需说明原因）。

## 2. 命名

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 视图 | PascalCase + `View` | `HomeView.vue` |
| 组件 | PascalCase | `ProfileCard.vue` |
| Composable | `use` + PascalCase，`.js` | `useMarkdown.js` |
| Store | camelCase + `Store` | `blogStore.js` |
| 工具函数 | camelCase | `resolveUrl` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_BACKGROUND_IMAGES` |
| CSS 类 | kebab-case，页面前缀 | `.blog-article`、`.quick-links-grid` |
| i18n 键 | snake_case，模块前缀 | `archive_filter_all` |
| 文章目录 | 中文原名 | `blogs/三上/编译/文法与词法/` |

避免缩写（`btn`、`idx` 仅限局部循环）。布尔变量用 `is` / `has` / `should` 开头。

## 3. 文件与目录

- 功能域：`src/features/<kebab-case>/`，视图在域根，私有组件在 `components/`。
- 跨域组件才进 `src/shared/components/`。
- 一个文件只导出一个主要实体；工具文件可导出多个纯函数。
- 新增目录必须带 `README.md` 说明职责（代码目录同样适用）。

## 4. 导入

```js
// 1. 第三方
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

// 2. 内部别名
import { useBlogStore } from '@/shared/stores/blogStore'
import { resolveUrl } from '@/shared/utils/url'

// 3. 同级相对
import { useMermaid } from './useMermaid'
```

规则：

- 跨目录一律用 `@/`，禁止 `../../..`。
- 同级文件才允许 `./`。
- 不引入未被使用的导入；动态导入需注释说明原因（通常是为了拆包）。

## 5. Vue 组件

顺序固定：`<template>` → `<script setup>` → `<style scoped>`。

```vue
<script setup>
import { ref, computed, onMounted } from 'vue'

const props = defineProps({
  title: { type: String, default: '' },
})
const emit = defineEmits(['navigate'])

const count = ref(0)
const doubled = computed(() => count.value * 2)

onMounted(() => {
  // 副作用集中在这里
})
</script>
```

约定：

- Props 必须声明类型与默认值（对象/数组默认用工厂函数）。
- 事件名用 kebab-case（模板中 `@update-title`）。
- 不在模板中写复杂表达式，抽到 `computed`。
- 不在 `watch` 中做重计算或 DOM 查询；必要时加 `flush: 'post'`。
- 组件卸载时清理定时器、事件监听、observer。

## 6. 组合式函数

- 命名 `useXxx`，返回对象而非位置数组。
- 依赖 Store 时在函数内部获取，不在模块顶层调用（避免 Pinia 未初始化）。
- 不在 composable 中定义全局单例状态；共享状态放 Store。
- DOM 操作类 composable 必须提供 `destroy` / `dispose`，并由调用方在卸载时执行。

## 7. Store

- Setup Store，返回 state / getters / actions。
- 异步 action 必须处理失败：设置 `error`、回退到安全默认值，不让页面崩溃。
- 不做 DOM 操作，不直接读写 `localStorage`（持久化键需登记）。
- 跨 Store 只读依赖，避免循环。

## 8. 工具函数

- 纯函数优先；输入输出写 JSDoc。
- 不吞异常：要么返回明确的失败值，要么向上抛。
- 路径拼接统一走 `resolveUrl`，不要手写 `BASE_URL`。

## 9. 异步与错误

```js
try {
  const res = await fetch(resolveUrl('/data/blogs.json'))
  if (!res.ok) throw new Error(`HTTP ${res.status}`)
  // ...
} catch (e) {
  console.warn('[BlogStore] 加载失败:', e)
  // 回退到空数据，保持页面可用
}
```

- 面向用户的失败要给可读提示；控制台日志统一带模块前缀。
- 不静默忽略错误，除非是明确的「可选资源」（如 `stats.json`）。
- 不用 `alert` / `confirm`，交互统一走站点弹窗。

## 10. 国际化

- 所有用户可见文案走 `i18nStore`。
- 三个语言对象必须同时有键；不使用机器翻译占位。
- 文案中的变量用 `{n}` 形式，由调用方替换。
- 不在模板里硬编码中文（日志、注释除外）。

## 11. 样式

- 组件样式 `scoped`；需要穿透时用 `:deep()` 并写注释。
- 不新增全局选择器；确需全局时放 `src/assets/styles/` 并登记。
- 颜色优先使用变量；新增变量在 `:root` 定义。
- 不使用 `!important` 掩盖层叠问题，除非已有代码就是这么处理的。
- 动画尊重 `prefers-reduced-motion`。

## 12. 注释

- 解释「为什么」，不复述「做了什么」。
- 复杂正则、算法、兼容性处理必须注释。
- 文件头用块注释说明职责、依赖与使用方式（现有代码风格）。
- 中文注释为主；专有名词保留英文。

## 13. 安全

- 不把用户可控内容拼进 HTML；Markdown 渲染结果来自本地内容，但仍避免新增 `innerHTML` 入口。
- 外链统一 `rel="noopener noreferrer"`。
- 不提交密钥、Token、个人隐私数据。
- 新增依赖前评估体积与维护状态，并在 PR 说明理由。

## 14. 提交

遵循 Conventional Commits；一次提交只做一类改动。
重构与功能分开，格式化与逻辑分开。详见 [贡献指南](../../贡献指南.md)。
