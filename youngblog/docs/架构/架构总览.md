# 架构总览

## 1. 设计目标

| 目标 | 落地方式 |
| --- | --- |
| 写作与代码解耦 | 文章是 `blogs/` 下的普通 Markdown，Obsidian 可直接编辑 |
| 纯静态可托管 | 无服务端逻辑；数据以 JSON 随站点分发；Hash 路由 |
| 跨部署路径一致 | 所有资源请求经 `resolveUrl` 拼接 `import.meta.env.BASE_URL` |
| 阅读体验优先 | 入场加载器、背景轮播、沉浸阅读、目录跟随 |
| 可长期维护 | 功能域目录、生成式数据、文档与 ADR 同仓 |

## 2. 非目标

- **不做在线编辑器 / CMS**：写作在本地完成，通过 Git 发布。
- **不做服务端搜索**：搜索在前端对已加载的文章与 Markdown 正文做匹配。
- **不做账号体系**：站点无登录、无用户数据。
- **不承诺浏览器兼容旧版**：以现代 Chromium / Firefox / Safari 为准。

这些非目标决定了「构建时生成 + 运行时只读」的基本形态，避免引入后端与数据库。

## 3. 运行时拓扑

```text
浏览器
 ├─ index.html（preload 首屏图片）
 ├─ Vue App（App.vue 壳）
 │   ├─ EntrySplash（预载字体/数据/图片，权重进度）
 │   ├─ AppNavbar / AppFooter / FloatingControls
 │   ├─ router-view → features/<view>
 │   └─ 全局弹窗：SearchPanel / SettingsModal / AnnouncementModal
 ├─ Pinia Stores（blog / i18n / settings / music / background）
 └─ fetch
     ├─ /data/blogs.json        （构建生成）
     ├─ /data/series.json       （构建生成，入场预取）
     ├─ /data/announcements.json（人工维护，支持 CLI 追加）
     ├─ /data/quick-links.json  （人工维护）
     ├─ /data/about.<lang>.md   （人工维护）
     ├─ /data/background-images.json（构建生成，当前为空 → 回退默认图）
     └─ /blogs/**/*.md          （原始文章，构建后复制到 dist/blogs）
```

## 4. 技术选型理由

| 选型 | 理由 | 代价 |
| --- | --- | --- |
| Vue 3 + `<script setup>` | 单文件组件、组合式 API 与现有代码风格一致 | 无类型约束，需靠约定与 lint |
| Vite | 开发启动快、按需动态导入天然支持 | 大依赖（Mermaid/KaTeX）需显式分包 |
| Pinia Setup Store | 与组合式函数写法一致，便于在 composable 中复用 | Store 间依赖需人工约束 |
| marked + 自定义预处理 | 可插入 Obsidian 双链、习题块等站点特有语法 | 需自行保证 HTML 安全边界 |
| 原生 CSS | 视觉定制自由度高，无框架覆盖成本 | 全局样式需人工防冲突 |

## 5. 架构不变量

修改代码时，以下性质必须保持：

1. **`contentFile` 是文章身份的一部分**：它既是详情页的 fetch 路径，也是 `generate.js` 生成稳定 ID 的输入。移动 `blogs/` 下的文章会改变 ID 与旧链接。
2. **`blogs/` 的目录层级即标签**：前 3 层目录会写进 `tags`，首层还决定首页分类。
3. **`public/data/blogs.json` 是生成产物**：手工修改会在下一次 `npm run build` 时被覆盖。
4. **`dist/blogs/` 必须存在**：`postbuild.js` 负责复制；部署时漏掉会导致详情页 404。
5. **资源请求必须经过 `resolveUrl`**：否则子路径部署会 404。
6. **Hash 路由不可随意换成 History**：静态托管没有 404 回退就无法工作。
7. **入场加载屏的预载清单要与 `index.html` 的 preload 保持一致**：两者不一致会造成加载阶段抖动。

## 6. 分层与依赖规则

```text
app  →  features  →  shared  →  （无内部依赖）
```

- `features/*` 之间**不得**互相导入视图；确需复用请下沉到 `shared`。
- `shared` 不得导入 `features`。
- `shared/utils` 只放纯函数，不得访问 Store 或 DOM 全局状态。
- `shared/stores` 可以依赖 `shared/utils` 与 `shared/composables`，反向依赖禁止。

当前唯一允许的跨域引用是 `features/about` 复用 `features/blog-detail/components/BlogContent.vue`，
因为它需要与详情页完全一致的 Markdown 渲染结果。若未来出现第三处复用，应将其上移到 `shared`。
