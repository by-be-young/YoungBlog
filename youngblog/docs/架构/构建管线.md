# 构建管线

## 1. 命令与阶段

| 命令 | 阶段 |
| --- | --- |
| `npm run dev` | 仅 Vite 开发服务器，不生成数据（使用现有 `public/data/*.json`） |
| `npm run build` | `generate.js` → `vite build` → `postbuild.js` |
| `npm run build:github` | 同上，但 `vite build --mode github`（`base=/YoungBlog/`） |
| `npm run preview` | Vite 预览 `dist/`（不带 `blogs/` 之外的仓库文件） |
| `node scripts/preview-server.mjs` | 同时服务 `dist/` 与仓库根目录，可访问 `blogs/*.md` |

## 2. `scripts/generate.js`

输入：`blogs/**/*.md`（跳过名为 `模板` 的目录）。

输出：

| 文件 | 内容 |
| --- | --- |
| `public/data/blogs.json` | 全量文章索引，按日期倒序 |
| `public/data/series.json` | 系列聚合与章节排序 |
| `public/data/announcements.json` | 仅在带命令行参数时追加 |
| `public/data/background-images.json` | 背景图清单（当前为空，见 known-quirks） |

关键行为：

- 日期优先取 frontmatter；缺失时读取**上一次** `blogs.json` 中同 `contentFile` 的日期；
  再缺失才用文件 mtime。这样重新构建不会让旧文章「变新」。
- ID 由 `contentFile` 的 FNV-1a 哈希生成，因此**移动文章会换 ID**。
- 摘要优先 frontmatter，否则取正文第一段有效行并截断 80 字符。
- 构建过程不做 Markdown 渲染，只做元数据与摘要，速度与文章总量线性相关。

## 3. `vite build`

`vite.config.js` 要点：

| 配置 | 值 | 影响 |
| --- | --- | --- |
| `base` | `/`，`mode=github` 时 `/YoungBlog/` | 决定所有资源与数据 URL 前缀 |
| `resolve.alias['@']` | `./src` | 源码统一用 `@/` 导入 |
| `server.port` | `5173` | 开发端口 |
| `server.open` | `true` | 启动自动打开浏览器 |
| `build.outDir` | `dist` | 产物目录（git 忽略） |
| `manualChunks` | vue / vue-router / pinia → `vendor` | 基础框架单独分包 |

大依赖（`marked`、`katex`、`mermaid`、`highlight.js`）通过动态 `import()` 按需加载，
因此构建日志会出现大量 Mermaid 子包；这是预期现象，不是重复打包。

构建结束可能出现「chunk 大于 500 kB」提示，来源于 Mermaid 的子图实现。
只要首屏 `index-*.js` 与 `vendor-*.js` 未显著增长，可忽略。

## 4. `scripts/postbuild.js`

把仓库根目录的 `blogs/` 递归复制到 `dist/blogs/`。
原因：Vite 只拷贝 `public/`，而文章源在根目录，运行时详情页与搜索需要按
`blogs/...` 路径 fetch。缺这一步会导致详情页 404。

复制包含 `.obsidian` 配置与模板目录，这属于既有行为；不影响站点运行。

## 5. 产物结构

```text
dist/
├── index.html
├── favicon.ico
├── assets/            # JS / CSS / 图片 / 音乐
├── data/              # blogs.json、series.json、announcements.json 等
└── blogs/             # 文章原文（postbuild 复制）
```

部署时必须整体上传 `dist/`，不能只传 `assets/` 与 `index.html`。

## 6. 本地预览的两种方式

| 方式 | 覆盖范围 | 适用 |
| --- | --- | --- |
| `npm run preview` | Vite 预览 `dist/`，`blogs/` 已在 dist 内 | 快速验收构建产物 |
| `node scripts/preview-server.mjs` | `dist/` + 仓库根目录回退 | 验证源码资源、模板或未构建内容 |

后者支持 `--port`、`--root`、`--dist`，用于验证脚本对临时产物目录做断言。

## 7. 图片流水线

| 脚本 | 输入 | 输出 | 备注 |
| --- | --- | --- | --- |
| `optimize-images.mjs` | `public/` 原图 | 同名 `.webp` | 按显示尺寸上限缩放；保留原图回退 |
| `compare-image-quality.mjs` | 原图 / WebP 配对 | PSNR / MAE / MaxDiff | ≥40 dB 视为视觉无损 |
| `image-info.mjs` | 文件参数 | 尺寸 | 仅解析文件头，无第三方依赖 |

新增图片时需在 `optimize-images.mjs` 的 `MANIFEST` 中登记，否则不会生成 WebP。

## 8. 验证脚本

`scripts/verify-detail-mobile.mjs` 会复制 `dist` 到临时目录、注入探针、用
`--dump-dom` 在多个视口下读取真实几何并断言。依赖本机可用的 Chromium 系浏览器，
属于本地验证工具，不参与 CI 构建。

## 9. CI

`.github/workflows/ci.yml` 在 push / PR 时执行：

1. `npm ci`
2. `npm run lint`（失败不阻断，先暴露存量问题）
3. `npm run build`
4. `node scripts/check-docs.mjs` 校验文档相对链接

`deploy-pages.yml` 默认手动触发，避免与仓库现有的 Pages 配置冲突；
确认 Pages 源为「GitHub Actions」后可改为 push 自动部署。

## 10. 构建失败排查

| 现象 | 常见原因 |
| --- | --- |
| `Cannot find module '@/...'` | 文件移动后未更新导入，或别名失效 |
| `generate.js` 报 frontmatter 解析错误 | 文章开头 `---` 未闭合 |
| `postbuild` 警告找不到 `blogs/` | 工作目录不是仓库根 |
| 产物页面空白 | `base` 与部署路径不匹配 |
| 字体 / 图片 404 | 被误移到 `src/` 或使用了绝对文件路径 |
