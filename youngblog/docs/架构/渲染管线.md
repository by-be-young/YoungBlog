# 渲染管线

Markdown 渲染集中在 `src/shared/composables/useMarkdown.js`。它先做文本级预处理，
再用 `marked` 解析，最后在临时 DOM 上做后处理，把 HTML 字符串交给 `BlogContent`。
`BlogContent` 在**真实 DOM**上绑定事件，避免序列化时丢失监听器。

## 1. 处理顺序

| # | 阶段 | 作用 | 位置 |
| --- | --- | --- | --- |
| 1 | 剥离 frontmatter | 去掉开头 `--- ... ---` | `stripFrontMatter` |
| 2 | Obsidian 图片嵌入 | `![[img.png]]` → `![alt](path)` | `transformObsidianImageEmbeds` |
| 3 | 有序列表缩进规范化 | 1–3 空格的 `1.` 提升到顶格 | `normalizeOrderedListIndentation` |
| 4 | 自定义块预处理 | question / options / task / answer / analysis | `processCustomBlocks` |
| 5 | `marked.parse` | GFM 解析 | 动态导入 `marked` |
| 6 | 数学公式 | `$...$` / `$$...$$` → KaTeX | 按需动态导入 `katex` |
| 7 | 资源 URL 重写 | 相对图片路径按 `contentFile` 所在目录解析 | `rewriteMarkdownAssetUrls` |
| 8 | 标题锚点与内部引用 | 生成标题 ID，解析 `[[#标题]]` | `assignHeadingIdsAndLinkifyRefs` |
| 9 | 代码高亮 | highlight.js `highlightElement` | `shared/utils/highlight.js` |
| 10 | 视觉微调 | 列表标记马卡龙色、引用块首段居中 | 渲染末尾 |

## 2. 自定义块

站点在标准 Markdown 之外支持一组方括号块。**当前实现的结束标记使用反斜杠**
（`[\task]`），而不是常见的 `[/task]`；这是历史实现，修改前需评估已有内容兼容性。

```markdown
[task]
题干内容，可用 Markdown。
[question]可选的问题说明[\question]
[options]
A. 选项一
B. 选项二
[\options]
[answer]B[\answer]
[analysis]解析文字，可用公式 $x^2$。[\analysis]
[\task]
```

- `[options]` 的每一行可带显式字母（`A.` / `B)` / `C：`），也可省略，省略时按行自动标 A/B/C。
- `[answer]` 支持写 `A`、`A,B`、`答案：A` 或 `结论：A`；仅一个字母为单选，多字母为多选，
  提交后由 `useAnswer` 判定并锁定选项。
- `[analysis]` 与相邻 `[answer]` 合并进入同一个答案面板。
- `[task]` 渲染为 `.md-task`，受「习题显示模式」设置控制（隐藏 / 折叠 / 练习 / 展开）。

## 3. 数学公式

- 行内：`$...$`
- 块级：`$$...$$`

渲染前会先把公式替换为占位符，避免 `marked` 把下划线、星号当作强调语法。
只有存在公式时才动态加载 KaTeX。

## 4. 图片与资源路径

```markdown
![[图片1.png]]                 → /blogs/图片/图片1.png（裸文件名默认前缀）
![[图1.png|说明文字]]           → 带 alt
![](./images/a.png)            → 相对当前 Markdown 文件目录
![](assets/images/a.webp)      → 相对站点根
![](https://example.com/a.png) → 原样保留
```

`rewriteMarkdownAssetUrls` 会区分「站点根」与「文章目录」两种基准，
并在子路径部署时补上 `BASE_URL` 前缀。新增图片时优先使用仓库内相对路径，
避免外链失效。

## 5. 内部引用

`[[#标题]]` 会链接到当前文章内对应标题。标题 ID 由 `assignHeadingIdsAndLinkifyRefs`
统一生成；重复标题会追加序号。该语法只用于**文内跳转**，不支持跨文章双链。

## 6. 真实 DOM 上的增强

`BlogContent` 拿到 HTML 后依次执行：

| 增强 | 组合式函数 | 说明 |
| --- | --- | --- |
| 代码块 | `useCodeBlock` | 行号、复制、折叠 / 展开、Mermaid 全屏 |
| Mermaid | `useMermaid` | 动态加载与渲染，失败时保留源码 |
| 图片查看器 | `useImageViewer` | 缩放、拖拽、切换、下载、复制 |
| 答案交互 | `useAnswer` | 选项点击、提交、对错反馈、统计 |
| 任务清单 | `useChecklist` | 可勾选复选框、进度条、`localStorage` 持久化 |
| 目录 | `useToc` | 标题层级、滚动高亮、自动居中 |
| 显示设置 | `useSettings` | 将 Store 中的模式应用到文章 DOM |

这些处理都依赖真实节点，因此不能在 `renderMarkdown` 里完成；
若把逻辑移进字符串阶段，事件将全部失效。

## 7. 导出与展示

- `ExportModal` 以原始 Markdown 为输入，导出前会清理站点私有标记。
- `DisplayModal` 控制字号、行距、背景等阅读参数。
- 沉浸模式由 `settingsStore.isImmersive` 驱动，切换时同步 `wide-mode` 类。

## 8. 修改渲染逻辑的检查项

1. 新语法必须同时支持代码块内的**字面量**（不能被误处理）。
2. 公式占位符必须在所有文本变换中保持可识别。
3. 新语法若产生 DOM 结构，需在 `BlogContent` 中补充增强与清理逻辑。
4. 更新 [Markdown 扩展参考](../参考/扩展语法参考.md)。
5. 用一篇含公式、图表、代码、图片、任务清单的文章做回归。
