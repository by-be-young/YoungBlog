# 数据流

本文描述「一篇 Markdown 如何变成页面」，以及每一步的输入、输出与失败点。

## 1. 内容生产阶段（构建时）

```text
blogs/<学年>/<主题>/<小节>/<文章>.md
        │
        ▼  scripts/generate.js
        ├─ gray-matter 解析 frontmatter
        ├─ 从目录层级派生 tags（前 3 层）
        ├─ 由首层标签判定首页分类（学习 / 娱乐）
        ├─ 计算摘要、日期、系列、章节、排序
        ├─ 生成稳定 ID（FNV-1a，或 frontmatter.id）
        ▼
public/data/blogs.json
public/data/series.json
        │
        ▼  vite build（public/ 原样拷贝）
dist/data/*.json
dist/blogs/**/*.md   ← postbuild.js 复制
```

### 1.1 `generate.js` 的字段规则

| 字段 | 来源 | 规则 |
| --- | --- | --- |
| `title` | frontmatter `title` | 缺失时用文件名（不含扩展名） |
| `date` | frontmatter `date` → 旧清单中的同路径记录 → 文件 mtime | 统一格式化为 `YYYY-MM-DD`；保留旧日期以避免构建间漂移 |
| `excerpt` | frontmatter `excerpt` | 缺失时取正文第一段有效文本，截断 80 字符并加 `...` |
| `tags` | 相对 `blogs/` 的目录层级 | 取前 3 层；单篇文章的标签即「学年 / 主题 / 小节」 |
| `category` | `tags[0]` | 命中 `二上/二下/三上/三下/四上/四下/大三` 为「学习」，否则「娱乐」 |
| `series` | frontmatter `series` | 支持字符串、数组（取首个有效值）或对象（`title`/`name`） |
| `order` | frontmatter `order` | 数字或数字字符串，取整；非法值记 `null` |
| `chapter` | frontmatter `chapter` | 原样保留，`1 - 标题` 形式会被解析出序号 |
| `type` | frontmatter `type` | 可为空 |
| `recommended` | `recommended` 或 `推荐` | 布尔化 |
| `id` | frontmatter `id` 或路径哈希 | FNV-1a 32 位；重复时 `+1` 直至唯一 |
| `contentFile` | 相对仓库根的路径 | 形如 `blogs/三上/编译/...md`，运行时据此 fetch |
| `lastEditedDate` | 文件 mtime 与上次构建时间比较 | 仅当本次构建检测到修改时写入 |

### 1.2 系列聚合

`series.json` 按 `series` 名称分组，每组输出：

```json
{
  "id": 123456789,
  "title": "操作系统",
  "coverImage": "assets/images/background/bg2.webp",
  "count": 12,
  "posts": [
    { "id": 1, "title": "概述", "date": "2026-01-01", "order": null, "chapter": "1 - 引言", "contentFile": "blogs/..." }
  ]
}
```

组内排序优先级：有 `chapter` > 无 `chapter`；`chapter` 序号升序；同序号按标题 `zh-CN` 排序；
无章节时按 `order` 升序，最后按日期倒序。系列之间按文章数降序、再按标题排序。

### 1.3 公告追加

`scripts/generate.js "公告正文"` 会把参数拼接为一条公告，插入
`public/data/announcements.json` 头部，日期取运行当天。

### 1.4 背景图清单

`generate.js` 扫描的是**仓库根目录**的 `assets/images/background`。当前仓库不存在该目录，
因此 `public/data/background-images.json` 恒为 `{"images": []}`，前端会回退到
`DEFAULT_BACKGROUND_IMAGES`（`bg1.webp` / `bg2.webp` / `bg3.webp`）。
这是既有行为，详见 [known-quirks](../运维/已知行为与陷阱.md)。

## 2. 应用启动阶段（运行时）

```text
index.html
  └─ /src/main.js
       ├─ 注册 Pinia / Router
       ├─ 给 <html> 加 entry-loading（无 reduced-motion 时）
       └─ mount(App)

App.vue
  ├─ EntrySplash 预载：渲染引擎 → 字体 → 数据 → 图像 → 首页视图 → 收尾
  ├─ fetch /data/background-images.json → build 背景轮播
  ├─ 首次点击/按键初始化音频（浏览器自动播放策略）
  └─ 监听路由名，切换 body.home 与背景蒙版样式
```

入场加载器的阶段权重总和为 100，进度用 `requestAnimationFrame` 缓动插值，
因此进度条单调爬升。任一图片加载失败会走 fallback，不会卡死门帘。

## 3. 页面数据阶段

### 3.1 列表类页面

```text
features/home | archive | categories | series | about | footer
        │
        ▼
blogStore.fetchBlogs()  →  GET /data/blogs.json（只请求一次，已加载则跳过）
        │
        ├─ totalPosts / tags / seriesList / recommendedBlogs / latestBlogs
        └─ getCategoryKey / getRecentUpdates
```

- `home`：欢迎区、资料卡、推荐、最近更新、按分类分组的卡片。
- `archive`：按年月聚合，支持「学习 / 全部 / 娱乐」筛选。
- `categories`：领域 / 科目 / 主题三级筛选，云图交互。
- `series`：由 `useSeries` 从 `blogStore.blogs` 派生系列与章节。
- `about`：额外 fetch `/data/about.<lang>.md`，按语言回退。
- `AppFooter`：可选 fetch `stats.json`（仅服务器部署存在），并统计全站字数。

### 3.2 详情页

```text
/blog/:id
  → blogStore.getBlogById(id)
  → fetch(resolveUrl(blog.contentFile))     // 原始 Markdown
  → useMarkdown.renderMarkdown(text, contentFile)
  → BlogContent 在真实 DOM 上做增强：
     代码块 / Mermaid / 图片查看器 / 答案交互 / 任务清单 / 目录
```

`SearchPanel` 在开启「搜索正文」时也会 fetch 每篇文章的 `contentFile`，因此
**部署时 `dist/blogs/` 必须存在**；否则搜索退化为仅匹配标题与摘要。

## 4. 失败模式与表现

| 失败点 | 表现 | 定位方式 |
| --- | --- | --- |
| `blogs.json` 缺失或格式错误 | 首页空列表，控制台 `[BlogStore] 加载失败` | 检查 `public/data/blogs.json` |
| `contentFile` 404 | 详情页正文空 / 提示加载失败 | 检查 `dist/blogs/` 是否随构建复制 |
| `base` 配置错误 | 资源与数据全部 404，页面空白 | 检查 `vite.config.js` 的 `mode` 与 `BASE_URL` |
| 背景清单为空 | 正常，回退三张默认图 | 属预期行为 |
| `stats.json` 404 | 页脚不显示访问量 | 属预期行为（Pages 部署无此文件） |
