# 任务配方

每个配方包含：目标、前置阅读、步骤、验证。命令均在仓库根目录执行。

## 配方 A：修改现有页面的 UI

**目标**：调整布局、样式或交互，不改变数据与路由。

1. 读 `docs/架构/样式与主题.md` 与目标视图。
2. 只改目标视图的 `<style scoped>` 或对应组件；不新增全局选择器。
3. 若涉及文案，补齐 `zh` / `en` / `ja`。
4. 验证：

```bash
npm run lint
npm run build
```

5. 在 1280 / 900 / 480 三档宽度检查；移动端跑一次详情页。
6. 若改变了背景蒙版或页面级类名，检查 `App.vue`。

**不要**：顺手格式化整个文件；改 `main.js` 的 CSS 顺序。

## 配方 B：新增页面

按 `docs/指南/新增页面或功能.md` 执行。最小步骤：

1. 建 `src/features/<name>/<Name>View.vue` 与 `README.md`。
2. 在 `src/router/index.js` 添加路由（相对路径 + `meta.title`）。
3. 在 `i18nStore` 补三语文案。
4. 如需导航，更新 `AppNavbar.vue` 的菜单数组。
5. 更新 `docs/架构/模块地图.md`。
6. 验证构建与直接访问 / 刷新。

## 配方 C：修改 Markdown 渲染

1. 读 `useMarkdown.js` 的预处理与后处理两段，确认改动作用于**字符串阶段**还是 **DOM 阶段**。
2. 新语法必须：
   - 不影响代码块内文本；
   - 与公式占位符兼容；
   - 在 `BlogContent` 中有对应的增强（如需要交互）。
3. 用一篇包含以下内容的文章回归：标题、列表、代码、公式、Mermaid、图片、任务清单、习题块。
4. 更新 `docs/参考/扩展语法参考.md`。
5. 验证：

```bash
npm run build
node scripts/preview-server.mjs --port 4180
```

**不要**：把事件绑定写进 HTML 字符串；在 `v-html` 上依赖内联 `onclick`。

## 配方 D：内容更新

1. 从 `blogs/模板/文章模板.md` 复制，放到正确的三层目录。
2. 填 frontmatter（`title` / `date` / 可选 `series` / `chapter`）。
3. 生成索引：

```bash
node scripts/generate.js
```

4. 检查 `git diff public/data/blogs.json`：只应出现目标文章。
5. `npm run dev` 预览；详情页能打开、目录正确。
6. 提交时把 Markdown 与生成的 JSON 一起提交。

**不要**：在 `blogs/` 根放临时 `.md`；手工编辑 JSON。

## 配方 E：图片优化

1. 把图片放入 `public/assets/...`。
2. 在 `scripts/optimize-images.mjs` 的 `MANIFEST` 登记。
3. 运行：

```bash
npm run optimize:images
npm run check:images
```

4. 首屏图同步 `index.html` 的 preload（若新增）与 `useEntryLoader` 清单。
5. 更新 `docs/指南/图片与媒体.md`（若新增目录约定）。

## 配方 F：排查子路径 404

1. 确认构建命令：GitHub Pages 必须 `npm run build:github`。
2. 检查 `vite.config.js` 的 base 是否与仓库名一致。
3. 检查报错 URL：缺少 `/YoungBlog/` 前缀 → 该请求未走 `resolveUrl`。
4. 全文搜索 `fetch(` 与 `src=`，确认没有硬编码绝对路径。
5. 用 `node scripts/preview-server.mjs` 复现，排除宿主因素。
6. 修完后记录到 `docs/运维/故障排查.md`（若属新类型）。

## 配方 G：重构（目录 / 文件移动）

1. 先列出移动清单与影响文件（`Grep` 导入）。
2. 用 `git mv` 保留历史。
3. 批量替换导入后，**必须** `npm run build` 验证。
4. 检查：
   - `Grep` 是否还有旧路径；
   - 动态导入（`import('...')`）是否遗漏；
   - CSS 相对路径（`url(...)`）是否仍然有效。
5. 更新 `docs/架构/模块地图.md` 与 `AGENTS.md` 的目录说明。
6. 若改变分层规则，补 ADR。

## 配方 H：写文档

1. 查 `docs/文档索引.md`，确认是否已有同主题文档。
2. 使用中文文件名与相对链接。
3. 运行 `node scripts/check-docs.mjs`。
4. 在索引中登记新文档。

## 通用收尾

```bash
npm run lint
npm run build
node scripts/check-docs.mjs
git status --short
```

确认 diff 只包含预期文件；在最终回复中列出未验证项。
