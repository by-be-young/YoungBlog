# 提示词库

以下提示词可直接复制给 Agent。方括号内为需要替换的内容。
共同前提：Agent 已阅读 `AGENTS.md` 与「上下文地图」中对应任务的必读文件。

## 1. 定位问题

```text
在 YoungBlog 仓库中定位以下问题：[现象]。
要求：
1. 先给出你读过的文件与判断依据；
2. 列出最可能的 3 个原因并按可能性排序；
3. 对每个原因给出验证命令或检查步骤；
4. 先不要改代码，等我确认方向。
```

## 2. 修复 Bug

```text
修复 [页面/组件] 的 [现象]。
约束：不改变其他页面行为，不引入新依赖。
步骤：复现 → 定位 → 最小修改 → npm run build 验证 → 说明未覆盖的场景。
```

## 3. 新增页面

```text
按 docs/指南/新增页面或功能.md 新增「[页面名]」页面，路由 /[path]。
要求：三语文案、响应式、README、路由 meta.title，并更新模块地图。
完成后运行 lint 与 build，列出改动文件。
```

## 4. 修改 UI

```text
调整 [页面] 的 [区域]：[期望效果]。
只改 scoped 样式与必要的模板结构；不要新增全局 CSS。
完成后说明在 1440/900/480 三档宽度下的表现。
```

## 5. 重构

```text
将 [模块/目录] 重构为 [目标结构]，不改变运行时行为。
要求：
1. 先给出文件移动清单与导入影响面；
2. 用 git mv；
3. 改完后 npm run build 必须通过；
4. 更新 docs/架构/模块地图.md；
5. 不顺手改格式化与无关文件。
```

## 6. 写文档

```text
为 [主题] 写一篇文档，放入 docs/[分册]/，中文文件名。
要求：包含适用读者、步骤/表格、验证命令、相关文档链接，并登记到 docs/文档索引.md。
不要重复其他文档的大段内容。
```

## 7. 代码审查

```text
以 docs/质量/代码审查清单.md 为基准，审查当前改动（git diff）。
输出：阻塞问题、建议改进、可忽略项；每条给出文件与行号。
不要直接修改代码。
```

## 8. 性能排查

```text
分析 [页面] 的首屏性能：列出关键请求、体积、可能的阻塞点。
基于 docs/运维/性能说明.md 的预算给出结论。
不要为了分数牺牲现有视觉；给出可验证的优化方案与风险。
```

## 9. 内容检查

```text
检查 [文章路径] 的 frontmatter 与目录层级是否符合 docs/参考/文章元数据参考.md。
指出：字段缺失、日期格式、系列/章节排序、图片路径、是否会被误分类。
不要移动文件。
```

## 10. 发布前检查

```text
按 docs/指南/发布检查清单.md 审查当前工作区。
逐项给出「通过 / 未通过 / 不适用」与依据；未运行的检查必须标注。
```

## 11. 解释代码

```text
解释 [文件] 中 [函数/流程] 的作用与调用链，面向新加入的维护者。
引用具体行号；指出它依赖的 Store / composable 与可能的副作用。
```

## 12. 约束冲突

```text
我的需求是 [需求]，但它可能与 [约束/文档] 冲突。
请先指出冲突点与影响，再给 2 个可行方案（含代价），不要直接实施。
```
