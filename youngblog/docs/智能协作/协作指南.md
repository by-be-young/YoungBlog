# AI 协作指南

本分册面向在仓库中工作的 AI Agent（以及使用 Agent 的人）。目标：让 Agent 在不破坏
站点行为的前提下，快速定位上下文、执行改动并给出可验证的交付。

## 1. 文档层级

| 文件 | 角色 | 读者 |
| --- | --- | --- |
| [AGENTS.md](../../AGENTS.md) | **唯一事实来源**：事实、约束、配方、验收 | 所有 Agent |
| [CLAUDE.md](../../CLAUDE.md) | Claude 入口摘要，指回 `AGENTS.md` | Claude |
| [.github/copilot-instructions.md](../../.github/copilot-instructions.md) | Copilot 摘要 | Copilot |
| [.cursor/rules/youngblog.mdc](../../.cursor/rules/youngblog.mdc) | Cursor 规则 | Cursor |
| 本分册 | 详细上下文地图、配方、提示词 | 需要深入任务的 Agent |

规则：**入口文件只做摘要，不复制完整规则**，避免多份说明分叉。

## 2. 工作原则

1. **先读后改**：先读 `AGENTS.md` 与「上下文地图」中列出的文件，再动手。
2. **最小改动**：只改任务需要的文件，不顺手重构、不批量格式化。
3. **保持行为**：视觉、路由、数据格式、构建产物属于契约，改动必须有明确理由。
4. **可验证**：每个结论都要有对应的命令或检查，不凭推测宣布完成。
5. **写下来**：结构性变化同步文档与 ADR；新发现写入「已知行为与陷阱」。

## 3. 禁止清单（摘要）

- 不手工编辑 `public/data/blogs.json` / `series.json`（生成产物）。
- 不移动/重命名 `blogs/` 下已发布文章（会换 ID、断链）。
- 不修改 `dist/`、`node_modules/`。
- 不把 Hash 路由改为 History 路由。
- 不绕过 `resolveUrl` 拼资源路径。
- 不引入会改变首屏体积的新依赖而不说明。
- 不在 `blogs/` 根目录创建 `.md`（会被当文章收录）。

完整清单见 [AGENTS.md](../../AGENTS.md)。

## 4. 推荐工作循环

```text
定位 → 读上下文 → 制定最小方案 → 实施 → 静态检查 → 构建 → 抽查 → 汇报
```

- 定位：用任务类型查 [上下文地图](上下文地图.md)。
- 静态检查：`npm run lint`（会 `--fix`，注意 diff）。
- 构建：`npm run build`（会重建 `public/data`，检查 diff）。
- 抽查：至少首页 + 一篇文章；涉及路径时跑 `build:github`。
- 汇报：给出改动文件、验证命令与未验证项。

## 5. 不确定时怎么办

| 情况 | 建议 |
| --- | --- |
| 不知道某个文件是否共享 | 按「两个及以上功能域使用」判断；不确定就先留在功能域 |
| 不确定是否改变视觉 | 对比改动前后的 DOM / 截图，或把视觉改动拆成独立提交 |
| 不确定数据结构 | 读 `docs/参考/数据结构参考.md` 与 `generate.js`，不要猜 |
| 不确定是否要新依赖 | 优先用现有依赖；确需新增时说明体积与替代方案 |
| 需求与既有约束冲突 | 先记录冲突点，提出方案，不要擅自破例 |

## 6. 交付格式

Agent 的最终回复应包含：

1. 做了什么（按文件/模块）。
2. 为什么这样做（若涉及取舍）。
3. 验证了什么（命令与结果）。
4. 没验证什么（明确列出）。
5. 后续建议（如有）。

不要只说「已完成」，也不要把未运行的检查说成已通过。
