# 数据 Schema

`public/data/` 下的文件分两类：**构建生成**与**人工维护**。
生成文件不要手工修改，下一次 `npm run build` 会覆盖。

| 文件 | 来源 | 用途 |
| --- | --- | --- |
| `blogs.json` | 生成 | 全量文章索引 |
| `series.json` | 生成 | 系列聚合（入场预取，页面主要用 `useSeries` 派生） |
| `announcements.json` | 人工 / CLI | 公告 |
| `quick-links.json` | 人工 | 快捷链接与友链 |
| `about.zh.md` / `about.en.md` / `about.ja.md` | 人工 | 关于页正文 |
| `background-images.json` | 生成 | 背景轮播清单（当前为空） |
| `articles.json` | 历史快照 | 未被代码引用，保留作参考 |
| `stats.json` | 服务器生成 | 页脚访问量（不存在时静默隐藏） |

## 1. `blogs.json`

数组，按 `date` 倒序。单个元素：

```json
{
  "id": 1727027237,
  "title": "编译实验-词法分析",
  "excerpt": "2421编译实验作业——词法分析实验心得",
  "date": "2026-10-01",
  "image": "assets/images/blog_bg.webp",
  "tags": ["三上", "编译", "文法与词法"],
  "category": "学习",
  "type": "系统笔记",
  "series": "编译原理",
  "order": 2,
  "chapter": "2-实验",
  "contentFile": "blogs/三上/编译/文法与词法/编译实验-词法分析.md",
  "recommended": true
}
```

| 字段 | 类型 | 可能为 null | 说明 |
| --- | --- | --- | --- |
| `id` | number | 否 | 32 位无符号整数，路由 `/blog/:id` |
| `title` | string | 否 | 文章标题 |
| `excerpt` | string | 否 | 摘要，可能为空字符串 |
| `date` | string | 否 | `YYYY-MM-DD` |
| `image` | string | 否 | 固定为 `assets/images/blog_bg.webp` |
| `tags` | string[] | 否 | 目录前 3 层，可能少于 3 项 |
| `category` | `"学习"` \| `"娱乐"` | 否 | 首页分类 |
| `type` | string | 是 | 自定义类型 |
| `series` | string | 是 | 系列名 |
| `order` | number | 是 | 系列排序 |
| `chapter` | string | 是 | 章节原文 |
| `contentFile` | string | 否 | 相对仓库根，运行时 fetch |
| `recommended` | boolean | 否 | 是否推荐 |
| `lastEditedDate` | string | 是 | 仅检测到文件修改时出现 |

## 2. `series.json`

```json
[
  {
    "id": 1234567890,
    "title": "编译原理",
    "coverImage": "assets/images/background/bg2.webp",
    "count": 12,
    "posts": [
      {
        "id": 1727027237,
        "title": "编译实验-词法分析",
        "date": "2026-10-01",
        "order": 2,
        "chapter": "2-实验",
        "contentFile": "blogs/三上/编译/文法与词法/编译实验-词法分析.md"
      }
    ]
  }
]
```

- 系列之间按 `count` 降序，再按标题 `zh-CN` 排序。
- `posts` 的排序规则见 [data-flow](../架构/数据流.md)。

## 3. `announcements.json`

```json
[
  {
    "id": 1788969600000,
    "date": "2026-09-10",
    "message": "「制作者通讯·4.1」……\n\n更新内容>>\n……"
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `id` | 毫秒时间戳，同时作为列表 key |
| `date` | `YYYY-MM-DD` |
| `message` | 纯文本，`\n` 表示换行；由弹窗与公告页渲染 |

追加方式：

```bash
node scripts/generate.js "公告正文"
```

## 4. `quick-links.json`

```json
{
  "categories": [
    {
      "key": "friends",
      "label": "友链",
      "items": [
        {
          "title": "Connor大佬",
          "url": "https://connorz.site/",
          "image": "assets/images/快速链接/connor.webp"
        }
      ]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `categories[].key` | 分类标识，页面用于状态同步 |
| `categories[].label` | 展示名 |
| `categories[].items[]` | 链接条目 |
| `items[].title` | 卡片标题 |
| `items[].url` | 外部链接，会以 `noopener` 打开 |
| `items[].image` | 相对站点根的资源路径 |

现有分类：`friends`、`Beihang`、`personal`、`Study`、`fun`、`ai`。

## 5. `about.<lang>.md`

纯 Markdown，无 frontmatter。加载顺序：

```text
/data/about.<lang>.md
/data/about.<lang>.markdown
/data/about.md.<lang>
/data/about.md
```

因此缺某语言时不会报错，会回退到中文版本。

## 6. `background-images.json`

```json
{ "images": ["assets/images/background/bg1.png", "..."] }
```

- `resolveBackgroundImages` 在数组为空时回退
  `DEFAULT_BACKGROUND_IMAGES`（`bg1.png` / `bg2.webp` / `bg3.webp`）。
- 当前生成器扫描的目录不存在，文件恒为空数组，这是既有行为。

## 7. `stats.json`（可选）

```json
{ "site_pv": 12345 }
```

由服务器从访问日志生成，站点每 5 分钟读取一次（`cache: no-store`）。
不存在或字段缺失时页脚不显示访问量。

## 8. `articles.json`（历史）

与 `blogs.json` 同结构的旧快照，当前代码未引用。保留原因是便于对比历史数据；
不要把它当作数据源，也不要让它与 `blogs.json` 混用。

## 9. 新增数据文件的约定

1. 放 `public/data/`，使用 UTF-8 无 BOM。
2. 在本文档登记 schema 与消费方。
3. 首屏需要的文件加入 `useEntryLoader` 的预取列表。
4. 路径统一相对站点根（不带前导 `/`），运行时用 `resolveUrl` 拼接。
