# 脚本参考

所有脚本位于 `scripts/`，使用 Node ESM（`.mjs` 或 `type: module` 下的 `.js`）。
除特别说明外，均在**仓库根目录**执行。

## 1. `generate.js`

```bash
node scripts/generate.js                 # 只生成数据
node scripts/generate.js "公告正文"       # 生成数据并追加一条公告
```

- 输入：`blogs/**/*.md`，跳过目录名 `模板`。
- 输出：`public/data/blogs.json`、`series.json`、`announcements.json`（仅追加时）、
  `background-images.json`。
- 退出码：`0` 成功；`1` 未捕获异常（`main().catch` 设置 `process.exitCode`）。
- 幂等性：日期沿用旧清单，重复运行结果稳定（除公告追加外）。

## 2. `postbuild.js`

```bash
node scripts/postbuild.js
```

把 `blogs/` 递归复制到 `dist/blogs/`。`dist` 不存在时会先创建。
源目录缺失时打印警告并跳过，不返回失败码。

实现使用逐层 `readdir` + `copyFileSync`，而不是 `fs.cpSync`：在部分 Windows + Node 22
环境中，后者复制含中文名的目录会崩溃（`0xC0000409`）。输出保持一致，仍包含 `.obsidian/`。
详见 [已知行为与陷阱](../运维/已知行为与陷阱.md) 第 15 条。

## 3. `optimize-images.mjs`

```bash
npm run optimize:images            # 生成缺失的 WebP
npm run optimize:images -- --force # 全部重建
```

- 读取 `MANIFEST` 中登记的源图与尺寸上限。
- 输出同名 `.webp`，保留原图。
- 依赖 `sharp`（devDependency）。

## 4. `compare-image-quality.mjs`

```bash
npm run check:images
node scripts/compare-image-quality.mjs
```

- 对 `PAIRS` 中列出的原图 / WebP 计算 PSNR、MAE、MaxDiff。
- 透明图按 alpha 预乘后再比较，避免全透明像素导致虚假误差。
- 仅打印结果，不写文件。

## 5. `image-info.mjs`

```bash
node scripts/image-info.mjs <文件...>
```

- 解析 PNG / JPEG 文件头，输出宽高。
- 不依赖第三方库；其他格式会提示无法识别。

## 6. `preview-server.mjs`

```bash
node scripts/preview-server.mjs
node scripts/preview-server.mjs --port 4180 --root . --dist dist
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--port` | `4173` | 监听端口（绑定 `127.0.0.1`） |
| `--root` | `.` | 站点根与文章源根 |
| `--dist` | `<root>/dist` | 构建产物目录 |

行为：

1. 先查 `dist/<path>`，再查 `<root>/<path>`；
2. 目录请求回退到 `index.html`；
3. 拒绝包含 `..` 的路径；
4. 所有响应 `Cache-Control: no-store`。

适用于验证「`/blogs/*.md` 可直接访问」的线上行为。

## 7. `verify-detail-mobile.mjs`

```bash
node scripts/verify-detail-mobile.mjs --id <文章ID> [--out <输出目录>]
```

- 复制 `dist/` 到临时目录，注入探针脚本，模拟点击「沉浸阅读」；
- 在多个手机 / 平板 / 桌面视口下运行浏览器 `--dump-dom`，读取真实几何；
- 输出断言结果与截图路径；
- 退出码：`0` 全部通过，`1` 存在失败项。

依赖本机 Chromium 系浏览器与已构建的 `dist/`，不参与 CI。

## 8. `check-docs.mjs`

```bash
node scripts/check-docs.mjs
```

- 扫描仓库内所有 `.md`（跳过 `node_modules`、`dist`、`.git`）；
- 校验相对链接目标是否存在；
- 忽略外链、锚点与 `mailto:`；
- 发现问题时打印文件与行号，退出码 `1`。

用于防止重构后文档链接失效。

## 9. `test-toc.mjs`

```bash
npm run test:toc
```

- 只测 `tocModel.js` 的纯函数：标题清理、建树、重复/缺失 id、星标、当前位置、阅读进度；
- 不启动浏览器，不依赖 `dist`；
- 全部通过时退出码 `0`，存在失败用例时退出码 `1`。

适合改动目录模型后先跑这一层，失败信息会指出具体用例。

## 10. `e2e-toc.mjs`

```bash
npm run build
npm run test:toc:e2e
```

- 自己启动静态服务器读取 `dist/`，通过本机 headless Chrome 的 CDP（默认 `127.0.0.1:9333`）跑真实页面；
- 覆盖桌面目录树、点击滚动、`?section=` 深链、手动折叠、阅读进度、首标题为 H4 的文章、短文章布局；
- 覆盖移动端关闭态 `inert` / `aria-hidden`、模态弹层、Tab 焦点陷阱、Esc 归还焦点、点击目录项关闭；
- 覆盖平板弹层尺寸、Hash 路由切换、沉浸模式导航高度；
- 截图写入系统临时目录 `youngblog-toc-e2e/`；
- 退出码：`0` 全部通过，`1` 存在失败项。

需要先构建 `dist/`，并确保本机 headless Chrome 已在 9333 端口开启 CDP；不参与 CI。

## 11. 脚本开发约定

- 使用 `node:` 前缀导入内置模块（`node:fs/promises`、`node:path`）。
- 路径基于 `import.meta.url` 推导，不依赖调用者的当前目录。
- 输出统一以 `[脚本名]` 前缀，便于在构建日志中定位。
- 新增脚本后同步本文档与 `.github/workflows/ci.yml`（若需纳入 CI）。
