# 内容工作流

## 1. 目录即分类

```text
blogs/
├── 二上/
│   ├── 算法/
│   │   ├── 图/并查集.md
│   │   └── 模板/算法板子.md
│   └── 计组/...
├── 二下/...
├── 三上/...
├── 文学/诗词/词/...
├── 明日方舟/...
└── 模板/                 # 被构建跳过，不作为文章
```

- **第 1 层**：学年或领域（`二上` / `三上` / `文学` / `明日方舟`）。
- **第 2 层**：课程或主题。
- **第 3 层**：章节或小节。
- 前 3 层目录会写进文章的 `tags`；`tags[0]` 决定首页「学习 / 娱乐」分类。
- 更深的目录不会进入标签，但仍会影响 `contentFile` 路径。

> 不要在 `blogs/` 根目录随手放 `.md`：它会被当作一篇文章收录。
> 写作模板与草稿请放进 `blogs/模板/`（构建时整体跳过）。

## 2. 写一篇新文章

1. 复制 `blogs/模板/文章模板.md` 到目标目录，重命名为文章标题。
2. 填写 frontmatter：

```yaml
---
title: 并查集
date: 2026-03-12
excerpt: 路径压缩、按秩合并与常见题型。
series: 算法模板
chapter: 2 - 图论
order: 2
recommended: true
---
```

3. 正文使用站点支持的 Markdown 扩展（公式、Mermaid、任务清单等），
   语法见 [Markdown 扩展](../参考/扩展语法参考.md)。
4. 运行 `node scripts/generate.js`，再 `npm run dev` 预览。
5. 确认 `public/data/blogs.json` 的 diff 只包含预期文章，随代码一起提交。

## 3. frontmatter 速查

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 建议 | 缺失时用文件名 |
| `date` | 建议 | `YYYY-MM-DD`；缺失时继承旧记录或文件修改时间 |
| `excerpt` | 否 | 首页摘要，缺失时自动截取正文首段 |
| `series` | 否 | 系列名；同名文章自动聚合 |
| `chapter` | 否 | `N - 章节名`，决定系列内顺序 |
| `order` | 否 | 无章节时的排序值 |
| `recommended` / `推荐` | 否 | 首页推荐 |
| `id` | 否 | 手动指定数字 ID；一般不要写 |
| `type` | 否 | 自定义类型标签 |

完整规则见 [frontmatter 参考](../参考/文章元数据参考.md)。

## 4. 系列与章节

```text
series: 操作系统
chapter: 3 - 内存管理
order: 3
```

- 系列内有 `chapter` 的文章排在无章节文章之前，按章节序号升序。
- 同一篇系列文章在详情页会显示「上一篇 / 下一篇」，由 `PostNav` 计算。
- 系列封面当前统一使用 `assets/images/background/bg2.webp`，由生成器写入。

## 5. 图片

| 写法 | 解析结果 | 适用 |
| --- | --- | --- |
| `![[图片1.png]]` | `/blogs/图片/图片1.png` | Obsidian 粘贴的裸文件名 |
| `![[图片1.png\|说明]]` | 同上，带 alt | 需要替代文本 |
| `![](./images/a.png)` | 相对当前文章目录 | 文章专属配图 |
| `![](assets/images/a.webp)` | 相对站点根 | 复用公共素材 |

推荐把文章配图放在文章同级的 `images/` 目录，或统一放 `blogs/图片/`。
新增公共素材放 `public/assets/images/`，并按 [图片与媒体](图片与媒体.md) 生成 WebP。

## 6. 发布公告

站点公告保存在 `public/data/announcements.json`。追加一条：

```bash
node scripts/generate.js "「制作者通讯·4.2」本次更新内容……"
```

该命令会把参数拼接成一条公告插到数组头部，日期取运行当天。
注意：同一次运行也会重建 `blogs.json` / `series.json`，提交前一起检查 diff。

## 7. 发布流程

1. `node scripts/generate.js`（或直接 `npm run build`）。
2. 本地 `npm run build` + `node scripts/preview-server.mjs` 抽查 3 个页面：
   首页、最近一篇文章、系列页。
3. 检查 `git status`，确认没有误提交 `dist/`、临时图片或 `.obsidian/workspace.json` 之类。
4. 按 `feat(content): ...` / `docs: ...` 提交。
5. 部署（见 [部署](../运维/部署指南.md)）。

## 8. 写作禁忌

- 不要手工修改 `public/data/blogs.json` / `series.json` —— 会被覆盖。
- 不要重命名已发布文章的路径 —— ID 基于路径哈希，旧链接会失效。
- 不要在文章里引用本地绝对路径（如 `D:\...`），部署后必然 404。
- 不要在正文写 `</script>` 之类的原始标签，`v-html` 渲染会截断。
