# 架构说明

本文件是架构的「一页纸」入口，细节拆分在 `docs/架构/` 下。

## 目标与约束

1. **纯静态**：不依赖后端与数据库，所有数据以 JSON / Markdown 形式随站点分发。
2. **内容即仓库**：写作发生在 `blogs/`，构建时转成索引，运行时不依赖任何 CMS。
3. **双路径部署**：同一套代码要能在 `/` 与 `/YoungBlog/` 两种 base 下工作。
4. **视觉稳定**：入场动画、背景轮播、字体与配色属于产品体验的一部分，重构不得改变最终呈现。
5. **可被 Agent 维护**：目录职责、命令、约束必须可被文档准确描述。

## 分层

```text
┌─────────────────────────────────────────────┐
│ app/            App.vue（全局壳、轮播、门帘） │
├─────────────────────────────────────────────┤
│ features/       每个功能域：视图 + 私有组件    │
│  home / blog-detail / archive / categories  │
│  series / about / announcements / quick-links│
├─────────────────────────────────────────────┤
│ shared/         跨域复用                      │
│  components / layout / composables / stores │
│  utils                                       │
├─────────────────────────────────────────────┤
│ assets/         字体与全局样式（参与构建）      │
├─────────────────────────────────────────────┤
│ public/         原样分发资源 + 站点数据         │
│ blogs/          内容源（构建后复制进 dist）     │
└─────────────────────────────────────────────┘
```

依赖方向只允许自上而下：`features` 可以依赖 `shared`，`shared` 不得反向依赖某个 feature。
`App.vue` 作为壳层可以组合任意 feature 的公共组件。

## 运行时边界

- **数据获取**：`fetch` + `public/data/*.json`，统一经 `shared/utils/url.js` 的 `resolveUrl` 加 base 前缀。
- **状态**：Pinia Setup Store，无持久化层（清单勾选状态例外，存 `localStorage`）。
- **Markdown 渲染**：`useMarkdown` 负责语法扩展与资源重写，`BlogContent` 负责真实 DOM 上的事件增强。
- **样式**：全局样式负责变量、布局基线与响应式；组件样式使用 `scoped`。

## 扩展点

- 新增页面：`features/<name>/` + `router/index.js` + `i18nStore` 三语文案。
- 新增 Markdown 语法：在 `shared/composables/useMarkdown.js` 的预处理阶段插入，并同步 `docs/参考/扩展语法参考.md`。
- 新增数据文件：放 `public/data/`，在 `docs/参考/数据结构参考.md` 登记 schema。
- 新增构建步骤：改 `package.json` 的 `build` 链，并在 `docs/架构/构建管线.md` 说明。
