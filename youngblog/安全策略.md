# 安全策略

## 报告漏洞

请**不要**通过公开 Issue 披露可利用细节。优先使用 GitHub 仓库的
「Security → Report a vulnerability」私密通道；若不可用，请通过维护者公开的联系方式私下联系。

报告请尽量包含：

- 受影响的页面 / 路由与浏览器版本；
- 复现步骤与最小示例；
- 影响判断（XSS、信息泄露、拒绝服务等）；
- 你希望的署名方式（可选）。

## 范围

本项目是纯静态站点，重点关注的攻击面：

| 面 | 说明 |
| --- | --- |
| Markdown 渲染 | 文章内容经 `marked` 渲染后以 `v-html` 注入；自定义块与链接处理是否存在注入 |
| 资源路径重写 | `useMarkdown` 对图片 / 链接 URL 的拼接与 base 前缀处理 |
| 外部链接 | `quick-links.json` 与文章中的外链是否强制 `noopener` |
| 构建脚本 | `scripts/` 读取仓库内文件；是否存在路径穿越 |
| 第三方依赖 | `marked`、`mermaid`、`katex`、`highlight.js` 等 |

## 不在范围

- 文章作者的笔误、事实性错误与内容版权问题；
- 需要物理接触设备或已控制用户终端的攻击；
- 第三方托管平台（GitHub Pages、DNS、CDN）自身的问题；
- 社会工程学与钓鱼邮件。

## 处理流程

1. 确认报告可复现后，维护者在私下评估影响。
2. 修复在非公开分支进行，必要时先发布临时缓解措施。
3. 修复上线后，与报告者协商公开披露时间。
4. 在 `更新日志.md` 记录安全相关修复（不披露可利用细节）。

## 依赖安全

建议定期执行：

```bash
npm audit
```

升级依赖时遵循 `docs/参考/配置参考.md` 的版本约束说明，并在 PR 中说明升级原因。
