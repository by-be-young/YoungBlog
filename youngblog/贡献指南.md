# 贡献指南

感谢你愿意改进 YoungBlog。本仓库同时包含内容与代码，请按下面的约定提交改动。

## 1. 环境准备

```bash
node -v        # 需 ^22.18.0 || >=24.12.0
npm ci
npm run dev
```

Windows 下建议使用 PowerShell 7；仓库的换行符由 `.gitattributes` 统一为 LF，请勿提交 CRLF 变更。

## 2. 目录归属

| 改动类型 | 应放位置 |
| --- | --- |
| 新页面 / 新功能 | `src/features/<feature>/`（视图 + 该功能私有组件） |
| 跨页面复用组件 | `src/shared/components/` 或 `src/shared/layout/` |
| 复用逻辑 | `src/shared/composables/` |
| 全局状态 | `src/shared/stores/` |
| 纯函数工具 | `src/shared/utils/` |
| 全局样式 / 字体 | `src/assets/styles/`、`src/assets/fonts/` |
| 静态资源（图片、音乐） | `public/assets/` |
| 站点数据 | `public/data/` |
| 构建与工具脚本 | `scripts/` |
| 文章 | `blogs/<学年>/<主题>/<小节>/` |

判断标准：**只有一个功能域使用的，留在该功能域；两个及以上功能域使用的，才上移到 `shared`。**

## 3. 提交规范

采用 Conventional Commits 的语义前缀，描述可用中文：

```text
feat(归档页): 新增按年份折叠时间轴
fix(详情页): 修复移动端目录遮挡正文
docs: 补充 frontmatter 字段说明
refactor(shared): 将 URL 解析抽到 utils
chore: 升级 vite 到 8.x
```

一次提交只做一件事。纯格式化、重命名与逻辑改动分开提交，便于审阅与回滚。

## 4. 代码约定

- 缩进 2 空格、单引号、不加分号、行宽 100（Prettier 配置见 `.prettierrc.json`）。
- 组件文件名 PascalCase；组合式函数 `useXxx.js`；Store `xxxStore.js`。
- 导入统一使用 `@/` 别名，禁止新增 `../../..` 深路径。
- 用户可见文案必须走 `i18nStore`，并同时补齐 `zh` / `en` / `ja` 三套键。
- 不引入新的全局 CSS 选择器，除非它确实跨组件生效。
- 修改 Markdown 渲染行为时，同步 `docs/参考/扩展语法参考.md`。

提交前至少执行：

```bash
npm run lint
npm run build
```

若改动涉及图片或首屏，另跑 `npm run check:images`。

## 5. 内容投稿

1. 从 `blogs/模板/文章模板.md` 复制一份，放到合适的学年 / 主题目录。
2. 填写 frontmatter（字段说明见 `docs/参考/文章元数据参考.md`）。
3. 本地 `npm run dev` 预览；构建前确认 `public/data/blogs.json` 的 diff 只包含预期文章。
4. 文章默认采用 CC BY-NC-SA 4.0，除非文章内特别声明。

不要手工编辑 `public/data/blogs.json`、`series.json`：它们是生成产物，会被下一次构建覆盖。

## 6. 文档要求

- 结构或约定发生变化时，更新对应 `docs/` 文档与 `AGENTS.md`。
- 新增重要技术决策时，在 `docs/决策记录/` 添加一条 ADR。
- 文档中的命令必须实际可运行；路径链接使用相对路径。

## 7. Pull Request 检查清单

- [ ] 变更范围与 PR 描述一致，没有顺带重构无关文件。
- [ ] `npm run lint` 与 `npm run build` 通过。
- [ ] 没有提交 `dist/`、`node_modules/` 或临时产物。
- [ ] 涉及 UI 的改动附前后对比说明（移动端 / 桌面端）。
- [ ] 新增或修改的文案已补齐三语。
- [ ] 文档与 ADR 已同步。

更细的审查项见 [docs/质量/代码审查清单.md](docs/质量/代码审查清单.md)。

## 8. 行为准则

参与本项目即表示同意遵守 [行为准则.md](行为准则.md)。
